# 문서 좌표 감사

문서가 가리키는 것이 실재하는지, 박힌 값이 실물과 맞는지, 같은 사실이 두 곳에 있는지를 검사하고 **판정한다.**

- **바깥 도구가 먼저** — 링크·URL은 **lychee**(`lycheeverse/lychee`), 마크다운 구조는 **markdownlint**(`DavidAnson/markdownlint`)가 든다. 둘 다 언어를 안 가린다. 그 자리를 손으로 만들지 않는다.
- **산문 린터는 언어별 규칙 묶음이 일을 한다** — **Vale**·**textlint** 둘 다 그렇다. **깔기 전에 내 언어의 묶음이 실재하는지 확인한다.** 묶음이 있으면 값을 하고, 없으면 남의 언어 규칙이 오탐으로 진짜를 덮는다.
- **이 스킬만 `references/` 가 없다** — 위 넷은 읽을 명세가 아니라 **깔아서 돌리는 것**이라 옮겨 둘 원문이 없다. 도구를 부르는 것 자체가 알맹이다.
- **근거 원칙** — 규범 **[Single Source · Point or Derive]** · **[Docs-as-Code · State Only]**
- **아래는 도구가 못 하는 것만이다** — 코드 스팬 경로(링크가 아니라 lychee가 안 봄)와 **의미 판단**(맞출까 걷을까 · 지금인가 그때인가 · 자칭 진본이 실제 주인인가).

## 1. 도구를 먼저 돌린다

```bash
lychee --offline --no-progress .              # 링크·상대경로. 깨진 것이 있으면 종료코드 2
lychee --offline --include-fragments README.md  # 목차 앵커까지 본다
npx markdownlint-cli2 "**/*.md"               # 마크다운 구조
```

markdownlint 기본값에는 **줄 길이·표 정렬**이 들어 있어 문체와 부딪히면 오탐이 대부분을 덮는다.
부딪히는 규칙만 끄고 나머지를 살린다 — 통째로 끄지 않는다.

**도구가 안 깔리는 자리라면** — 부트스트랩 게이트가 먼저 안다. 세션 시작 진단에서
lychee·markdownlint-cli2 줄이 ❌ 면 이 스킬의 도구 단계는 못 돈다 — 아래 수동 갈래로 간다.
(도구를 깔고 재는 법은 훅이 든다: `bash .claude/hooks/session-start.sh --check`.
`npx --yes` 로 재지 않는다 — 설치법과 도달 판정을 섞는다, claude-config 0004.)

도구 자리를 손으로 다 메우지는 않는다(아래 **갈리는 자리** 참조). 다만 **깨진 상대경로 링크**
하나만은 셸로 잡힌다 — 낡은 문서에서 가장 흔하고 가장 확실한 결함이기 때문이다.

```bash
grep -rnoE '\]\([^)]+\)' --include='*.md' . | while IFS= read -r hit; do
  f=${hit%%:*}; rest=${hit#*:}; n=${rest%%:*}; link=${rest#*:}
  t=${link#*](}; t=${t%)}; t=${t%%#*}
  case "$t" in http*|mailto:*|'') continue;; esac
  [ -e "$(dirname "$f")/$t" ] || echo "MISS $f:$n -> $t"
done
```

이건 파서가 아니라 정규식이라 **코드블록 안의 `](` 도 문 다.** `MISS` 를 볼 때 그 줄이
코드블록인지부터 본다 — 오탐을 결함으로 세면 진짜가 묻힌다.

**대신하지 못하는 것**은 그대로 남는다 — 바깥 URL 생사(망이 있어야 안다) · 목차 앵커 · 마크다운 구조.

## 2. 코드 스팬 경로 — lychee가 안 보는 자리

lychee는 마크다운 링크와 URL을 본다. `` `deploy.ps1` `` 처럼 백틱으로만 감싼 경로는 링크가 아니라 검사에서 빠진다.

```bash
grep -ohE '`[A-Za-z0-9_./-]+\.[a-z]{2,4}`|`[A-Za-z0-9_-]+/`' <문서들> \
  | tr -d '`' | sort -u | while read p; do [ -e "$p" ] || echo "MISS $p"; done
```

⚠ **이 grep 은 확장자가 있는 경로만 본다.** `config.MODES`·`#planbox`·`paneGo` 같은 식별자 스팬은 한 건도
안 물어 **0 건이 초록으로 읽힌다** — 안 잰 것과 같다. 그물은 **꼴로** 넓힌다: **경로**(`/` 가 들거나 `/` 로
끝나거나 확장자로 끝난다)는 나무에, **식별자**(`_` · `a.b` · `f()` · `#id` · `.class` · camelCase)는 코드에 그
글자가 있어야 한다. `모듈.이름` 은 통글자로 코드에 없으니 head 를 파일로 풀어 그 안에서 tail 을 찾는다. 남는
**한 낱말**(`web`·`config`)은 안 문다 — 물면 산문이 통째로 빨강이 된다.

**저장소가 이 그물을 든 검사를 이미 가졌으면 그것을 돌리고 이 grep 은 안 든다** — 손 grep 은 검사가 없는
자리의 임시 자다. 검사를 세울 때 지킬 것 셋: **① 검사 파일 자신과 검사 대상 문서를 코드 자루에서 뺀다** —
자기 이빨의 씨 글자와 문서 스팬이 자루에 들면 심은 가짜가 제 손으로 통과한다. **② 「코드가 그 이름을 쓰면
통과」로 일반화하지 않는다** — 지운 파일의 이름은 남의 주석에 남아 있어 하필 삭제·이동 갈래가 눈먼다. 돌아야
나는 자리는 **이름과 까닭을 값으로** 적는다. **③ 안 무는 꼴을 꼴별 건수와 견본으로 찍는다** — 그 목록이
줄이려고 두는 것이다.

`MISS`를 셋으로 가른 뒤 고친다.

| 무엇 | 처리 |
|---|---|
| 옮겼다 | 새 경로로 고친다 |
| 지웠다 | 가리키던 문장을 걷는다 |
| 애초에 없었다 | 좌표가 아니라 **미결**이다. 그렇게 표시한다 |

저장소 밖 경로(다른 저장소·홈)는 **어느 검사도 못 본다.** 통과를 근거로 삼지 않는다.

## 3. 박힌 수치·날짜

```bash
grep -rnE '[0-9]+(장|개|건|종|줄)' <문서들>
grep -rnE '20[0-9]{2}-[0-9]{2}(-[0-9]{2})?( 기준| 현재)?' <문서들>
ls <실물 경로> | wc -l
```

어긋났으면 **맞추지 말고 걷어낸다.** 개수 대신 **관계**를 적는다 — *"N장"*이 아니라 *"종마다 형식별로 한 벌"*.
시점은 `git log`가 든다.

가르는 물음 하나: **이 숫자가 지금을 말하나, 그때를 말하나.**
그때를 말하면 걷지 않는다 — 결정 기록·핸드오버·실측 스냅샷의 숫자는 낡는 게 아니라 굳는다.

## 4. 번호 참조

```bash
grep -nE "[0-9]번|[0-9]부터|[0-9]단계|§[0-9]|항목 [0-9]" <문서>
# 가리켜지는 표·목록의 실제 항목 수를 센다
```

항목 수를 바꾸는 편집을 했으면 **저장소 전체**를 다시 훑는다. 인용 문장은 대개 표에서 몇 줄 떨어져 있다.

**근본 해결은 축을 바꾸는 것이다** — 번호 대신 이름으로 가리키면(`§4` → `[Recall Priority]`) 항목을 끼워 넣어도 안 깨진다. 검사는 차선이다.

## 5. 어긋난 사본

기계가 다 못 잡는다. 의심 목록으로 좁힌 뒤 **진본을 열어 대조한다.**

1. 환경·설정·경로처럼 다른 곳에 진본이 있는 주제를 문서에서 찾는다
2. 진본을 열어 대조한다 — 대조 없이 "있으니 맞겠지" 하지 않는다
3. 어긋났으면 사본을 걷고 좌표만 남긴다

배포본·미러·번들처럼 **그 자리에 실물이 있어야 기능하는 사본**은 없애지 말고 대조를 자동화한다.

| 알아보는 법 | 처리 |
|---|---|
| 사본이 없으면 기능이 죽는가 | 죽으면 걷지 말고 **검사를 붙인다** |
| 사본 쪽에서 진본이 보이는가 | 안 보이면 거기서는 판별 불가 — 둘 다 보이는 자리에서 대조한다 |
| 갱신이 여러 단계인가 (복사 → 커밋 → 푸시) | **어느 단계에서 멈췄는지까지** 본다 |

사본만 있는 자리에서 "낡았나"를 물으면 언제나 "아니다"가 나온다. 그 답을 근거로 삼지 않는다.

## 6. 자칭 진본

문서의 자기소개(*"이 표가 진본이다"*)는 **가장 약한 근거다.** 밖에서 확인한다.

| 물음 | 어디서 답을 받나 |
|---|---|
| 상위 규범이 이 문서를 뭐라 하는가 | 프로젝트 `CLAUDE.md` · 진본 지도 |
| 그 폴더가 이 문서를 뭐라 하는가 | 그 폴더의 `README` |
| 어디에 놓여 있나 | 보관·동결 폴더에 있으면 자칭과 무관하게 옛것이다 |
| 이 문서의 좌표는 살아 있나 | 죽은 좌표가 섞였으면 문서 자체가 낡았다는 신호다 |

엇갈리면 **상위 규범이 이긴다.**
**정교함을 최신성으로 읽지 않는다** — 문서는 손봐지기를 멈추기 직전에 가장 정교하다.

## 7. 색인 대조

```bash
ls <실물 폴더> | wc -l ; grep -c '<목록 행 패턴>' <색인 문서>
```

색인이 진본을 못 들면 색인이 아니다.

## 갈리는 자리

| 갈리는 자리 | 어느 쪽 |
|---|---|
| 두 문장이 어긋나 보인다 | 각각 **어떤 질문에 답했나**를 먼저 적는다. 질문이 다르면 모순이 아니라 층이 다른 것이다 |
| 요약 문서의 압축 문구가 근거로 보인다 | 원 조항을 열어 문맥을 본다 |
| 수단을 드는 문서가 목적에 안 답한다 | 안 답하는 것을 어긋남으로 읽지 않는다 |
| 한 건을 틀리게 판정했다 | 같은 방식으로 판정한 나머지를 다시 본다 |
| 바깥 도구가 내 언어를 안 든다 | **빈 칸으로 남긴다.** 규칙을 손으로 지어 채우지 않는다 — 채우는 순간 유지할 것이 하나 늘고, 그것도 낡는다(규범 **[Recall Priority]** · **[YAGNI]**) |
| 표·목록·색인을 새 판으로 다시 쓴다 | 규범 **[Root Cause Fix]** 의 블록 교체 감사가 먼저 걸린다 |
| 무엇을 보고하나 | 규범 **[Meaning Before Shorthand]** — *몇 건 고쳤나*가 아니라 어떤 낡음이었나 |
