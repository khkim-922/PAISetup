# 문서 좌표 감사

문서가 가리키는 것이 실재하는지, 박힌 값이 실물과 맞는지, 같은 사실이 두 곳에 있는지를 검사하고 **판정한다.**

- **바깥 도구가 먼저다** — 링크·URL은 **lychee**, 마크다운 구조는 **markdownlint**가 든다. 둘 다 언어를 안 가린다.
  이 스킬이 맡는 것은 도구가 못 하는 자리다 — 코드 스팬 경로(링크가 아니라 lychee가 안 봄)와 **의미 판단**(맞출까
  걷을까 · 지금인가 그때인가 · 자칭 원본이 실제 주인인가).
- **산문 린터(Vale·textlint)는 언어별 규칙 묶음이 일을 한다** — 깔기 전에 내 언어의 묶음이 실재하는지 본다. 없으면
  그 칸은 **빈 칸으로 둔다** — 남의 언어 규칙은 오탐으로 진짜를 덮고, 손으로 지은 규칙은 유지할 것이 하나 늘어
  그것도 낡는다(규범 **[Recall Priority]** · **[YAGNI]**).
- ⚠ **이 스킬은 「문서에 적힌 것」만 잰다 — 반쪽이다.** 도구가 다 초록이어도 「낡았나」에는 아직 답하지 않은
  것이다. 초록은 *문서가 짚은 좌표가 산다*는 말이고, 부탁은 대개 *문서가 실물을 옳게 드나*였다 —
  `doc-rederive-from-source` 를 돌린 뒤에 답한다. 손댄 코드의 **뜻**이 바뀐 판이면 특히 그렇다: 옛 문장은 좌표가
  다 살아 있는 채로 **읽는 사람만 틀리게** 만든다.
- **근거 원칙** — 규범 **[Single Source · Point or Derive]** · **[Docs-as-Code · State Only]**

## 1. 도구를 먼저 돌린다

```bash
lychee --offline --no-progress .              # 링크·상대경로. 깨진 것이 있으면 종료코드 2
lychee --offline --include-fragments README.md  # 목차 앵커까지 본다
npx markdownlint-cli2 "**/*.md"               # 마크다운 구조
```

markdownlint 기본값의 **줄 길이·표 정렬**은 문체와 부딪혀 오탐이 대부분을 덮는다 — 부딪히는 규칙만 끄고 나머지는
살린다.

**도구가 깔렸나는 세션 시작 진단이 먼저 안다** — lychee·markdownlint-cli2 줄이 ❌ 면 도구 단계를 건너 아래 수동
갈래로 간다. 깔고 재는 것은 훅으로 한다(`bash .claude/hooks/session-start.sh --check`) — `npx --yes` 는 깔기와
닿는지 재기를 한 번에 해서 성공이 어느 쪽 성공인지 모른다.

도구가 없을 때 셸로 메우는 것은 **깨진 상대경로 링크** 하나다 — 낡은 문서에서 가장 흔하고 가장 확실한 결함이라서다.

```bash
grep -rnoE '\]\([^)]+\)' --include='*.md' . | while IFS= read -r hit; do
  f=${hit%%:*}; rest=${hit#*:}; n=${rest%%:*}; link=${rest#*:}
  t=${link#*](}; t=${t%)}; t=${t%%#*}
  case "$t" in http*|mailto:*|'') continue;; esac
  [ -e "$(dirname "$f")/$t" ] || echo "MISS $f:$n -> $t"
done
```

파서가 아니라 정규식이라 **코드블록 안의 `](` 도 문다** — `MISS` 를 결함으로 세기 전에 그 줄이 코드블록인지 본다.
바깥 URL 생사 · 목차 앵커 · 마크다운 구조는 셸이 대신하지 못한다 — 판정 옆에 「안 쟀다」로 적는다.

## 2. 코드 스팬 경로 — lychee가 안 보는 자리

백틱으로만 감싼 경로는 링크가 아니라 lychee 검사에서 빠진다.

```bash
grep -ohE '`[A-Za-z0-9_./-]+\.[a-z]{2,4}`|`[A-Za-z0-9_-]+/`' <문서들> \
  | tr -d '`' | sort -u | while read p; do [ -e "$p" ] || echo "MISS $p"; done
```

⚠ **이 grep 은 확장자가 있는 경로만 본다** — 식별자 스팬은 한 건도 안 잡혀 **0 건이 초록으로 읽힌다.** 안 잰 것과
같다. 그물은 **모양으로** 넓힌다:

- **경로 모양**(`/` 가 들거나 `/` 로 끝나거나 확장자로 끝난다) — 그 파일이 있는지 본다
- **식별자 모양**(`_` · `a.b` · `f()` · `#id` · `.class` · camelCase) — 코드에 그 글자가 있는지 본다. `모듈.이름` 꼴은
  통째로는 코드에 없으니 앞쪽을 파일로 찾은 뒤 그 파일 안에서 뒤쪽 이름을 찾는다
- 남는 **한 낱말**은 그물 밖에 둔다 — 잡으면 산문이 통째로 빨강이 된다

**저장소에 이 그물을 든 검사가 있으면 그것을 돌린다** — 손 grep 은 검사가 없는 자리의 임시 자다. 검사를 세울 때는
둘을 지킨다:

1. **검사 파일 자신과 검사 대상 문서는 「코드에 이 이름이 있나」를 찾는 범위에서 뺀다** — 안 빼면 검사가 시험용으로
   심은 가짜 이름이 검사 파일 안에서 발견되어 저절로 통과한다
2. **경로 모양은 그 파일이 있어야 통과다.** 실행해야만 생기는 이름은 이름과 까닭을 값으로 적어 둔다 — 「코드가 그
   이름을 쓰면 통과」로 넓히면 지운 파일의 이름이 남의 주석에 남아 있어 하필 삭제·이동을 못 잡는다

안 잡는 모양은 건수와 견본으로 드러낸다(규범 **[Goal-Driven Execution]** — 초록은 「본 데까지는 없다」다).

`MISS`를 셋으로 가른 뒤 고친다.

| 무엇 | 처리 |
|---|---|
| 옮겼다 | 새 경로로 고친다 |
| 지웠다 | 가리키던 문장을 걷는다 |
| 애초에 없었다 | 좌표가 아니라 **미결**이다. 그렇게 표시한다 |

저장소 밖 경로(다른 저장소·홈)는 **어느 검사도 못 본다** — 그 자리는 「안 쟀다」로 적는다.

## 3. 박힌 수치·날짜

```bash
grep -rnE '[0-9]+(장|개|건|종|줄)' <문서들>
grep -rnE '20[0-9]{2}-[0-9]{2}(-[0-9]{2})?( 기준| 현재)?' <문서들>
ls <실물 경로> | wc -l
```

가르는 물음 하나 — **이 숫자가 지금을 말하나, 그때를 말하나.**

- **그때를 말하면 둔다** — 결정 기록·핸드오버·실측 스냅샷의 숫자는 낡는 게 아니라 굳는다
- **지금을 말하는데 어긋났으면 걷어낸다** — 숫자를 고쳐 맞추면 사본이 새로 서서 또 낡는다. 개수 대신
  **관계**(무엇마다 무엇이 서나)를 적고, 시점은 `git log` 에 맡긴다

## 4. 번호 참조

```bash
grep -nE "[0-9]번|[0-9]부터|[0-9]단계|§[0-9]|항목 [0-9]" <문서>
# 가리켜지는 표·목록의 실제 항목 수를 센다
```

항목 수를 바꾸는 편집을 했으면 **저장소 전체**를 다시 훑는다 — 인용 문장은 대개 표에서 몇 줄 떨어져 있다.

**근본 해결은 번호 대신 이름으로 가리키는 것이다** — 항목을 끼워 넣어도 안 깨진다. 검사는 차선이다.

## 5. 어긋난 사본

기계가 다 못 잡으니 의심 목록으로 좁혀 손으로 대조한다.

1. 원본이 다른 곳에 사는 주제를 문서에서 찾는다
2. **원본을 열어 대조한다** — 「있으니 맞겠지」는 대조가 아니다
3. 어긋났으면 사본을 걷고 좌표만 남긴다

| 알아보는 법 | 처리 |
|---|---|
| 사본이 없으면 기능이 죽는가 | 죽으면 사본을 두고 **대조 검사를 붙인다** |
| 사본 쪽에서 원본이 보이는가 | 안 보이면 거기서 물은 「낡았나」는 언제나 「아니다」로 나온다 — 둘 다 보이는 자리에서 대조한다 |
| 갱신이 여러 단계인가 | **어느 단계에서 멈췄는지까지** 본다 |

## 6. 자칭 원본

문서의 자기소개(*"이 표가 원본이다"*)는 **가장 약한 근거다.** 밖에서 확인한다.

| 물음 | 어디서 답을 받나 |
|---|---|
| 상위 규범이 이 문서를 뭐라 하는가 | 프로젝트 `CLAUDE.md` · 원본 지도 |
| 그 폴더가 이 문서를 뭐라 하는가 | 그 폴더의 `README` |
| 어디에 놓여 있나 | 보관·동결 폴더에 있으면 자칭과 무관하게 옛것이다 |
| 이 문서의 좌표는 살아 있나 | 죽은 좌표가 섞였으면 문서 자체가 낡았다는 신호다 |

엇갈리면 **상위 규범이 이긴다.** 최신성은 정교함이 아니라 위 넷으로 잰다 — 문서는 손봐지기를 멈추기 직전에 가장
정교하다.

## 7. 색인 대조

```bash
ls <실물 폴더> | wc -l ; grep -c '<목록 행 패턴>' <색인 문서>
```

색인은 원본을 빠짐없이 들어야 색인이다.

## 갈리는 자리

| 갈리는 자리 | 어느 쪽 |
|---|---|
| 두 문장이 어긋나 보인다 | 각각 **어떤 질문에 답했나**를 먼저 적는다. 질문이 다르면 모순이 아니라 층이 다른 것이다 — 수단을 드는 문서가 목적에 답하지 않는 것도 같다 |
| 요약 문서의 압축 문구가 근거로 보인다 | 원 조항을 열어 문맥을 본다 |
| 한 건을 틀리게 판정했다 | 같은 방식으로 판정한 나머지를 다시 본다 |
| 표·목록·색인을 새 판으로 다시 쓴다 | 규범 **[Root Cause Fix]** 의 블록 교체 감사가 먼저 걸린다 |
| 무엇을 보고하나 | 규범 **[Meaning Before Shorthand]** — *몇 건 고쳤나*가 아니라 어떤 낡음이었나 |
