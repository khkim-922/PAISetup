# 표준 위에 스킬을 세운다

**스킬 하나의 골격은 이렇다**:

- 자리 — `.claude/skills/<이름>/SKILL.md` · 머리말은 `name`(폴더명과 같게) + `description` 둘
- **`description` 이 트리거다** — 3인칭으로, *무엇을 하나* + *언제 부르나*를 함께. 이 줄로 걸린다
  - ⚠ **값에 `: `(쌍점+빈칸)나 ` #` 이 들면 큰따옴표로 감싼다** — 머리말은 YAML 이라 따옴표 없는 값 안의
    그 글자가 문법을 깬다. 깨져도 아무 말이 없고 트리거 줄만 조용히 안 읽힌다. 파일 머리의 BOM 도 같은 길로
    머리말을 못 찾게 한다 — 스킬을 고친 뒤에는 머리말을 한 번 눈으로 본다
- 본문 — 명령형 · 군더더기 없이. **본문만 읽어도 일이 되게 쓴다**(아래 4)
- 딸림 — `scripts/`(결정론 작업) · `assets/`(산출물 재료) · `references/`(받아 온 원문 보관 — 아래 3)
- 검증 — 부를 만한 물음을 실제로 던져 걸리는지, 걸린 채로 산출물이 규격에 맞는지 본다

이 파일의 나머지는 하나를 든다 — **밖에서 찾은 것 위에 우리 판을 어떻게 세우나.**

- **근거 원칙** — 규범 **[Recall Priority]** · **[Single Source · Point or Derive]** · **[YAGNI]** · **[Determinism First]**

## 1. 쓰기 전에 표준을 찾는다

**만들기 전에 부른다**(규범 **[Recall Priority]**). 규칙을 한 줄이라도 쓰기 전에 찾는다.

- **같은 일을 하는 것** — 명세·스펙·널리 쓰는 도구·같은 자리의 공개 스킬
- **다른 분야** — 같은 *물음*을 오래 푼 곳. 인계·검수·분류처럼 오래된 문제일수록 밖에 답이 있다
- **찾은 뒤 판정 하나** — **원문이 우리보다 아는 게 있나.** 없으면 그건 참조가 아니라 장식이다

## 2. 그대로 쓰나, 우리 판을 세우나

**찾은 것을 그대로 쓰면 이 스킬의 몫이 아니다.** 남의 스킬이 우리 자리에 그대로 맞으면 원문을 손대지
않고 `.claude/skills/<이름>/` 에 깔고, 라이선스가 요구하는 고지(`LICENSE`)만 곁에 둔다. `references/` 도
안 둔다 — **스킬 자체가 원문이라 따로 보관할 것이 없다.** 번역본이 있고 원문과 뜻이 같으면 그것을 깔아도 된다.

우리와 다르게 써야 할 자리가 있을 때만 아래로 간다 — 무엇을 가져올 수 있나부터 가른다:

| 상태 | 어떻게 |
|---|---|
| 자유 라이선스 + 원본 파일 있음 | **`references/` 에 바이트 그대로 보관한다.** 아래 3 |
| 재배포 금지 (상업 저작물·논문) | **인용만.** 개념을 우리 말로 적고 출처를 단다. 원문은 안 묶는다 |
| 원본 파일이 없음 (블로그·구전) | 같음. 인용만 |
| 어느 것도 안 맞음 | **참조 없는 스킬로 간다.** 아래 6 |

못 묶을 때는 **그 사실을 파일에 적는다.** 안 적으면 다음 사람이 *"왜 이것만 없지"* 를 다시 조사한다.

## 3. 원문은 보관한다 — 바이트 그대로

찾아 놓고 요약만 남기면, 무엇을 근거로 그 요약을 썼는지가 사라진다. 그래서 원문은 `references/` 에
**요약 · 번역 없이** 통째로 둔다. 이것은 **사람이 나중에 대조하려고 두는 보관본**이다 — 스킬이 돌 때
기대는 자리가 아니다(아래 4).

- 설치본을 복사하지 말고 상류에서 받는다 — 설치본은 이미 누군가 손댔을 수 있다
- 파일 이름이 `SKILL.md` 면 바꾼다 — 스킬 로더와 부딪힌다
- 스킬 맨 아래 한 자리에 **출처 한 줄**을 적는다 — 저장소 · 경로 · 받은 판(커밋이나 날짜) · 라이선스

## 4. `SKILL.md` 는 혼자 선다

본문은 스킬이 걸릴 때 자동으로 실리고, `references/` 는 모델이 스스로 열어야 한다. **스스로 여는 일은
건너뛰어진다** — 안 연 채 절 이름을 지어낸다. 그래서 **본문만 읽어도 일이 되게** 쓴다:

- **원문의 요지를 우리 말로 요약해 본문에 담는다** — 골격(절 이름·순서·필수/선택)과, 그것을 실제로
  먹히게 하는 규칙 · 예시 가운데 우리 일에 필요한 것
- **본문에서 `references/` 를 가리키지 않는다** — 가리키면 여는 일에 기대게 되고, 안 열면 그 자리가 빈다
- **우리가 표준과 다른 자리를 분명히 적는다**:

| 갈래 | 무엇 |
|---|---|
| **선택** | 표준이 선택으로 둔 것 중 무엇을 켜고 끄나 |
| **덮어쓰기** | 표준과 **어긋나는** 것. 왜 어기는지까지 |
| **더하기** | 표준에 **없는** 것. 표준의 가장 가까운 조항과 **왜 그걸론 안 되는지**를 짝지어 쓴다 |

셋이 다 비면 우리 판을 세울 까닭이 없다 — 위 2 대로 그대로 깐다.

## 5. 역방향으로 점검한다

표준을 **기준선으로 놓고** 우리 것을 턴다. *"우리 규칙 중 표준에 이미 있는 것은 무엇인가."*

있으면 **지운다.** 우리 말로 다시 쓴 것이 제일 많이 나온다.

⚠ **우리 스킬끼리도 본다.** 한 조항이 다른 스킬 소관이면 거기 두고 **좌표만** 든다.
표준과의 중복만 보면 우리끼리 생긴 사본을 못 잡는다.

## 6. 참조가 없을 수도 있다

표준이 전부 딴 데를 겨냥해 안 맞는 축이 있다. 그때는 **억지로 묶지 않는다.**
대신 **왜 없는지**를 스킬 맨 아래에 적는다 — 후보와 탈락 사유를 함께.

안 적으면 다음 사람이 같은 검색을 처음부터 다시 한다.

## 갈리는 자리

| 갈리는 자리 | 어느 쪽 |
|---|---|
| 별이 한둘인 개인 저장소를 표준으로 삼을까 | **아니다.** 검증 없는 한 사람의 의견이다. 널리 쓰이는 것과 그럴듯한 것은 다르다 |
| 원문이 짧은데 표준이라 부를까 | **원문이 우리보다 아는 게 없으면 참조가 아니다.** 한 줄 출처 표기로 내린다 |
| `references/` 를 지울까 | **지우지 않는다.** 요약의 근거를 대조할 유일한 자리다 |
| 본문에서 `references/` 를 가리킬까 | **안 가리킨다** — 위 4. 출처 한 줄만 맨 아래에 둔다 |
| 원문이 길어서 요약할까 | **본문에서는 요약한다, 보관본은 통째로 둔다** — 둘은 따로 산다 |
| 원문 파일이 서로 겹친다 | 상류의 중복은 상류 사정이다. 보관본은 통째로 두고, 본문 요약에서 한 번만 적는다 |
| 스크립트가 딸려 있다 | 전제(저장 위치·도구·규모)가 다르면 **안 가져온다.** 안 쓸 것을 만드는 스크립트가 제일 흔하다 |
| 스킬이 아니라 훅·룰 감인가 | 규범 **[Layer Triage]** 가 가른다 — 빠뜨리면 치명적이면 훅, 특정 파일 영역에서만 걸리면 `paths` 룰 |
