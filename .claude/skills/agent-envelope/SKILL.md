# 에이전트에게 일을 시킨다

**이 스킬은 일을 나눠 주는 부모 세션이 읽는다.** 일을 받는 서브에이전트(이하 **레인**)는 이 파일을
보지 않고, 부모가 써 준 작업 지시서(이하 **봉투**)만 받는다. 그래서 봉투에 무엇을 실을지가 부모 몫이다.

**하네스 몫은 안 옮긴다** — 띄우기·여럿 한꺼번에 띄우기·백그라운드·완료 통지·이어가기·모델
지정·worktree 격리는 도구 계약이 세션에 싣고, 대규모 오케스트레이션 스크립트는 그쪽
스킬(workflow-authoring)이 맡는다. 여기는 도구 계약이 적지 않는 규율, 곧 레인끼리 부딪히거나
결과를 못 믿게 되는 자리만 다룬다.

- **근거 원칙** — 규범 **[Single Source · Point or Derive]** · **[Goal-Driven Execution]** · **[Root Cause Fix]**

## 1. 가르기 전 — 병렬을 열 수 있나

- **찾기·재기는 언제든 병렬이다. 고치기는 한 손이거나 worktree 격리다** — 같은 트리에
  쓰는 손이 둘이면 늦게 쓴 쪽이 이기고, 검사는 서로의 반쯤 고친 코드 위를 돈다
- 구현 병렬은 셋이 함께 설 때만 연다 — **worktree 격리 · 봉투에 소유 선긋기 · 부모 한 손 머지**
- **누가 무엇을 맡는지는 파일로만 가르지 않는다** — 실행 중에 붙잡는 자원도 나눠야 한다. 한 번에
  하나만 뜨는 자동화 서버(오피스 COM 류) · 포트 · 기준 스냅샷(골든) · 공용 검사는 파일 표에 안
  잡히고, worktree 격리도 파일만 가른다
- 같은 트리에서 여럿이 재면 **재는 자가 제 소스 지문(해시)을 산출에 같이 찍게 한다** —
  재는 도중 트리가 움직이면, 지문 없는 측정은 어느 판 위에서 났는지 증명이 안 된다
- **레인을 한꺼번에 죽이는 것을 띄우기 전에 센다** — **세션 토큰 한도(429)와 동시 실행 상한**은 레인 하나가
  아니라 한꺼번에 띄운 묶음 전체를 같이 죽인다. 한 번에 몰수록 한도 하나에 여러 레인이 함께 죽으니 무거운
  일은 나눠 띄운다. 상한·리셋 시각 같은 수는 재 봐야 나오므로 그 저장소 메모리가 맡는다

## 2. 봉투를 짓는다

**과업 원본이 곧 봉투다** — 문제·실측·갈래·재는 법·경계는 원본(이슈)이 들고, 봉투에는
좌표와 이 판의 규율만 얹는다(이슈 골격은 issue-write 스킬). **이력을 붙여넣지 않는다** —
봉투가 원본을 옮겨 적기 시작하면 그 순간 두 벌이 되고, 봉투는 대화 내내 컨텍스트에 산다.

**원본은 레인이 직접 연다** — 부모가 본문을 사본 파일로 옮겨 적지 않는다: 옮기는 순간
두 벌이고(낡는 쪽은 늘 사본), 옮겨 적기 자체가 봉투마다 이중 일이다. 봉투에는 원본의
주소(이슈 번호)만 싣고, 릴레이가 본문을 손대는 판(따옴표를 엔티티로 굳히는 류)은 **푸는
법 한 줄**을 곁에 적는다. 재는 법의 코드가 전달 도중에 잘렸으면 레인이 곁의 서술을 보고 다시 짓는다.

봉투에 미리 가르는 것 — 뒤늦게 가르면 머지에서야 드러난다:

| 칸 | 무엇 |
|---|---|
| 소유 | 파일/구역 + 붙잡는 자원 + **그 실물을 역산한 Reference 문서**(코드를 고친 손이 같은 봉투에서 문서도 고친다 — 문서만 따로 레인을 세우지 않는다) · **안 볼 것**까지 — 겹침은 소유가 아니라 「안 봄」이 막는다 |
| 이름 | 표찰(라벨·앵커) · 산출/보고 파일 경로 — **레인마다 다르게.** 같은 이름은 서로 덮는다 |
| 모델 | **판단이 드는 레인은 `opus` 로 적는다** — 조사든 고치기든. **판단 없이 정해진 차례만 밟는 심부름**(넓게 훑어 자리 찾기 · 표 뽑기 · 정해진 검사 결과 가져오기)은 `sonnet` — 스크립트로 되면 레인을 안 띄운다(규범 [Determinism First]) |
| 산출 계약 | 발견마다 `파일:줄` + 실패 시나리오 — 없으면 인상이라 안 받는다 · **안 잰 것·안 본 것을 이름으로** · **0건도 유효한 보고다** — 없으면 없다고 쓰고 어디까지 봤나를 댄다(채우려고 지어내면 그것이 인상이다) · 화면이면 그림 경로와 「무엇이 보이나」를 사람 말로 · **탐침은 트리를 인자로 받게 짓는다** — 경로를 박으면 부모의 전/후 재기가 헛돈다 |

⚠ **봉투가 가리키는 좌표가 실재하는지 부모가 먼저 확인한다** — 원본 본문이 낡았을 수 있다.
레인에도 같은 확인을 시키고, 없으면 **고치지 말고 보고하라**고 적는다.

**레인이 다른 저장소의 규격을 옮겨 오는 판이면 봉투에 borrow-spec-as-pair 를 싣는다** — 레인은
스킬을 안 읽으므로 짝을 세는 규율은 봉투가 이름으로 든다.

**봉투와 레인의 말은 영어다. 한국어는 사람이 직접 여는 파일에만 쓴다** — 모델 안의 매체는 영어라
봉투를 한국어로 쓰면 레인이 매 문장을 옮기며 읽고, 중간 산출도 한 번 더 옮긴다. 레인이 돌려주는 보고도
영어다 — 사람은 그것을 직접 안 읽고 부모가 풀어 전하므로, 한국어로 시키면 옮김만 한 번 는다. 레인이
**사람이 열 보고서 파일**을 남길 때만 그 파일을 한국어로 시킨다(옮김의 규율은 규범 [Cross-Cultural
Recoupling]). 좌표·이름·따옴표 안의 실물 문자열은 원문 그대로다 — 옮기면 못 찾는다.

## 3. 레인 절대 규칙 — 이 블록을 봉투에 그대로 싣는다

레인이 읽는 말이라 영어다(2절). 부모는 뜻을 알고 싣는다 — 옮겨 적지 않는다.

    ① Own exactly one envelope. Read neighbouring files, never edit them — another lane is there.
    ② Never touch anything outside your ownership. Report defects you find there; do not fix them.
    ③ Never run golden/snapshot blessing (bless-style commands) — a human reads the full text and approves.
    ④ A "could not measure" mark counts as red — never say "done" while one stands.
    ⑤ If tightening a check turns green into red, fix the check and the specimen in the same pass.
    ⑥ Never change state through git. The parent commits — leave changes uncommitted in the worktree.
    ⑦ Never derive expected values from what you measured. Write why the value must be what it is; if the measurement differs, report it.
    ⑧ Before reporting "absent", run a positive control — first ask whether the specimen really has that shape.
    ⑨ Never run commands that print the environment or the process list (env, printenv, set, ps aux, pgrep -af) — they write secrets into the transcript.

레인 갈래에 맞게 **덜어내되 더하지 않는다** — 읽기 전용 재기 레인이면 ③⑤ 는 안 걸릴 수 있다.

## 4. 레인 결과 거두기 — 부모가 지는 것, 레인에 못 넘긴다

- **부모 확인은 재검이 아니라 시야다** — 봉투가 좁힌 시야 밖을 부모가 본다. 제 손으로
  재는 것은 넷: 소유 밖 형제(레인이 고친 무늬를 grep) · 레인 목록 밖 곁 검사 전수 ·
  레인이 옮겨 적거나 다시 쓴 덩어리의 원본 대조 · 레인이 올린 「부모가 가를 것」. 그림은
  눈으로 연다
- **레인이 돌린 검사와 물림은 다시 돌리지 않는다** — 물림은 일부러 틀린 표본을 넣어 검사가 정말
  빨강을 내는지 보는 단계다. 새 판정을 물리는 손은 레인이고 봉투가 시킨다. 보고에 건수·물림 결과·트리
  지문이 있으면 받는다. diff 는 읽는다 — 커밋 안 된 worktree 에서 `git checkout` 으로 되돌리면
  곧 지우는 것이라, 되돌려 볼 일은 사본에서 한다
- 레인 여럿의 산출은 **교차 중복부터 걷는다** — 같은 자리를 두 축이 문다
- **소유 밖 발견은 부모가 가른다**(갈래 셋은 issue-write) — 지금 고칠 것이면 그 자리를
  쥔 레인에게, 없으면 발견한 레인에 소유를 넓혀서(맥락을 이미 쥐어 새 봉투보다 싸다).
  넓힌 소유는 봉투에 적는다
- **넘김은 받는 이슈에 줄을 남긴다** — 마감 코멘트에만 적으면 증발한다
- **worktree 레인의 변경은 파일로 거둔다** — 봉투가 소유를 갈라 두었으므로 레인이 손댄 파일은 본 클론의
  것과 겹치지 않는다. **겹치지 않는 변경에 병합기는 필요 없다**: 그 파일들을 그대로 복사하고, 거둔 것이
  레인 트리와 같은지 **해시로** 견준다 — 줄 수는 같은 수로 다른 내용이 지나간다. 복사해 오면 부모 커밋이
  훅을 그대로 탄다.
  ⚠ **패치로 옮기는 길은 작업 사본의 줄끝이 색인과 다른 설정에서 죽는다** — 트리에서 뽑은 diff 가 본 클론에
  안 붙고 「필요한 blob 이 없다」나 「적용되지 않는다」로 끝난다. 그래서 패치는 소유가 **겹쳐서** 진짜 병합이
  필요한 판에서만 쓴다(`git -C <트리> diff --cached --binary` → `git apply --index --3way`, 새 파일까지
  실으려면 트리에서 먼저 담는다). 그 길로 왔으면 둘을 더 한다: 충돌을 스크립트로 풀었을 때 끝에 충돌
  표식(`<<<<<<<` · `=======` · `>>>>>>>`)을 **반드시 grep 한다**(리졸버가 한 파일에서 멈추면 뒤 파일이
  미해결인 채 담긴다) · `apply`·`cherry-pick` 은 커밋 훅을 안 타므로 게이트를 본 클론에서 손으로 돌린다
- **남은 작업 트리를 걷는다** — 격리 트리는 저장소 **안** `.claude/worktrees/<이름>/` 에 선다. 변경이 남은
  트리는 옛 판의 사본이라 저장소를 통째로 훑는 검사가 그것까지 잡는다.
  거두기가 끝나면 `git worktree remove --force` 와 `git branch -D worktree-*` 로 걷는다

## 갈리는 자리

| 갈리는 자리 | 어느 쪽 |
|---|---|
| 파일 소유로 갈랐는데 겹쳤다 | 파일 밖 자원(단일 기계·포트·골든)을 다시 센다 — 1절 |
| 고침이 작아 물림을 건너뛸까 | 안 된다. 한 번도 빨강을 못 낸 검사는 통과하도록 짠 검사와 구별되지 않는다 |
| 레인 보고가 길고 자세하다 | 길이는 판정이 아니다. 좌표·시나리오·안 잰 것 셋이 있나만 본다 |
| 봉투를 더 채워 줄까 | 짧은 것이 옳다. 원본 좌표 + 이 판의 규율이면 끝 — 붙여넣은 이력은 값이 아니라 비용이다 |
| 레인이 곁 결함을 고쳐 왔다 | 시키지 않은 소유 밖 고침은 받지 않는다 — 보고로 되돌리고, 가름은 4절 「소유 밖 발견」이 맡는다 |
| 봉투를 한국어로 쓸까 | 안 쓴다 — 2절. 레인이 돌려주는 보고도 영어고, 사람이 직접 여는 보고서 파일만 한국어다 |

## 왜 참조가 없나

기준선이 **하네스 자체**다 — 도구 계약이 세션에 이미 실려 있어 옮겨 적으면 사본이 된다.
