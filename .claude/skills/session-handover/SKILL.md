# 세션 핸드오버

> **다음 세션이 이번 세션을 다시 겪지 않게 한다.**
> 이 파일 하나가 전부다 — 다른 파일을 열 필요 없이, 아래 골격대로 쓴다.
> 단 하나, **쓰기 전에 직전 인계 본문을 연다** — 골격의 실물 예시다.

## 언제 쓰나 — 층이 먼저다

**핸드오버는 이어달리기 바통이다 — 아무 미완이나 바통이 되지 않는다.**
닫는 자리에서 셋으로 가른다:

1. **다 끝났다** → 안 쓴다. 닫힌 일은 진본(이슈·커밋·ADR)이 들고, 남길 경위는
   이슈 마감 코멘트가 받는다
2. **덜 끝났는데 단순하다** — 남은 것이 목록으로 다 말해진다 → **이슈 코멘트면
   끝이다.** 핸드오버를 안 세운다
3. **덜 끝났고 경위가 실린다** — 헤맨 순서·기각·세션 층 판단·전제를 모르면 다음
   세션이 이 세션을 다시 겪는다 → **그때만, 한 번** 쓴다

가르는 물음 하나 — **이슈 코멘트로 다 말해지는가.** 말해지면 핸드오버가 아니다.
세션 중간에도 쓰지 않는다 — 진행 중에 남길 것이 생기면 그것은 핸드오버가 아니라
**그 자리 진본**에 적는다:

| 무엇이 생겼나 | 어디에 적나 — 핸드오버 아님 |
|---|---|
| 작업이 됐다 · 남았다 · 다음 무엇 | **이슈** — 작업큐 진본. 마감·경과는 이슈 코멘트 |
| 결정이 섰다 · 뒤집혔다 | **ADR** (`adr-and-source-together`) |
| 코드·문서가 바뀌었다 | **커밋** — 뜻은 커밋 메시지가 든다 |
| 세션이 끝난다 | **핸드오버** — 위 셋이 못 드는 것만 |

축이 다르다 — **이슈는 일의 상태**를 든다(살아 움직이고 세션을 넘어 산다).
**핸드오버는 세션의 경위**를 든다(닫는 순간 굳고, 그 세션에서만 아는 것 —
헤맨 순서·기각·세션 층 판단·다음 첫 일의 좌표). 둘이 같은 상태를 나눠 들면
**반드시 한쪽이 낡는다** — 상태는 움직이는데 핸드오버는 닫는 순간의 사진이라서다.

⚠ **닫은 뒤 세션이 이어지면** — 이미 쓴 핸드오버를 일이 생길 때마다 따라 고치지
않는다. 새로 벌어진 일은 제 진본(이슈·커밋)에 쌓고, **다시 닫는 자리에서 한 번**
그 좌표로 갱신한다.

## 원칙 넷

1. **[Coordinates Not Copies]** — 사실은 진본에 두고, 핸드오버는 그리로 가는 좌표만 든다.
   옮겨 적으면 낡는다. 실측한 값은 박는다(굳는 문서 — 규범 [Docs-as-Code · State Only] 의 예외).
   **같은 법이 층마다 든다** — 본문의 진본이 이슈·커밋이듯, 목차 줄의 진본은 본문이다.
   줄이 문단으로 자라거나 낡은 ⚠ 를 이고 있으면 좌표가 사본이 된 것이다.
2. **[Path Over Conclusion]** — 결론이 아니라 경로를 남긴다. 헤맨 순서 그대로 —
   정리하면 다음 세션이 그 사고를 못 겪는다.
3. **[Open Before Closed]** — 안 닫힌 것이 먼저다. 미결·기각·잠정 의견을 남긴다.
   닫힌 것은 진본이 든다.
4. **[Queue Chain]** — 큐는 완료·미완을 함께, 순서 있는 목록으로. 앞 큐가 뒤 큐의 근거다.

## 골격 — 절 이름과 순서

머리말(frontmatter): `name` · `description`(한 단락 요약 — 목차가 이 줄을 쓴다) ·
`metadata`(`node_type: memory` · `type: project`)

| 절 | 무엇 |
|---|---|
| **지금 상태** | 한 단락 — 무슨 일이었고 어디서 멈췄나. ⚠ 다음 세션 첫 일을 굵게 |
| **한 일** | 체크박스 목록, 짧게 — 상세는 이슈·커밋이 든다 |
| **내린 판단** | 표 `판단 \| 고려한 갈래 \| 왜` — **세션 층 판단만.** ADR·이슈에 든 것은 좌표만 |
| **안 닫힌 것** | 순서 있는 목록 — 첫 항목이 다음 세션의 첫 일 |
| **막힌 것 · 열린 물음** | 체크박스 — 무엇이 필요해 막혔나까지 |
| **미룬 것** | 왜 미뤘나까지 |
| **헤맨 순서** | 시간 순 그대로. 기각한 방향은 이유까지, 두 번 실패한 것은 **⚠ 다음에 의심할 것**까지 |
| **기각한 방향** | 표 `무엇 \| 왜 기각했나` — 다시 가지 말라고 남긴다 |

## 무엇을 안 적나

| 무엇 | 어디가 든다 |
|---|---|
| 아키텍처·핵심 파일·수정 파일 목록 | 설계도 · `git log` |
| 확정된 설계·계약·규약 | 진본 문서 |
| 잘 돌아간 일의 상세 | 짧게 — 닫힌 것은 진본이 든다 |
| 큐 항목의 끝 조건 | `roadmap-doc` 스킬 |

**없으면 없다고 적는다** — 번호·파일명·순서를 기억이나 목차에서 지어내지 않는다.

## 쓰는 절차

1. `claude-config/memory/<프로젝트>/project_handover_YYYY_MM_DD_<주제>.md` 로 쓴다
2. `MEMORY.md` 맨 위에 **좌표 한 줄**만 단다 — 내용을 옮기지 않는다(로드 한도에 잘린다)
3. **저장소로 되돌린다** — commit·push. 메모리는 기계마다 따로 살아, 밀어야 최신이 된다
   (경로·흐름은 `claude-config/README.md` §프로젝트 메모리)

## 이어받는 절차

- **목차가 아니라 본문을 연다** — 세션 첫 행동이고 도구 호출·보고보다 앞선다.
  핸드오버가 *"착수 전 필독"* 으로 가리킨 문서도 작업 전에 연다
- **적신호 — 멈추고 사용자에 확인한다**: 핸드오버의 전제(브랜치·머지 상태·파일 위치)가
  실측과 어긋날 때. 리모트 컨테이너는 원격 참조가 낡아 있을 수 있다 — **대조 전에 fetch**
