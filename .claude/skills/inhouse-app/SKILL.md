# 사내 앱을 세운다

사내 앱에서 **어려운 문제는 LLM 게이트웨이다** — 스트림이 끊기는 시한, 조용히 삼켜지는 필드, 없는 모델, 사내
인증서. 회사 코딩 기준은 쉬운 원칙(시크릿 · 서버 쪽 호출 · 프롬프트 분리)은 옳지만 이 자리에 답이 없고, 문자
그대로 따르면 틀리는 자리가 있다. 그래서 차례는 **우리가 잰 것 → 구현에서 배운 것 → 길 가르기 → 회사 기준**이다.

- **근거 원칙** — 규범 **[Recall Priority]** · **[Look Before Ask]** · **[Single Source · Point or Derive]**

## 1. LLM 은 우리 실측을 따른다

**새로 짜지 않는다 — 씨앗에서 출발한다.** `~/.claude/seeds/gateway/` 가 게이트웨이 배관이다: 계약 넷(Anthropic ·
OpenAI · Gemini · 로컬 CLI) · 스트리밍 · 잘린 출력 이어 쓰기 · 실측 상한. 그 폴더의 `README.md` 가 복사하는 법을 든다.

**사실의 원본은 `~/.claude/posco/ENV-posco.md` 다** — 「우리가 잰 것」 표와 「요청이 지나는 층」 표, 모델 목록은 그
머리말. 출력 상한은 씨앗의 `app/gateway.py`(벽에서 역산한 `WALL_MAX_TOKENS` 와 모델별 천장)가 든다. 설계를 가르기
**전에** 연다. 값은 거기서 읽고 여기 옮기지 않는다 — 게이트웨이는 예고 없이 바뀐다.

그 표가 가르는 설계 — 코드를 짜기 전에 하나씩 답한다:

| 물음 | 왜 먼저 묻나 |
|---|---|
| 한 번 부르는 데 오래 걸리나 | 스트림은 **요청 시작부터** 재는 시한에 신호 없이 잘린다. 심장박동으로 못 넘는다 — 한 번에 내는 양을 벽 안쪽으로 잘라 이어 쓰거나(씨앗의 길) 비스트리밍으로 비껴간다. 생각이 길어 침묵하는 판은 이어 쓰기로도 못 넘는다 |
| 도구를 쓰나 | 비스트리밍으로 받으면 큰 도구 인자가 **빈 채로** 정상처럼 온다. 도구를 쓰면 스트림을 버리지 않는다 — 위 물음과 부딪히는 자리다 |
| 구조화된 출력이 필요한가 | 회사 명세상 JSON 모드는 chat/completions 경로에만 있다(**명세다 · 우리가 잰 것이 아니다**). Claude 경로에서는 도구 스키마로 받는다(스트림으로) |
| 새 파라미터 · 새 블록을 쓰나 | 모르는 것을 400 이 아니라 **200 에 조용히 버린다.** 규격에 있어도 프로브로 먼저 잰다 |
| 어느 모델인가 | 목록은 문서가 아니라 `GET /v1/models` 에 묻는다 — 문서에 없는 모델이 돌고, 있을 법한 모델이 없다 |
| 캐시를 쓰나 | Anthropic 계약은 `cache_control` 표식을 단다(걸리는 것은 잼). OpenAI · Gemini 계약은 접두사가 맞으면 자동이라 표식을 달지 않는다 — 달면 조용히 삼킨다. 표식 없는 Anthropic 캐시가 걸리는지는 안 쟀다 |
| 오류를 어떻게 가르나 | HTTP 상태가 아니라 **오류 코드**로 가른다 — 상태 매핑이 문서와 다르게 온다 |

## 2. 구현에서 배운 것 — 회사 기준이 안 드는 자리

| 자리 | 이렇게 한다 | 안 하면 |
|---|---|---|
| 인증서 | 검증을 끄지 않는다. 사내 CA(`~/.claude/posco/corp-ca.pem`)를 신뢰 저장소에 싣는다 — 파이썬은 `truststore`, Node 는 `NODE_EXTRA_CA_CERTS` | 끈 채 배포되면 가로챈 연결도 받는다 |
| 게이트웨이 주소 | 환경변수로 받는다 | 개발 · 운영 · 루프백 프록시를 바꿀 때마다 코드를 고친다 |
| 로그인 없는 앱의 키 | 사용자 키를 요청마다 받고 서버는 저장하지 않는다. 브라우저에 둬야 하면 localStorage 가 아니라 HttpOnly · SameSite=Strict 쿠키 | 앱이 그리는 HTML 의 스크립트가 같은 출처에서 돌아 키를 읽는다 |
| 출력 상한 | 게이트웨이 경로에서는 씨앗의 벽 안쪽 상한(`WALL_MAX_TOKENS`)으로 끊고 이어 쓴다. 모델별 상한은 그 위의 천장일 뿐이다 | 모델 최대치로 두면 긴 답이 벽에서 신호 없이 잘려 「끝났나 · 잘렸나」를 못 가르고 이어 쓰기가 안 붙는다. 천장을 넘기면 400 과 빈 스트림이다 |
| 요청 검증 | 경로마다 요청 모양을 선언하고 **한 관문**에서 잰다. 틀리면 4xx(FastAPI 는 기본 422 — 회사 예제 테스트가 그 값을 본다) | 타입 틀린 필드 하나가 파이썬 문구와 함께 500 을 낸다 |
| 오류 문구 | 사내 사용자에게는 게이트웨이가 준 까닭(시간 초과 · 거절 문구)을 보인다. 스택은 안 보인다 | 「오류가 났습니다」만 남아 사용자가 다시 눌러 볼 수밖에 없다 |
| 로그 | `print` 가 아니라 `logging` | 두 스레드의 줄이 한 줄로 섞인다 |
| 원문을 옮기는 앱 | HTML 제거 · 개인정보 가림 · 행 자르기 같은 전처리로 입력을 깎지 않는다 | 앱이 지켜야 할 충실도를 입력에서 먼저 잃는다 |

## 3. 길을 가른다 — 회사 방식으로 배포하나

| 길 | 어디까지 따르나 |
|---|---|
| 사내 PC · 사내망에서 사람 손으로 띄우는 도구 — 회사 인프라(SR · 회사 GitLab · SSO · 발급 DB)를 안 쓴다 | 1 · 2 까지. 회사 기준의 배포 · SSO · DB 조항은 걸리지 않는다 |
| 운영팀 SR → 회사 GitLab → CI/CD 로 배포하는 앱 | 4 까지 |

**모르면 묻는다** — 이 갈림은 사용자만 안다.

## 4. 회사 방식으로 배포할 때만 — 회사 기준

회사 기준 본문은 씨앗 `~/.claude/seeds/vibecoding/` 이 든다(들머리 `SEED.md` · 판은 곁의 `.version`). 여기 옮기지
않는다 — 회사가 고치면 씨앗이 다시 뽑힌다. 하려는 일에 맞는 장을 **그때 연다**:

| 하려는 일 | 여는 장 |
|---|---|
| 시작 인터뷰 · 폴더 구조 | `docs/guides/futurem-fastapi-workflow.md` 와 공통 규약 `continue-rules/vibe-coding-standards.md` |
| SR · 배포 | `docs/guides/futurem-deploy.md` — 미리 신청할 것(저장소 · DB · CI 변수)부터 |
| SSO | `docs/guides/futurem-sso.md` |
| 앱 안 권한 | `docs/guides/futurem-role-management.md` · `docs/references/futurem-role-model.md` |
| 레이어별 규약 | `docs/references/futurem-routers.md` · `futurem-services.md` · `futurem-repositories.md` · `futurem-adapters.md` |
| 메일 · 문자 · DataBridge · UI | `docs/guides/` 의 `futurem-smtp.md` · `futurem-sms.md` · `futurem-databridge-rest.md` · `futurem-databridge-mcp.md` · `futurem-uxui-guide.md` |

**그대로 따르면 틀리는 자리 — 덮어쓴다:**

| 회사 문서 | 이렇게 한다 | 까닭 |
|---|---|---|
| LLM 은 `llm_gateway.complete()` · `AI_GW_URL` · `AI_GW_TOKEN` | 이름은 따르되 속은 1 의 씨앗으로 짓는다 | 함수 파일이 묶음에 없다. 한 주소 · 한 토큰으로는 계약 셋을 못 나타낸다 |
| 출력 스키마 강제 · JSON 모드 | Claude 경로는 도구 스키마로 | Claude 경로에 JSON 모드가 없다 |
| 긴 LLM 출력을 SSE 로 브라우저에 흘린다 | 1 의 시한을 먼저 본다 | 스트림 시한에 신호 없이 잘린다 |
| 예제 `max_tokens` | 2 의 상한 규칙 | 예제 값은 긴 출력에 작다 |
| SSO 가이드의 `SSO_SSL_VERIFY=false` 기본값 | 켠다(2 의 인증서) | 검증을 끈 기본값이다 — 회사 메일 가이드는 오히려 끄지 말라고 한다 |
| SSO 콜백 경로 | 가이드(`/auth/sso/relay`)와 권한 예제(`/sso/callback`) 중 **하나로 맞추고** 미들웨어 예외 경로도 같이 | 섞으면 로그인이 무한 반복된다 |
| SSO 검증 주소를 요청의 `domainName` 으로 짓는 예제 | 서버 환경변수에서만 짓는다 | SSRF 다 — 회사 SSO 가이드 스스로 금지한다 |
| 권한 예제가 SSO 토큰을 세션에 저장 | 검증 뒤 버린다 | 회사 SSO 가이드와 어긋난다 |
| 세션 쿠키 `https_only=True` 와 HTTP 앱 주소 | 앱이 HTTPS 로 서는지 먼저 확인한다 | HTTP 에서는 Secure 쿠키가 안 실려 로그인이 돈다 |
| UI 가이드의 jQuery UI · 권한 예제의 Jinja | 공통 규약(순수 HTML · 프레임워크 금지)을 따른다 | 회사 문서끼리 어긋난다 |
| 고정된 requirements | 실제로 깔리는지 먼저 돌려 본다 | 회사 예제가 쓰는 패키지 일부가 빠져 있고, 고정 판이 파이썬 3.14 에 안 깔릴 수 있다 |

**우리 규범과 갈리는 자리** — 회사 저장소 안에서는 브랜치와 커밋 꼴을 운영팀 안내대로 따른다(우리 저장소의 「main 에
바로」는 거기서 안 선다). 규약과 부딪히는 요청은 실행을 막지 않고 **먼저 알린 뒤 사용자가 정한다.**

## 참조가 없는 까닭

바깥 표준이 없다 — 사내 게이트웨이와 회사 기준은 이 회사에만 있다. 회사 기준의 원문은 씨앗이 바이트 그대로 들어
`references/` 에 또 두지 않는다(두면 사본이다). 이 판의 근거 조사는 설정 저장소 `docs/research/2026-09-28-company-standard/`
가 든다.
