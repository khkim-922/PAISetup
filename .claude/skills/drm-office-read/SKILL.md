# 감긴 파일은 파서가 아니라 앱이 연다

Fasoo DRM 은 파일을 **통째로 자기 컨테이너로 감싼다.** 확장자는 그대로인데 머리 바이트가
바뀌므로, 형식을 시그니처로 판별하는 모든 파서가 인식 단계에서 죽는다.
**Fasoo 에이전트가 도는 PC 의 오피스 앱은 그 보호를 풀어 연다** — 에이전트가 오피스 프로세스 안에서 푼다. 그래서
파서를 바꿔 끼우는 대신 앱을 태운다. 에이전트가 없는 PC 에서는 오피스도 그 파일을 「손상됐다」 · 「형식이 잘못됐다」로
못 연다 — 읽기는 회사 PC 의 일이다.

문서를 파일째(원형 문서 블록) 넘기면 버리는 게이트웨이에 그 문서를 실을 때도 이 자리다 — 글자로 바꿔
넘겨야 하는데 그 글자를 뽑을 파서가 죽는다.

## 1. 감긴 것인지 먼저 판별한다

파서가 죽으면 파서를 바꿔 끼우기 전에 머리 바이트부터 본다.

```bash
python -X utf8 -c "print(open(r'<경로>','rb').read()[:12])"
```

머리가 평문 형식(PDF · OOXML · RTF · 옛 오피스 OLE)의 시그니처면 감기지 않았다 — 보통 파서로 읽는다.
그 밖이면 감겼다(Fasoo 는 머리에 `DRMONE` 이 보인다) — 아래 2로 간다.

⚠ **git 저장소 안이면 커밋된 판을 먼저 본다** — DRM 은 **작업트리 파일만** 덮어쓰므로 커밋된 판은 평문인
채 남는다. `git show HEAD:<경로>` 로 꺼내 머리를 다시 보고, 평문이면 그 판을 읽는다. 같은 성질 때문에 감긴
파일은 매번 `git status` 에 수정으로 뜬다.

## 2. 앱을 태워 글자를 뽑는다

`scripts/read-drm.ps1` 이 든다. 파일이든 폴더든 받고, 확장자로 앱을 골라 확장자별로 한 번만 띄운다 —
앱 생성이 건당 수 초라 **파일은 한 번에 몰아 넘긴다.**

```bash
# 폴더 통째 — 지원 확장자를 훑어 글자를 파일로 뽑는다
powershell -NoProfile -ExecutionPolicy Bypass \
  -File "<이 스킬>/scripts/read-drm.ps1" "<폴더>" -OutDir "<나갈 폴더>"
```

⚠ **파일 여럿을 줄 때는 `-Command` 로 콤마 배열을 넘긴다** — `-File` 은 뒤따르는 인수를 낱낱의
문자열로 넘겨 배열 파라미터에 묶이지 않는다.

```bash
powershell -NoProfile -ExecutionPolicy Bypass -Command \
  "& '<이 스킬>/scripts/read-drm.ps1' -Path '<파일1>','<파일2>' -Preview 120"
```

`-OutDir` 를 빼면 화면에 앞부분만 낸다(`-Preview` 로 길이 · `0` 이면 셈만).

확장자마다 어느 앱이 맡나는 스크립트 머리의 표가 든다 — 글 문서는 워드, 시트는 엑셀, 슬라이드는
파워포인트다.

⚠ **`.pdf` 도 워드로 연다** — 워드는 PDF 를 변환해 열어 글자가 다 오고, Acrobat COM 은 아크로뱃을 깔아도
클래스가 등록되지 않는 판이 있어 기댈 수 없다.

앱이 안 뜨면 오피스가 깔렸나·그 계정으로 활성화됐나를 본다. **사람이 로그온한 대화형 세션에서 돌린다** —
서비스·무인 스케줄러에서는 대화창이 떠 멈출 수 있다.

## 3. 뽑은 글자는 원문이 아니라 추출본이다

앱이 뽑은 글자에는 잡음이 섞이므로 **인용하기 전에 원문과 대조한다.** 잡음은 두 꼴로 온다:

- **줄바꿈 자리에 `/` 가 낀다** — 붙은 낱말은 원문에서 확인한다
- **표의 마지막 칸이 빌 수 있다** — 워드의 글자 뽑기가 끝 칸을 흘릴 때가 있다. **표는 다른 엔진이나 앱
  화면으로 한 번 더 본다**

⚠ **수치·표·고유명사는 그 자리를 눈으로 확인한다** — 산문은 잡음이 눈에 걸리지만 숫자는 틀린 채 조용히
지나간다.

### PDF·Word의 페이지를 그림으로 확인한다

`read-drm.ps1`의 Word 경로는 `Document.Content.Text`를 읽는다. Word가 PDF를 이미지·도형·머리글로
변환하면 화면에 보이는 글자가 빠질 수 있고, 글자가 모두 나와도 표와 주변 문장의 위치 관계는 평탄해진다.
추출 글자가 지나치게 짧거나 표·그림·워터마크·배치가 중요하면 `scripts/capture_pages.ps1`로 페이지 전체를
PNG로 꺼내 직접 본다.

```bash
powershell -NoProfile -ExecutionPolicy Bypass \
  -File "<이 스킬>/scripts/capture_pages.ps1" -Path report.pdf

# 필요한 쪽만
powershell -NoProfile -ExecutionPolicy Bypass \
  -File "<이 스킬>/scripts/capture_pages.ps1" -Path report.docx -Pages "1,3"
```

이 길은 Word의 `EnhMetaFileBits`를 메모리에서 받아 PowerShell이 PNG로 쓴다. Office의 내보내기나
다른 이름으로 저장을 쓰지 않으며 원본은 읽기 전용으로 열고 저장하지 않는다. 결과 경로가 출력되면 이미지
도구로 열어 확인한다. `.pdf`·`.docx`·`.doc`·`.rtf`만 맡고, 슬라이드는 아래 전용 캡처를 쓴다.

## 4. 덱을 검수한다 — 배치는 재고, 인상은 본다

덱(pptx)을 만든 뒤 검수는 두 갈래이고 잡는 결함이 다르다. 둘 다 파워포인트를 COM 으로 태운다 — 공식 `pptx`
스킬의 변환 길(soffice → pdftoppm)은 DRM 이 **디스크에 쓰는** 산출물을 가로채는 자리에서 안 선다.

### 배치 — `scripts/audit_layout.ps1`

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "<이 스킬>/scripts/audit_layout.ps1" -Path deck.pptx
```

넘침 · 겹침 · 가장자리 여백(스크립트 기준값)을 파워포인트가 **직접 잰 글 높이**로 보고, 이상이 없으면 그렇게 말한다.
고치는 동안은 이쪽만 돌린다 — 빠르고 비전 토큰이 안 든다.

⚠ **글꼴이 없으면 판정이 한쪽으로 기운다.** 맑은 고딕이 없는 자리는 대체 글꼴이 더 넓게 잡혀 —
「안 넘쳤다」는 믿어도 되고 「넘쳤다」는 거짓 경보일 수 있다. 그 판정으로 글을 줄이기 전에 실물을 본다.

### 인상 — `scripts/capture_slides.ps1`

DRM 은 디스크에 쓰이는 것을 막지 화면에 그려진 것은 막지 않는다. 그래서 **디스크를 거치지 않는다** —
슬라이드쇼로 화면에 띄우고 화면 버퍼를 직접 읽는다. 내보내기 · PDF 변환처럼 파일을 쓰는 길은 파일이 생겨도
감겨 있어 안 열린다.

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File "<이 스킬>/scripts/capture_slides.ps1" -Path deck.pptx -Slides "1,8"
```

찍은 그림에서는 **재서는 안 보이는 것** — 색 대비 · 활자 인상 · 여백 균형 — 을 본다. 스크립트가 긴 변을
줄여 낸다. 게이트웨이를 지나는 환경이면 그림이 보이는 조건을 그 환경 문서의 그림 절에서 본다.

⚠ **한글 낱말이 줄 끝에서 반으로 갈리는 결함은 이 길로만 잡힌다** — 배치 검사는 통과한다. 파워포인트는
문단의 `eaLnBrk="0"` 과 런의 `lang="ko-KR"` 이 **함께** 있어야 한국어 줄바꿈 규칙을 적용한다. 그래도 한
낱말이 한 줄보다 길면 갈리니, 그때는 내용이 맡는다 — 구분자 앞뒤에 공백을 두거나 갈리면 안 되는 자리에서
직접 줄을 바꾼다.

**손으로 짜야 하면 `capture_slides.ps1` 을 읽는다** — 차례가 곧 함정 회피이고 까닭은 그 파일 주석이 든다.
창은 프로세스 Id 로 활성화한다 — `SlideShowWindow.HWND` 는 비어 오는 판이 있다.

⚠ **찍힌 그림이 그 슬라이드인지 먼저 본다** — 다른 창이 전경을 쥐고 있으면 엉뚱한 창이 찍혀도 파일은
멀쩡히 생긴다.

⚠ **캡처는 마무리에 핵심 한두 장만 한다** — 그림은 치수만큼 값이 든다. 여러 장을 봐야 하면 이어 붙여 한
장으로 연다.

## 갈리는 자리

| 갈리는 자리 | 어느 쪽 |
|---|---|
| DRM 을 풀어 평문으로 저장할까 | **읽기만 한다** — 보호 해제는 사내 정책과 권한의 일이다 |
| 파워포인트 창이 떠서 방해된다 | 그 앱만 그렇다 — 워드·엑셀은 숨겨지지만 **파워포인트는 숨기기를 거부한다** |
| 파워포인트를 태운 뒤 권한 경고창이 반복된다 | 띄운 파워포인트가 안 끝난 것이다 — COM `Quit` 뒤에도 DRM 훅이 프로세스를 붙잡는다. 스크립트는 **제가 띄운 프로세스(PID)만** 끝내고 그 덱의 복구 항목과 잠금 파일(`~$…`)을 걷는다. 손으로 짰으면 같은 일을 한다 |
| 파일 한 건인데 스크립트를 쓸까 | 한 건이면 인라인 COM 호출로 족하다 — **스크립트는 규모가 정당화한다** |
| 여러 번 참조할 문서다 | **필요한 것을 추려 읽는 자리에 박는다** — 파일째 저장소에 두면 DRM 이 다시 감싸 다음 사람도 같은 벽을 만난다 |
