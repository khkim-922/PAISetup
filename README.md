# Claude Code 사내 설치본

윈도우 PC 한 대에 Claude Code 개발 환경을 한 번에 세운다. 사내에서는 회사 게이트웨이에 붙이고,
사외에서는 개인 구독으로 세운다.

**포스코 사람용이다.** 회사 키 · 프록시 · 회사 설정은 게이트웨이가 닿는 사내에서만 뜻이 있어
사내에서만 세우고, 사외에서는 구독이나 개인 계정 로그인으로 쓴다. 프로그램(고른 도구의 CLI · 확장 ·
데스크탑 앱)은 어디서나 깔린다. 사내 PC · 사외 VDI · 사내 VDI · 집 — **네 자리 어디서든 같은 파일을
누르면 된다.** 사내인지 사외인지는 설치가 회사 게이트웨이 주소에 닿는지를 재서 스스로 가른다. 고를 것이 없다.

## 왜 있나

맨바닥 PC 에서 Claude Code 를 쓰려면 프로그램 몇 개를 깔고, VS Code 확장을 붙이고, 게이트웨이
주소와 키를 사용자 환경변수에 심어야 한다. 순서를 하나만 어겨도 아무 말 없이 어긋난다 — 확장은
깔렸는데 실행할 CLI 가 없거나, 키는 심었는데 창을 안 닫아 새 값이 안 먹거나, 파이썬은 깔렸는데
윈도우가 미리 깔아 둔 껍데기가 대신 잡히거나. 이런 자리를 다 겪고 나서 순서와 확인을 한 파일에 담았다.

## 무엇이 깔리나

무엇을 할 수 있게 되나를 한눈에 보려면 설치 창의 「제공기능」 링크(`features.html`)를 연다 — 판의 앞 두 자리가 새로 오른 판(예: 2.0 → 2.1)을 처음 깐 PC 에서는 설치가 끝날 때 그 페이지를 한 번 연다(설치 창 · 로그온 자동 실행 어느 쪽이든). 이 판에서 바뀐 것은 그 곁의 「바뀐 것」 링크가 그 판의 릴리스 노트를 연다 — 주소는 값 파일의 `#update-repo` 와 `VERSION` 에서 지어 진다. 아래 표는 어디에 무엇이
어떤 조건으로 깔리나를 적는다.

| | |
|---|---|
| **고른 도구** — Claude · Codex · 구글 Antigravity · GitHub Copilot | 설치 창에서 **켠 것만** 깔린다. 한 칸이 그 도구의 **CLI · VS Code 확장 · 데스크탑 앱**을 한꺼번에 든다 — 도구마다 드는 것이 다르다(Copilot 은 확장 없이 데스크탑 앱과 CLI 를 든다). **Copilot 은 꺼진 채로 뜬다** — 아직 시범 운영이라 쓸 사람만 켠다. 끈 것은 어디에도 안 깔린다. 구글 쪽은 안티그래비티 하나다 — Gemini CLI 는 안 깐다 |
| **VS Code 와 확장** | 칸이 따로 있다. **사내는 필수라 켠 채로 잠겨 있다. 사외는 꺼진 채로 뜬다** — 데스크탑 앱만으로도 쓸 수 있어서다. 끄면 VS Code 자체도 안 깐다. ⚠ 확장은 CLI 를 자식 프로세스로 부른다 — 둘 중 하나만 있으면 안 돈다. 깔린 VS Code 에는 **설정 저장소들의 작업 영역 신뢰를 미리 적어** 처음 열 때 「작성자를 믿느냐」를 안 묻고 확장이 바로 선다 — 그 밖의 폴더는 그대로 묻는다 |
| Node.js | Claude · Codex · Copilot 의 CLI 가 이것으로 돈다 — 무엇을 골랐든 늘 깔린다. 안티그래비티 CLI(`agy`)만은 Node 가 아니라 winget 이 깐다. npm 으로 전역에 깐 CLI 가 서는 폴더(`%APPDATA%\npm`)가 있으면 그 자리를 **사용자 PATH 끝에 더한다** — 이미 있으면 안 건드리고 다른 자리는 그대로 둔다. 그래서 설치가 끝난 뒤 새로 여는 터미널에서도 `claude` · `codex` · `copilot` 과 사람이 npm 으로 깐 CLI 가 이름만으로 선다 (아래 「무를 때」) |
| 어디에 붙나 — 사내 · 사외 | **사내**에서는 켠 도구가 같은 회사 키로 게이트웨이에 붙는다 — 아래 로컬 프록시를 거쳐 붙는다. **사외**에서는 각자 로그인한다 — Codex 는 `codex login`(ChatGPT 계정), 안티그래비티는 처음 실행할 때 Google 로그인. 설치가 잰 자리는 사용자 환경변수 `PAISETUP_SITE`(`inside` · `outside` — 모르면 `outside`)에 남는다 — 일을 맡기는 세션이 맡기기 모델 표(아래 「agy 묶음」)에서 이 자리 줄을 읽는다. ⚠ **안티그래비티 확장은 제 화면을 가진 에이전트다** — 사이드바에서 바로 쓴다. 이 확장은 처음 열 때 제 본체(`agy` · 188MB)를 따로 받는다 — 설치가 깐 안티그래비티 CLI 와 같은 것을 한 번 더 받는 셈이다 |
| **로컬 프록시** | **사내에서만.** `127.0.0.1:18901` 에서 돌며 Claude Code(Opus 5) · Codex · 안티그래비티의 요청을 게이트웨이로 넘긴다. Claude Code 의 웹 검색은 게이트웨이의 제미나이 검색으로, Codex 의 웹 검색은 게이트웨이의 Responses 검색으로 여기서 메운다 — 두 도구가 묻는 꼴을 게이트웨이가 그대로는 안 받는다. 로그인할 때마다 감시 작업(`PGPTProxy-Watchdog`)이 알아서 띄우고 지킨다. 왜 있나는 `posco/pgpt-proxy/README.md` 가 든다 |
| Git · Python · GitHub CLI | 코드를 짤 사람용이다. 설치 창에는 이 칸이 없어 늘 깔린다 — 빼려면 `Setup.exe -NoDevTools` 로 부른다. **다만 Python 으로 도는 것이 서는 자리면 Python 만은 깐다** — 사내 프록시와, 아래 「칸 없이 깔리는 스킬」의 맡기기 래퍼들과, Claude 를 고르면 심기는 DRM 길잡이 훅과, Codex 를 고르면 심기는 Codex 훅과, 제작자 칸을 하나라도 켜거나 Claude 를 고르면 규범 · 룰 · 스킬 · Claude 훅 등록을 놓는 프로그램(`tool-homes.py` — 아래 「규범 · 룰 · 스킬」)이다. 설치 창이 까닭을 그 줄에 적는다. 「내 저장소 받기」에 주소를 넣었고 GitHub CLI 로그인이 안 돼 있으면, **저장소를 받기 직전에** 설치가 브라우저 로그인을 띄운다 — 일회용 코드와 남은 시간(180초)이 팝업에 뜬다. pip 가 사용자 자리(`%APPDATA%\Python\Python<판>\Scripts`)에 깐 명령(`markitdown` 등)이 있으면 설치가 끝날 무렵 그 폴더를 **사용자 PATH 끝에 더한다** — npm 전역 자리와 같은 규칙이다(위 Node.js 줄 · 아래 「무를 때」) |
| **VC++ 런타임** — Python 이 깔리는 판 | Microsoft 의 공식 「Visual C++ 재배포 가능 패키지(x64)」를 **14.40 이상으로 맞춘다** — 판은 `C:\Windows\System32\msvcp140.dll` 파일에서 읽고, 그보다 옛 판이면 winget 으로 올린다(없으면 깐다). PPT 검수 패키지(`markitdown`)가 기대는 부품이 옛 런타임에서는 여는 순간 파이썬째 죽는다. ⚠ **PC 전체에 까는 것이라 관리자 승인 창(UAC)이 한 번 뜰 수 있다** — 승인 없이 올리는 PC(관리자 계정에 회사 정책이 묻지 않게 둔 PC)는 창 없이 지나간다. 승인 창이 뜨는 PC 에서 **로그온 자동 실행**은 누를 사람이 없으니 창을 안 띄우고 노란 줄로 미룬다 — 설치 창으로 다시 누르면 그때 한 번 뜬다. 승인을 못 받거나 관리자 권한이 없는 PC 면 그 까닭을 한 줄로 알리고 나머지는 그대로 깔린다 — 그 PC 에서는 PPT 검수만 안 서니 IT 에 그 패키지를 요청한다 |
| **lychee · markdownlint-cli2** — 제작자 칸을 켜면 | 제작자 칸이 보내는 문서 점검 스킬(`doc-coordinate-audit`)이 부르는 도구다 — 링크 · 경로는 lychee(winget 휴대용 · 사용자 범위라 승인이 안 든다), 마크다운 구조는 markdownlint-cli2(npm 전역). 칸을 끄면 안 깐다 |
| **브라우저 MCP** — Claude · Codex · 구글 Antigravity 가운데 하나라도 고르면 | 모델이 웹 페이지를 띄우고 읽고(자바스크립트로 그리는 화면까지) 누르고 입력하고 찍는 손이다 — 브라우저 도구가 없는 자리에서 쓴다. playwright 를 npm 전역에 깔고, 브라우저(크로미움)는 **처음 한 번** 구글 공식 스냅샷에서 받는다(수백 MB · 이미 있으면 안 받는다). 고른 도구마다 MCP 서버 `playwright` 로 달고, 안 고른 도구에서는 설치가 단 것만 걷는다. **창을 띄운 채 돈다** — 모델이 하는 일을 보며 로그인 · 확인 창처럼 사람 손이 드는 자리에서 거든다. 세션마다 새 프로필로 뜨므로 **로그인은 세션을 넘어 안 남는다.** 같은 이름(`playwright`)으로 손수 붙인 서버가 있으면 그것을 두고 우리 것은 안 단다(노란 줄) |
| **데스크탑 앱** | **앱마다 다르다.** 게이트웨이에 못 붙어 사내에서는 쓸모가 없는 것(Claude · Codex · Antigravity)은 **사외에서만** 깔리고, 제 계정으로 로그인해 쓰는 것(**GitHub Copilot**)은 **사내·사외 모두** 깔린다. 켠 도구의 것만 깔린다. **이미 깔렸는지는 시작 메뉴 → 윈도우 설치 목록 → winget 목록 차례로 잰다** — 깔린 앱 위에는 다시 깔지 않고(앱이 스스로 올린 판이 winget 목록의 판보다 앞서 있으면 그 판으로 내려간다), winget 이 더 새 판을 댈 때만 올린다. 셋 다 답을 못 내면 깔지도 올리지도 않고 끝 검증에 노란 `[?]` 로 남긴다. ⚠ Copilot 은 **WebView2 런타임**이 있어야 도는데 설치 목록에 그것이 딸려 오지 않는다 — 없는 기계(사내 VDI)면 **먼저 깔고**, 이미 있으면(사내 PC 에는 대개 있다) 건너뛴다. ⚠ **Gemini 데스크탑 앱은 안 깐다** — 회사 망이 설치 도중에 연결을 끊어 두 번 다 실패했다. 집에서는 깔리므로 필요하면 <https://gemini.google.com/app> 에서 손으로 받는다. ⚠ **Codex 는 ChatGPT 앱 안에 들어 있어 시작 메뉴에 「ChatGPT」로 뜬다.** Antigravity 는 VS Code 를 대신하는 **별개 편집기**다. ⚠ **로그인은 사람이 한다** — Copilot 은 회사 계정으로 직접 인증하고, 사외 개인 PC 에서는 회사 계정이 막혀(등록 안 된 기기) 개인 계정으로 쓴다. Codex · Antigravity 데스크탑에는 설정 저장소들을 **프로젝트로 미리 더해** 둔다 — 앱이 떠 있었으면 다음 설치가 더하고, 사람이 목록에서 뺀 것은 다시 안 넣는다. Copilot 데스크탑의 프로젝트는 안 더한다 |
| 게이트웨이 주소 · 모델 · **키** | 사용자 환경변수로 심는다. 키는 한 번만 넣으면 고른 도구가 읽는 이름에 같이 심긴다 — Claude 는 `ANTHROPIC_AUTH_TOKEN`, Codex 는 `OPENAI_API_KEY`, 안티그래비티는 `GEMINI_API_KEY`. **사외면 키를 안 묻고, 사내에서 쓰던 기계를 사외에서 다시 누르면 남아 있던 사내 값을 걷어 낸다** (아래 「무를 때」) |
| **워드의 PDF 변환 안내 끄기** | 워드가 깔린 PC 면 자리 · 고른 도구와 상관없이, 깔린 판마다 `HKCU\Software\Microsoft\Office\<판>\Word\Options` 의 `DisableConvertPdfWarning` 을 1 로 둔다. 스킬 `drm-office-read` 가 숨겨 띄운 워드는 이 안내창이 뜨면 아무도 못 눌러 멈춘다. ⚠ **사람이 PDF 를 워드로 열 때도 그 안내가 안 뜬다** — 설치 창에 칸은 없고 설치 기록 한 줄과 끝 검증 한 줄이 밝힌다. 워드가 없으면 안 건드린다 (아래 「무를 때」) |
| Claude Code 홈 설정 — `~/.claude/settings.json` | 파일이 없으면 만들고, 있으면 그대로 두고 필요한 줄만 맞춘다: 기능 스위치 · 사내면 `/model` 에 뜰 모델 목록 · 사내면 **웹페치 검증 건너뛰기**(`skipWebFetchPreflight` — 사내 망이 웹페치가 미리 묻는 Anthropic 차단 목록 조회를 끊어, 열리는 주소도 못 가져오던 것을 푼다. 사외는 그 검사가 서므로 안 켠다) · **자동 모드와 맡기기 러너 허락**(Claude 를 고르면 「permissions.defaultMode」를 `auto` 로 — 그 키가 이미 있으면 사람 값이라 안 덮는다. agy · Codex/Copilot 러너 스킬이 Claude 홈에 서면 그 러너를 부르는 `pythonw` 명령의 허락 한 줄씩을 `permissions.allow` 에 — 자동 모드 분류기가 뒤에서 러너를 띄우는 명령을 막기 때문이다. 심은 것은 설치기 폴더의 기록(`%LOCALAPPDATA%\Claude Code Setup\claude-settings.tsv`)에 적고, 조건이 빠지면 값이 그대로인 것만 걷는다. 지운 것은 다음 설치가 다시 심으니, 끄려면 다른 「defaultMode」 값이나 「permissions.deny」를 둔다) · `install.env` 의 공통값(키는 빼고 — 키는 환경변수에만 둔다) · **그림 문**(Claude 를 고르면 — 모델이 그림을 받기 직전에 크기를 재고, 너무 큰 것은 막는 훅) · **웹 다시 찾기**(Claude 를 고르면 — 웹 검색 · 웹 가져오기가 못 닿았을 때 `curl` · Tavily · agy 에게 맡기기 같은 다른 길이 있다는 것을 결과 곁에 붙이는 훅 — 막지는 않는다) · **DRM 길잡이**(Claude 를 고르면 — 붙이거나 경로를 적은 오피스 · PDF 가 회사 DRM 에 감겼으면 스킬 `drm-office-read` 로 읽는 길을 곁에 붙이는 훅. VS Code 앱에서 「+」로 붙인 PDF 는 경로 없이 본문만 오므로, 감긴 바이트 그대로를 임시 폴더의 `drm-attach` 밑에 한 벌 떨궈 그 자리를 댄다. 감기지 않은 파일에는 아무것도 안 붙이고, 막지 않는다) · **Bash 겹역슬래시 보정**(Claude 를 고르면 — 윈도우에서 Bash 로 보낸 명령의 역슬래시는 셸에 닿기 전에 짝마다 하나로 접히므로, 명령의 역슬래시를 두 배로 늘려 쓴 그대로 닿게 고쳐 넘기는 훅. 접힘을 잰 Claude Code 판에서만 고치고, 처음 보는 판이면 명령을 돌려보낸다) · **PowerShell UTF-8 BOM 보정**(Claude 를 고르면 — 편집한 `.ps1` 에 BOM 이 없으면 찍는 훅. 윈도우 파워셸 5.1 은 BOM 없는 파일의 한글을 깨뜨려 읽는다). 사외로 가면 사내 전용 줄은 걷어 낸다. 훅 여섯의 등록은 `tool-homes.py` 가 놓는다 — 명령은 `~/.paisetup/` 두 층 가운데 이긴 층의 `hooks/` 를 가리키고(설정 저장소가 훅을 들면 개인 층, 아니면 짐이 채운 표준 층), 사람이 넣은 훅은 같은 항목에 있어도 둔다. 고른 제품은 사용자 환경변수 `PAISETUP_PICK` 에 남는다(예: `claude,codex,agy,copilot` · 넷 다 아니면 `none`). **Claude 를 빼고 다시 누르면 우리 훅 등록만 걷는다** |
| Codex · 안티그래비티 설정 | 회사 연결 설정은 사내에서만 선다. `~/.codex/config.toml` 은 없으면 회사 틀(`posco/`)로 쓰고, 있으면 틀이 든 자리만 틀의 값으로 맞춘다 — 사람이 둔 키 · Codex 가 적는 훅 신뢰 · 폴더 신뢰는 그대로 두고, 바꾼 게 있으면 고치기 전 것을 `config.toml.before-pgpt-<시각>` 에 떠 둔다. `~/.gemini/antigravity-cli/settings.json` 에는 인증 방식 한 줄(`modelProvider`)을 둔다 — 같은 폴더의 `~/.gemini/settings.json` 은 Gemini CLI 의 것이라 안 건드린다. **Codex 훅은 자리와 관계없이 Codex를 고르면 선다** — DRM 길잡이 · 그림 문 · Windows Bash 겹역슬래시 차단 · PowerShell UTF-8 BOM 보정을 사람의 다른 Codex 설정을 두고 병합한다. 몸통은 설정 저장소 씨앗에서 오고, **설치가 우리 훅에 Codex 신뢰까지 적는다** — Codex 는 신뢰한 훅만 돌려, 신뢰가 없으면 대화형 시작은 묻고 `codex exec`(다른 도구가 Codex 에 일을 맡기는 길)는 말없이 건너뛴다. 신뢰는 Codex 제 설정 쓰기로 적고, 사람이 넣은 훅 · 사람이 끈 우리 훅은 안 건드린다. **Codex 를 빼고 다시 누르면 우리 훅만 걷는다** — 사람 훅과 뒤 항목의 자리 · 적어 둔 신뢰는 둔다. 걷는 손이 파이썬 3.11 이상으로 돌아, 없으면 노란 줄로 알리고 넘어간다. 키는 설정 파일에 안 들어가고 환경변수에만 있다. ⚠ **`GOOGLE_API_KEY` 가 이미 있으면 그 키가 회사 키보다 먼저 쓰인다** — 구글에 바로 붙는 키의 제 이름이라 설치는 지우지 않고 알리기만 한다. 회사 게이트웨이로 쓰려면 손으로 지운다 |
| **묻지 않고 돌기** — 고른 agy · Copilot · Codex | 설치 창에 칸이 없다 — 그 도구를 고르면, 그 도구가 사람에게 묻던 자리를 스스로 진행하게 하는 **제 설정 하나**를 심는다(Claude 는 위 「자동 모드」가 같은 몫이다). agy · Copilot 은 자리와 상관없이, Codex 는 **사외에서만** 심는다 — 사내 게이트웨이에서 Codex 의 검토자가 서는지 아직 못 쟀다. agy CLI 는 `~/.gemini/antigravity-cli/settings.json` 의 `toolPermission` 을 `always-proceed` 로, agy 데스크탑 앱은 `~/.gemini/config/config.json` 의 `userSettings` 에 Turbo 세 칸(`autoExecutionPolicy` · `enableTerminalSandbox` · `nonWorkspaceFileAccessPolicy`)을 둔다 — 앱의 값은 CLI 에 안 먹어 둘 다 심는다. Copilot CLI 는 `~/.copilot/settings.json`(`COPILOT_HOME` 이 서면 그 안)의 `defaultPermissionMode` 를 `allow-all` 로, 그 값이 `allow-all` 이면 `defaultMode` 를 `autopilot` 으로 둔다 — 새 대화형 세션이 첫 프롬프트에서 일을 끝까지 스스로 이어 그만큼 AI 크레딧을 쓴다. 승인을 `manual` 로 둔 사람에게는 Autopilot 을 안 심는다(새 세션마다 확인이 뜬다). 둘 다 대화형 시작에만 먹고, `-p` 로 일을 맡기는 길은 그대로다. Codex CLI 는 `~/.codex/config.toml` 맨 위에 `approvals_reviewer = "auto_review"`(「Approve for me」)를 둔다 — 샌드박스를 넘는 요청을 사람 대신 검토자가 가르고, 샌드박스 모드는 안 바꾼다. Codex 데스크탑 앱에는 그 키가 앱이 권한을 저장하기 전까지만 먹는다 — 앱은 첫 샌드박스 설정(앱의 배너를 누르고 관리자 승인)을 마칠 때 「승인 요청」을 한 번 적어 두므로, 설치기는 **Codex 를 닫아 둔 때**(이번 설치가 깐 Codex 를 닫은 뒤 · 손으로 다시 돌려 Codex 다시 띄우기에 동의한 뒤) 지금 값과 상관없이 「나 대신 승인」을 써 둔다 — 상태 파일의 그 칸 하나만 쓰고, 파일이 없으면 안 만든다. 기다리지 않으므로 샌드박스 설정 전에 쓴 값은 앱이 되돌리고, 그 뒤 설치기를 다시 돌려 다시 띄우기에 동의하면 남는다. 로그온 자동 실행은 Codex 가 떠 있어 못 쓴다. **사람이 둔 값은 안 덮는다** — 그 키가 이미 있으면(agy 앱은 세 칸 가운데 하나라도, Codex 는 `approval_policy` 도) 그 도구 줄을 통째로 둔다. 못 읽는 파일은 안 건드리고 빨간 줄로 알린다. agy · Copilot 의 이 설정은 **위험을 가르는 판단 없이 다 돌린다** — agy 에 걸린 우리 훅 가운데 DRM 길잡이는 그대로 막고(감긴 파일을 읽기 전에), Copilot 에는 우리 훅이 안 걸린다. **도구를 빼고 다시 눌러도 안 걷는다** — 사람이 같은 값을 둔 것과 글자로 안 갈려서다. 끄려면 그 도구의 설정에서 다른 값을 고른다(다음 설치가 그 값을 안 덮는다 — Codex 데스크탑의 모드만 예외다) |
| **사내 환경 문서** · **씨앗 넷** | `~/.claude/posco/` · `~/.claude/seeds/gateway/` · `~/.claude/seeds/check/` · `~/.claude/seeds/config-repo/` · `~/.claude/seeds/vibecoding/` 로 깔린다. 마지막 것은 회사가 쓴 사내 FastAPI 코딩 기준이다 — 들머리는 그 안의 `SEED.md` 고, 사내 앱을 짤 때는 스킬 `inhouse-app` 이 그 안의 장을 콕 집어 연다(Claude 또는 Codex 를 고르면 깔린다 — 아래 「칸 없이 깔리는 스킬」). 고를 것이 아니라 환경이라 스위치가 없다. **씨앗 넷은 거울로 깔려, 짐에서 빠진 파일은 홈에서도 빠진다** — 옛 판의 찌꺼기가 남아 원본인 척하지 않게. `posco/` 만은 덮어쓰기라 짐에서 빠진 파일이 홈에 남을 수 있다 — 프록시가 그 폴더에 제 기록 파일을 쓰고 있어 통째로 지우지 못한다. **설정 저장소를 넣은 PC 에서는 그 저장소의 `deploy.seeds.conf` 가 드는 폴더를 설치가 건드리지 않는다** — 그 자리는 저장소 배포가 최신판으로 밀고, 설치까지 깔면 둘이 판마다 번갈아 덮는다(홈에 그 폴더가 아직 없을 때만 설치가 먼저 깐다). **검사 씨앗의 그림 줄이기가 드는 파이썬 패키지(`pillow`)도 여기서 깐다** — 그림 문이 큰 그림을 「줄여서 연다」로 돌려보내면 그 부품이 돈다. 파이썬이 없으면 건너뛰고, 회사망이 막아 못 깔면 알리고 넘어간다(그때 줄이기는 원본 크기로 물러난다) |

## 폴더에 무엇이 들어 있나

**받는 것은 `Setup.exe` 하나다.** 두 번 누르면 끝이고, 아래 것들은 그 안에 들어 있다 —
설치가 제 자리(`%LOCALAPPDATA%\Claude Code Setup\<판>`)에 풀어 쓴다. **손으로 열 일은 없지만,
무엇이 오는지는 알고 받는 편이 낫다.**

```text
├─ install.cmd               설치 창을 띄우는 것. Setup.exe 가 이것과 같은 화면을 연다
├─ install.ui.ps1            설치 창 — 값을 받고 진행을 보여준다
├─ install.ps1               설치 몸통 — 무엇을 어떻게 깔지는 이 한 자리가 든다
├─ update-check.ps1          새 판이 있나 묻고 받은 것을 지문으로 대조한다 — 설치 창과
│                            로그온 자동 실행이 같은 이 자를 부른다
├─ open-page.ps1             아래 안내 페이지를 기본 브라우저로 연다 — 설치 창과 설치 몸통이 같이 쓴다
├─ install.env               회사 공통값(주소·모델)이 채워져 온다. 키 칸은 비어 있다
├─ install-flow.svg       ← 설치 흐름 그림(아래 「Install」). 설치 창의 「설치흐름」 링크가 연다
├─ setup-icon.ico            설치 창 제목줄의 아이콘. 바탕화면 아이콘은 Setup.exe 에 박힌 같은 그림이다
├─ config-repo-howto.html    설정 저장소를 만드는 법 한 장 — 설치 창의 「설정저장소 만드는 법」 링크가 연다
├─ features.html             설치하면 생기는 기능 한 장 — 설치 창의 「제공기능」 링크가 연다
├─ posco/                    사내 게이트웨이 환경 문서 한 층 — 되고 안 되는 것의 원본
│                            (회사 루트 CA `corp-ca.pem` 도 여기 있다 — 설치가 쓴다)
├─ seeds/
│  ├─ gateway/               게이트웨이 배관 씨앗 — 새 프로젝트가 복사해서 출발한다
│  ├─ check/                 검사 씨앗 — 새 저장소의 `_check/` 가 복사해서 출발한다
│  └─ config-repo/           설정 저장소 씨앗 — 직접 복사해 쓸 사람은 설정 저장소를 만들 사람뿐이다.
│                            세션 훅·배포·커밋 게이트가 **한 벌로 돌게** 들어 있고, 설정 저장소가 없는
│                            PC 에서는 저장소들의 세션 훅·커밋 게이트가 여기 든 것을 불러 쓴다
│
├─ kit/                      도구 홈 짐 — 고른 도구의 홈(Claude · Codex · agy)에 나눠 깔리는 것
│  ├─ norms/                 제작자의 규범(norms.md)과 영역 룰(rules/) — 제작자 칸을 켠 도구에만 간다
│  ├─ skills/                스킬 전부 — 제작자 칸을 켠 도구에는 다, 끈 도구에는 고른 제품이 부르는 몇 개만 간다
│  ├─ tool-homes.conf        갈 곳 표 — 규범 · 룰 · 스킬이 어느 도구 홈에 어떤 꼴로 가나
│  └─ tool-homes.py          그 표대로 놓는 프로그램(파이썬) — 설치가 부른다
│
├─ .claude/                  이 저장소가 제 일에만 쓰는 것(커밋 게이트의 훅 · 도구 선언 · 린터 설정) — 홈으로는 안 간다. 안 봐도 된다
├─ docs/                     설치기를 고치며 받은 바깥 리뷰 기록(reviews/) — 설치에는 안 쓰인다. 안 봐도 된다
│
├─ README.md                 이 글
├─ VERSION                   이 설치본이 몇 판인지. 릴리스 태그는 이 값 앞에 v 를 붙인 것이다
├─ LICENSE                   MIT
├─ .gitattributes            줄끝을 못박는다 — 저장소 사정이라 안 봐도 된다
├─ .gitignore                무엇을 저장소에 안 담나 — 저장소 사정이라 안 봐도 된다
├─ .markdownlint-cli2.jsonc  만든 사람의 글 검사 설정 — 안 봐도 된다
├─ lychee.toml               만든 사람의 링크 검사 설정 — 안 봐도 된다
├─ .github/                  태그를 밀면 설치본을 굽는 CI 한 벌 — 안 봐도 된다
└─ .githooks/                만든 사람이 커밋할 때 재는 문지기 한 벌 — 안 봐도 된다
```

`posco/` 와 `seeds/` 는 **고를 것이 아니라 환경**이라 스위치가 없다 — 누가 받아도 홈에 깔린다.

**도구 홈으로 가는 짐은 `kit/` 한 곳에 산다.** Claude Code · Codex 가 스스로 읽는 자리 이름(`.claude/skills` ·
`.agents/skills`)에 두지 않는 것이 요점이다 — 이 폴더를 그 도구로 열면 그 자리가 그 세션의 스킬로 실린다.
`.claude/` 에는 만든 사람이 이 저장소에 커밋할 때 쓰는 것만 있어 **어느 칸을 켜도 안 깔린다.**

⚠ **이 폴더를 사람이 만들 일은 없다.** `Setup.exe` 가 제 안에서 꺼내 제 자리에 편다. 같은 판을
다시 누르면, 같은 짐이 끝까지 펴져 있을 때는 건너뛰고 펴다 끊긴 자리면 그 판 폴더를 지우고
처음부터 다시 편다.

## Security

**키는 짐에 안 담겨 온다.** 설치가 물어보고, 화면에 안 찍히게 받아 사용자 환경변수로
심는다. **키는 사람마다 제 것이다** — 남의 것을 받아 쓰지 않는다. 받은 그대로의 짐에는
키 칸이 비어 있다.

같은 기계에서 다시 누르면 이미 심긴 키를 설치 창이 채워 둔다. 여러 대를 세우느라 매번 넣는 것이
번거로우면 펴진 짐의 `install.env`(`%LOCALAPPDATA%\Claude Code Setup\<판>\`)에 제 키를 적어 둘 수 있다. **그렇게 적었으면 그
파일을 남에게 넘기지 않는다.** ⚠ **그 파일의 `#이름 = 값` 줄은 주석이 아니라 설치가 읽는 지시다** — `#` 를 지우면 그 줄이
죽는다. 파일 머리말을 먼저 읽고 고친다.

## Install

먼저 한 장으로. **가로 띠 넷이 「누가 하나」다** — 손을 대는 것은 `사람` 띠의 네 칸뿐이고 나머지는
저절로 돈다. `내 저장소` 띠는 **아래 「내 저장소 받기」 칸을 채운 사람만** 도는 갈래다.
칸 안에 ⚠ 로 시작하는 작은 글씨가 실제로 사람들이 걸린 자리다.

![설치 흐름 — 담당 띠 넷으로 가른 설치 순서, 갈래 셋](install-flow.svg)

글자가 잘려 보이면 그 자리에 마우스를 올린다 — 전문이 뜬다. 이 글을 브라우저로 보고 있지
않다면 설치 창의 「설치흐름」 링크로 같은 그림을 연다.

1. 릴리스에서 **`Setup.exe`** 를 받는다 — 받을 것은 그 파일 하나다
2. **두 번 누른다** — 설치 창이 뜬다
3. **API 키**를 넣는다. 주소는 채워져 있다 (사외면 이 칸이 없다 — 「사외입니다」 한 줄만 뜬다)
4. **[설치 시작]** 을 누른다 — 막대가 차는 동안 기다린다. 설치 창 뒤에 **설치 기록을 통째로 흘려 주는 콘솔 창**이 같이 뜬다 — 무엇이 도는지, 어느 걸음에서 멈췄는지가 거기 보인다. 설치 창을 닫으면 그 창도 같이 닫힌다(손으로 닫을 것 없다)
5. **사외이고 Claude 로그인이 안 돼 있으면 브라우저가 뜨고, 최대 180초 기다린다** — 이미 로그인돼 있으면(`claude auth status` 로 잰다) 건너뛴다. `claude.ai` 에 아예 못 닿는 망이면 브라우저를 안 띄우고 지나간다 — 닿는 자리에서 새 터미널에 `claude auth login`. 「내 저장소 받기」 칸을 비워도 똑같이 돈다
6. **저장소 주소를 넣었으면 마지막 칸 직전에 GitHub CLI 로그인 코드 팝업이 뜬다** — [브라우저 열기]를 누르고 그 코드를 넣는다. 남은 시간이 창에 보이고, 로그인이 되면 스스로 닫힌다. 안 눌러도 설치는 이어서 간다
7. **검증이 끝나고 3초 뒤에 깐 것을 다 띄운다** — 이 판에서 선 데스크탑 앱들과 VS Code(VS Code 칸을 껐으면 뺀다). 띄운 뒤 **정말 떴는지 재고**, 안 뜬 것은 한 번 더 띄우고, 그래도 안 되면 「안 떴다. 시작 메뉴에서 직접 연다」 줄을 남긴다

⚠ **GitHub 로그인 팝업은 저장소를 받기 직전에 뜬다.** 앞쪽에 두면 프로그램을 깔기도 전에 사람을
붙들어 두는데, 그 로그인이 실제로 필요한 자리(비공개 저장소 clone)까지는 한참 남는다.

설치가 끝나면 **바탕화면과 시작 메뉴에 「PAI Setup Wizard」 꽃 아이콘**이 생긴다.
**다음부터는 그것을 누르면 된다** — 누르면 설치 창이 뜨면서 **새 판이 나왔는지 같이 봐 준다.**
새 판이 있으면 받을지 묻고, 「예」면 받아서 릴리스에 같이 오른 SHA-256 지문과 대조한다. 지문을 못 쟀거나
다르면 띄우지 않고 까닭을 댄다. (설치 창이 직접 받는 것이라 아래 「윈도우가 한 번 막는다」의 파란 경고는 안 뜬다.)

사내·사외를 가리지 않고 **선 것은 다 띄운다** — 어느 창으로 쓸지는 사람이 고른다. 사내에서는
게이트웨이 주소로 말이 통하는 것이 확장과 CLI 뿐이라 대개 VS Code 하나가 뜨고, 사외에서는 데스크탑 앱과
VS Code 가 같이 뜬다. VS Code 를 먼저 띄워 데스크탑 앱이 그 위에 오게 하지만 **보장은 못 한다** — 앱마다
뜨는 속도가 다르다.
**3초는 검증 칸의 `[O]/[X]/[?]`(아래 「Usage」)를 읽을 틈이다** — 새 창이 설치 창을 덮으므로 바로 띄우면
그 판정을 아무도 못 보고 지나간다.

⚠ **이미 돌고 있으면 먼저 묻는다.** 「껐다 새로 열까요?」 창이 뜬다 — **[예]** 면 끄고 새로
띄우고, **[아니오]** 면 안 띄우고 손으로 하라고 알린다. VS Code 든 데스크탑 앱이든 같다. 돌고 있는 것을
모아 **한 번에** 묻는다 — 앱마다 창이 연달아 뜨지 않는다.
「떠 있나」를 재고 끄는 것은 **그 앱이 깔린 폴더에서 도는 프로세스뿐이다.** 그래서 [예] 를 눌러도
VS Code 확장이나 터미널에서 도는 Claude Code 는 안 꺼진다 — 프로세스 이름은 데스크탑 앱과 같은
claude.exe 지만 사는 폴더가 다르다.

왜 굳이 새로 여나 — **돌던 것은 뒤에 바뀐 것을 모르기 때문이다.** 까닭은 둘이다. 창은 뜰 때
환경변수를 한 번 복사해 가고, 그 뒤에 바뀐 것은 안 따라온다. 그리고 저장소 주소를 넣었으면
**이 설치가 끝이 아니다** — 뒤이어 그 저장소의 세션 훅이 배포를 부르고, 거기서 규범 · 스킬이 놓이고
세션 훅이 심긴다. 돌던 앱은 그 설정을 뜰 때 한 번 읽고 말았다.

⚠ **[예] 를 누르기 전에 저장한다.** 먼저 창을 닫으라고 보내지만, 그래도 안 꺼지면 강제로
끝낸다. **Claude 데스크탑 앱은 창만 닫으면 안 꺼지고 트레이(시계 옆)로 내려간다** — 강제로
끝내는 길을 둔 까닭이 그것이다.

### 윈도우가 한 번 막는다 — 거기서 멈추지 않는다

인터넷에서 받은 파일이라 **처음 누를 때 파란 경고창이 뜬다.**

> **Windows의 PC 보호** — 「추가 정보」를 누르면 아래에 **「실행」** 단추가 나온다.

서명을 사지 않은 파일이라 뜨는 창이다. 경고창을 닫아 버리면 아무 일도 안 일어난 것처럼
보이므로 — **「실행」을 눌러야 시작된다.**

릴리스 본문에 두 가지가 더 적혀 있다: 이 경고창을 거치지 않고 받는 길(PowerShell 에 붙여 넣는
몇 줄 — 지문을 맞춰 보고 같을 때만 띄운다)과, Edge 브라우저가 내려받기부터 막을 때 푸는 법이다.

### 설치 창의 칸 — 그대로 두면 된다

| 칸 | 기본 | 무엇 |
|---|---|---|
| 설치할 것 — Claude · Codex · 구글 Antigravity · GitHub Copilot | Claude · Codex · Antigravity **켜짐**, Copilot **꺼짐** | 위 「무엇이 깔리나」 첫 줄 |
| VS Code 와 켠 것의 확장도 깝니다 | 사내 **켜짐**(못 끈다) · 사외 **꺼짐** | VS Code 와 켠 도구의 확장 — 끄면 둘 다 안 깔린다 |
| 제작자의 규범 · 룰 · 스킬도 깝니다: Claude · Codex · agy | **다 꺼짐** | 만든 사람의 작업 규율이 같이 들어 있다. **도구마다 고른다** — Claude 만 받고 Codex · agy 는 규범 없이 가볍게 쓸 수 있다. 제품 칸에서 고른 도구의 칸만 켜진다. 아래 저장소 칸에 설정 저장소 주소를 넣으면 고른 도구에 그 저장소의 것이 간다(그 저장소가 갈 곳 표를 들 때만 — 없는 것은 만든 사람의 것이 간다) — 칸 앞 글자가 「내 저장소의 규범 · 룰 · 스킬을 받을 도구」로 바뀐다(아래 「규범 · 룰 · 스킬」 절). 켜면 `-NoDevTools` 여도 Python 을 깐다. 안 켜도 설치는 완전하다 |
| 이미 깔린 것도 최신으로 올립니다 | **켜짐** | 옛 판이 깔려 있으면 올린다 |
| 로그온할 때 설치 창을 띄워 깔린 것을 최신으로 올리고 환경을 맞춥니다 | **꺼짐** (이미 켜 둔 기계면 켜진 채로 뜬다) | 아래 절 |

로그온 자동 실행을 켠 기계에서 창을 다시 열면 위 칸 가운데 제품 · VS Code · 제작자 칸은 **지난번에 고른 대로** 뜬다 —
자동 실행이 읽는 선택이 그것이라, 그대로 누르면 아무것도 안 바뀐다.

개발 도구(Git · Python · GitHub CLI)는 창에 칸이 없다 — 늘 깔린다. 빼려면 아래 「내 저장소 받기」 절
끝의 `-NoDevTools` 깃발을 쓴다.

### 로그온할 때 · 밤마다 혼자 도는 것 — 켜면 무엇이 생기나

켜면 작업 스케줄러에 작업 둘이 선다. **`PAISetup-AutoRun`** 은 로그인하고 1분 뒤,
**`PAISetup-AutoRun-Night`** 는 매일 새벽 3시 무렵(PC 마다 최대 2시간 흩뜨린다) 설치 몸통을 다시 돌려
**깔린 것을 최신으로 올리고 환경변수·설정을 다시 맞춘다.** 둘 다 창 없이 시작한다 — 로그온 회차는
설치를 실제로 할 때만 기록 창을 작업 표시줄에 내려 둔 채 띄우고(하던 일의 초점을 안 뺏는다), 끝나면
3초 뒤 스스로 닫는다. 밤 회차는 끝까지 창이 없다. 밤 작업은 그 시각에 꺼져 있거나 절전이면 켜진 뒤
따라 돌고, PC 를 깨우지는 않는다. 한 번 깔고 몇 달을 그냥 쓰는 기계, 다시 부팅하지 않고 절전으로 며칠을
잇는 기계가 아무도 모르게 뒤처지는 것을 막는 칸이다. 창 없이 띄우는 콘솔을 모르는 옛 윈도에서는 로그온
회차가 예전처럼 보이는 콘솔 창으로 돈다.

- **하루에 한 번만 끝까지 간다.** 그날 이미 성공했으면 다음 회차는 창 없이 건너뛴다 — 사내 · 사외
  자리가 지난 설치와 달라졌을 때만 로그온 회차가 다시 돈다.
- **밤 회차는 자리를 안 바꾸고 아무것도 안 띄운다.** 지금 자리가 지난 설치와 같다고 확인될 때만 돌고,
  아니면 아무것도 안 바꾸고 건너뛴다. 로그인 창 · 알림 창 · 「제공기능」 페이지도 안 띄운다 — 그 일은
  다음 로그온 회차나 설치 창이 한다.
- **설치본 자체도 새 판으로 간다.** 새 릴리스가 나와 있으면 `Setup.exe` 와 지문 파일을 받아 대조하고,
  맞으면 창 없이 풀어 그 새 판으로 설치를 잇는다. 지문이 없거나 다르면 새 판을 안 깔고 지금 판으로 간다 —
  까닭은 기록 파일에 남는다.
- **사내인지 사외인지는 그때그때 다시 잰다.** 설치하던 날의 판정을 굳혀 두지 않는다 — 굳혀 두면
  사내에서 깔고 집에 간 노트북이 그곳에서는 안 도는 프록시 주소를 매번 심는다.
- **고른 도구를 그대로 쓴다.** 껐던 도구는 되살아나지 않는다.
- **키는 파일에 안 남긴다.** 이미 사용자 환경변수에 심긴 것을 읽어 쓴다.
- 도는 기록은 `%LOCALAPPDATA%\Claude Code Setup\logs\autorun-<날짜-시각>-<번호>.log` 에 남는다 (최근 15 개).
  옛 판 폴더는 최근 셋만 남기고 거둔다.
- **설치가 겹치지 않게 막는다.** 다른 설치나 자동 실행이 이미 돌고 있으면 자동 실행은 물러나고,
  10분 안에 한 번 끝났으면 건너뛴다. 앞의 것이 멎어 있으면 거두고 제 일을 잇는데, 그 설치의 출력이
  세 시간 넘게 멈췄고 그 프로세스와 자식들이 CPU 도 안 쓸 때만 멎었다고 본다. 콘솔 창에서 직접 돌린
  설치는 가를 출력이 없어 안 거둔다 — 그 창을 닫으면 풀린다. 사람이 누른 설치는 앞의 것이 끝나기를 최대 60초 기다리고,
  그래도 안 끝나면 그 프로세스 번호와 경과 시간을 대며 끝내고 새로 시작할지 묻는다.
  부팅 때 다른 자동화가 `autorun.ps1` 을 불러도 같은 막음을 지난다.
- 끄려면 이 칸을 **끄고 한 번 더 설치한다** — 그때 작업과 딸린 파일을 같이 걷는다.

### 칸 없이 깔리는 스킬 — 사내에서 쓰는 도구

아래 스킬은 「제작자의 … 규범 · 룰 · 스킬도 깝니다」 칸과 **상관없이** 깔린다. 만든 사람의 일하는 방식이 아니라 회사에서
일할 때 쓰는 도구라서다 — 모두 그 규범 없이도 혼자 돈다(claude-config 결정 0091). **Codex 나 안티그래비티를 고르면 Claude 를
고른 자리와 같은 기본기를 받는다**(결정 0097 · 0099). 스킬 홈은 도구마다 따로다 — 그 도구가 읽는 자리에 깔린다.

맡기기 스킬만 홈이 갈린다 — 일을 **맡기는 쪽** 홈에 깔리고 **받는 쪽** 홈에는 안 간다(받는 쪽 홈에 서면 그 도구가 제게
맡기는 길을 든다). 그래서 셋을 다 고르면 도구마다 나머지 둘에게 맡기는 스킬을 받는다.

| 스킬 | 무엇을 하나 | Claude 홈(`~/.claude/skills/`) | Codex 홈(`~/.agents/skills/`) | agy 홈(`~/.gemini/config/skills/`) |
|---|---|---|---|---|
| `drm-office-read` | 회사 DRM 이 감싼 오피스 · PDF 에서 글자를 뽑는다. 페이지 · 슬라이드를 그림으로 떠서 표 · 배치를 본다 | Claude 를 고르면 | Codex 를 고르면 | 안티그래비티를 고르면 |

Codex 에게 맡기는 줄과 Codex 가 맡기는 줄은 사내에서는 Codex 회사 설정이 서는 자리에서만 선다.

**위 표의 조건은 제작자 칸을 끈 도구의 홈에서 쓰인다.** 칸을 켠 도구의 홈에는 `tool-homes.py` 가 짐의(설정 저장소를
넣었으면 그 저장소의) 스킬을 다 놓는다 — 위 이름들도 고른 제품과 상관없이 그 안에 들고, 받는 쪽 홈의 맡기기 스킬만 빠진다
(아래 「규범 · 룰 · 스킬」). 한 홈의 스킬 폴더를 쓰는 자가 늘 하나라, 둘이 같은 폴더를 번갈아 덮지 않는다.

칸을 끈 홈에 설치가 깐 이름은 홈마다 기록(`~/.claude/.paisetup-skills` · `~/.agents/.paisetup-skills` ·
`~/.gemini/.paisetup-skills`)에 남는다. 설치는 누를 때마다 그 기록 가운데 **이번에 깔 목록에 없는 것**(짐에서 빠졌다 · 그
제품을 더는 안 골랐다 · 옛 판이 짐에서 깐 제작자 스킬)을 그 홈의 `backups/install-skills-<시각>/` 로 옮긴다(`~/.claude` ·
`~/.agents` · `~/.gemini` 아래). 그 홈에는 사람이 둔 스킬도 같이 살아서, 깔 이름과 같은 폴더가 기록에 없으면 덮지 않고 통째로
그 홈의 `backups/install-aside-<시각>/` 로 옮긴 뒤 깔고 노란 줄로 알린다.

#### 안티그래비티를 고르면 — 일하는 도구 스킬 · 훅 둘

제품 칸에서 **구글 Antigravity 를 고르면** 칸 없이 아래가 선다 — Claude · Codex 를 안 골라도, 사내든 사외든 같다(결정 0099).
사내 agy CLI 를 회사 키로 쓸 때도 같은 홈 설정을 읽는다.

| 무엇 | 어디에 |
|---|---|
| 스킬 — 위 「칸 없이 깔리는 스킬」의 agy 홈 줄(`drm-office-read` · `inhouse-app` · `agent-envelope`, 같이 고른 도구에게 맡기는 `codex-copilot-background` · `claude-background`) | `~/.gemini/config/skills/` — agy 가 목록 없이 싣는 기본 스킬 자리이고, 설정 폴더 가운데 agy 가 스킬 본문을 열 수 있는 자리가 여기뿐이다. 사람이 둔 스킬과 같이 산다(위 「칸 없이 깔리는 스킬」의 기록 · 비켜 두기). 옛 판이 깐 자리 `~/.gemini/config/paisetup-skills/` 와 그 자리를 여는 목록 `~/.gemini/config/skills.json` 은 `tool-homes.py` 가 걷는다 — 옛 기록에 든 이름의 폴더만 `~/.paisetup/backups/<시각>/` 으로 옮기고(다 옮겨 비면 그 자리도), 목록은 우리가 깐 꼴일 때만 옮긴다. 옛 자리에 기록에 없는 것은 두고, 목록에 사람 항목이 섞였으면 노란 줄로 알리고 둔다. 제작자 칸의 agy 칸을 켜면 새 자리에 짐의 스킬이 다 간다(아래 「규범 · 룰 · 스킬」) |
| 훅 셋 — **DRM 길잡이**: agy 가 Fasoo DRM 에 감긴 파일을 열거나 그 경로를 적은 셸 명령으로 읽으려 하면 막고, 까닭에 스킬 `drm-office-read` 로 가는 길을 싣는다. **PowerShell UTF-8 BOM 보정**: agy 가 `.ps1` · `.psm1` · `.psd1` 을 쓰면 BOM 을 붙인다. **컨텍스트 알림**: 사내 자리(창 1M)에서 대화가 창의 33 % · 66 % 를 처음 넘으면 모델에게 한 줄을 붙인다 — 사외 무료 자리(창 200k)는 침묵한다 | `~/.gemini/config/hooks.json` 의 `paisetup-drm-guide` · `paisetup-utf8-bom` · `paisetup-context-alert` 항목. 사람이 넣은 다른 항목은 두고, 고치기 전 파일은 곁에 `hooks.json.before-paisetup-<시각>` 으로 떠 둔다. 우리 항목을 `"enabled": false` 로 꺼 두면 다음 설치도 꺼진 채 둔다. **안티그래비티를 빼고 다시 누르면 이 세 항목만 걷는다**(꺼 둔 것도) |
| Python — 훅 셋이 돈다 | 개발도구 칸을 꺼도 깐다 |

Claude 홈에 서는 나머지 셋(그림 문 · Bash 겹역슬래시 보정 · 웹 다시 찾기)은 agy 에 안 간다 — agy 는 그림 크기로 비용이
갈리지 않고 역슬래시를 접지 않아(결정 0083 실측), 막을 사고가 없다. agy 훅에는 사람의 글을 받는 자리가 없어 DRM 길잡이는
**도구가 그 파일을 읽으려는 순간**(파일 열기 · 그 경로를 적은 셸 명령)에만 걸린다 — 경로를 안 적은 셸 읽기(와일드카드 ·
변수로 이은 경로)는 못 본다(결정 0110).

#### agy 묶음 — Claude 또는 Codex 와 안티그래비티를 같이 고르면

제품 칸에서 **Claude 와 구글 Antigravity 를 둘 다** 고르면 사내든 사외든 agy 에게 일을 맡기는 데 드는 셋 — 모델 값 ·
스킬 `agy-background` · 그 스킬이 도는 Python — 이 선다. agy 가 Claude Code 와 같은 규범 아래서 일하게 하는 설정 둘은
맡기는 쪽과 상관없이 「제작자의 … 규범 · 룰 · 스킬도 깝니다」 칸에서 agy 를 고르면 선다 — 그 칸이 agy 에 규범을 놓는
스위치다(claude-config 결정 0089 · 0091 · 0099 · 0112).
맡기는 길은 스킬 `agy-background` 하나다 — agy 를 뒤에서 띄워 대화를 안 막고, 끝나면 Claude 가 결과를 거둔다.

| 무엇 | 어디에 |
|---|---|
| agy 모델 — **값이 자리마다 다르고, 맡기기 모델 표에서 온다.** 자리 · 일의 무게마다 어느 모델을 대고 한도나 과부하에서 어디로 넘어가나는 스킬 `agent-envelope` 폴더의 모델 표(`models.conf`)가 든다. 설치가 이 자리의 줄을 이름 셋(`AGY_DEFAULT_MODEL` · `AGY_MODEL_DELEGATE` · `AGY_FALLBACK_MODELS`)으로 옮겨 심고, 표를 못 읽으면 안 건드린 채 빨갛게 끝난다. 넘길 차례에서 `api:` 를 붙인 모델은 **구글 API 키(`GOOGLE_API_KEY`)가 있을 때만** 그 키로 돈다 — 무료 키는 구글 약관상 보낸 내용이 제품 개선에 쓰일 수 있다. 키가 없으면 그 차례를 건너뛰고 그대로 돈다. 다른 자리에서 심긴 값이 그대로 남아 있으면 걷는다 | 사용자 환경변수 — 스킬 `agy-background` 가 읽는다 |
| 스킬 `agy-background` — 위 「칸 없이 깔리는 스킬」 | `~/.claude/skills/` · Codex 를 골랐으면 `~/.agents/skills/` 에도 |
| Python — 그 스킬의 래퍼가 돈다(Claude 는 `pythonw` 로 뒤에서, Codex 는 `python` 으로 앞에서) | 개발도구 칸을 꺼도 깐다 |
| agy 설정 둘 — 규범을 가리키는 `~/.gemini/config/AGENTS.md`, 룰을 가리키는 `~/.gemini/config/rules.json`. **옮겨 적은 사본이 아니라 `~/.paisetup` 의 규범 · 룰을 이 PC 홈의 절대 경로로 가리키는 파일이다**(아래 「규범 · 룰 · 스킬」). **제작자 칸의 agy 칸을 켰을 때만** | `~/.gemini/config/` — 우리가 쓴 꼴이 아닌 같은 이름 파일은 `~/.paisetup/backups/<시각>/` 에 떠 둔다 |

사외에서 agy 가 로그인 전이면 터미널에서 `agy` 를 한 번 띄워 Google 계정으로 로그인한다(사내는 위 「어디에 붙나」
대로 회사 키로 선다).

#### Codex · Copilot 맡기기 — Claude 나 안티그래비티와 Codex 를 같이 고르면

제품 칸에서 **Claude 와 Codex 를 둘 다** 고르면 Claude 가 Codex 에게 일(긴 조사 · 큰 코드 읽기 · 분석 · 리뷰 · 다른 모델의
의견 · 웹 조사)을 뒤에서 맡기는 스킬 `codex-copilot-background` 가 선다. **안티그래비티와 Codex 를 같이 고르면** agy 도 같은
스킬로 맡긴다 — agy 에서는 끝날 때까지 기다려 답을 읽는다(결정 0099). 사내는 Codex 를 회사 키로 게이트웨이에 물리는 회사
설정이 서는 자리에서 선다. 받는 쪽의 권한은 맡길 때 일에 맞춰 고른다 — `--write` 없이 맡기면 읽기만 하고(claude-config 결정 0092 · 0093), 고치거나
적어 봐야 할 일(`--write`)은 맡긴 쪽이 세운 작업 폴더 안만 쓴다. Codex 가 한도면 Copilot 이 이어 받는데, Copilot 은 셸 없이 편집 도구만
연다(결정 0100 · 0109).

| 무엇 | 어디에 · 언제 |
|---|---|
| 스킬 `codex-copilot-background` — 위 「칸 없이 깔리는 스킬」 | `~/.claude/skills/` · 안티그래비티를 같이 골랐으면 `~/.gemini/config/skills/` |
| Python — 그 스킬이 돈다(Claude 는 `pythonw` 로 뒤에서, agy 는 `python` 으로 앞에서) | 개발도구 칸을 꺼도 깐다 |
| 자리 값 — **자리마다 다르다.** **사외**는 Codex 가 ChatGPT 로그인으로 실시간 웹 검색을 하고, Codex 한도가 차면 Copilot 이 받는다. **사내**는 Codex 가 회사 설정 틀대로 로컬 프록시를 거쳐 게이트웨이로 가고, 웹 검색도 그 프록시가 게이트웨이로 잇는다. Copilot 으로는 넘기지 않는다(사내에서 그 쓰임이 아직 안 정해졌다). 두 자리 다 Codex 를 관리자 승인이 안 드는 윈도 샌드박스로 띄운다. 이름(`CC_BG_AGENTS` · `CC_BG_CODEX_WEB_SEARCH` · `CC_BG_CODEX_WIN_SANDBOX`)과 자리별 값은 `install.ps1` 의 `$CcBgVarsBySite` 가 든다. Codex 의 모델 둘 — 깊은 판단의 `CC_BG_CODEX_MODEL_DELEGATE` 와 심부름의 `CC_BG_CODEX_MODEL` — 은 맡기기 모델 표(위 「agy 묶음」)가 그 자리에 이름을 줄 때만 심고, 둘 다 없으면 Codex 설정의 모델(대화형 기본값)로 뜬다 | 사용자 환경변수 — 스킬의 래퍼가 읽는다 |
| Copilot CLI — Codex 한도가 찼을 때 받는 쪽 | 제품 칸에서 **Copilot 을 고르면** 사내 · 사외 다 깔린다(위 「고른 도구」). 받는 쪽으로 쓰는 것은 자리 값이 Copilot 을 드는 사외다. 없으면 Codex 만으로 돈다 |

**사외의 로그인은 한 번씩 손으로 한다** — Codex 는 터미널에서 `codex login`(ChatGPT 계정 · 브라우저가 뜬다). 설치 창의 CLI 칸
끝에도 같은 줄이 찍힌다. Copilot CLI 는 따로 로그인하지 않고 gh 로그인(GitHub 계정 — Copilot Free 도 된다)을 쓴다 — 설치 끝
검증이 그 로그인을 재서, 없거나 무효면 노란 줄로 `gh auth login` 한 번을 든다(아래 「설치가 도는 중」). 사내 Codex 는 회사 키로
서서 로그인이 없다. 사내에서 Copilot CLI 의 로그인과 쓰임은 아직 정해지지 않았다.

#### Claude 맡기기 — Claude 와 Codex 나 안티그래비티를 같이 고르면

위의 거울이다. 같은 조건에서 Codex 가 Claude 에게 일을 맡기는 스킬 `claude-background` 가 Codex 홈에 선다.
Claude 와 안티그래비티를 같이 고르면 agy 도 같은 스킬로 맡긴다(결정 0099).
`--write` 없이 맡기면 받는 Claude 는 읽기 · 찾기 · 웹 읽기 도구만 보이게 뜨고, MCP 서버 · 스킬 · 훅은 끈다(claude-config 결정 0098).
고치기를 맡길 때(`--write`)는 편집 도구 둘을 맡긴 쪽이 세운 작업 폴더 안에만 허락하고 셸은 안 연다(결정 0100). Claude 는 이 PC 의 설정 그대로 붙는다 — 사외는 구독 로그인, 사내는 위 게이트웨이 값이다.

| 무엇 | 어디에 · 언제 |
|---|---|
| 스킬 `claude-background` — 위 「칸 없이 깔리는 스킬」 | Codex 를 골랐으면 `~/.agents/skills/` · 안티그래비티를 골랐으면 `~/.gemini/config/skills/` |
| Python — 그 스킬의 래퍼가 `python` 으로 돈다 | 개발도구 칸을 꺼도 깐다 |

### 규범 · 룰 · 스킬 — 그 칸이 옮기는 것

「제작자의 규범 · 룰 · 스킬도 깝니다」 칸은 **도구마다** 고른다(결정 0099).

**주로 일하는 도구에만 켠다.** 규범 · 룰 · 스킬 목록은 그 도구가 부를 때마다 맥락에 싣는다 — 켠 도구는 그만큼 호출마다
무거워진다. agy 로 잰 값이 그 크기다: 설정 없이 호출 하나에 입력 약 11,700 토큰, 규범과 스킬 목록을 실으면 약 16,000
토큰(claude-config 결정 0083). Codex 도 규범 블록이 호출마다 실린다. 그래서 **직접 대화하며 일을 시키는 도구**에만 켜고,
조사 · 리뷰를 **가끔 맡기기만 하는 도구**는 끄면 맡길 때마다 가볍게 부른다 — 맡긴 일에 드는 규칙은 맡기는 쪽이 작업
지시서(`agent-envelope`)에 그때그때 싣는다. 예를 들어 Claude 로 일하고 Codex · agy 에는 조사 · 리뷰만 맡기면 Claude 만 켠다.
칸을 꺼도 회사 문서 스킬 · 맡기기 스킬 · 안전 훅은 그대로 깔린다(위 「칸 없이 깔리는 스킬」).

**규범 · 룰 · 스킬은 한 자리에 모았다가 켠 도구에만 놓는다.** 먼저 이 PC 의 `~/.paisetup` 에 모이는데, 어느 도구도 그
자리를 스스로 읽지 않는다 — 그래서 칸을 켠 도구에만 실린다. 무엇이 어느 홈에 어떤 꼴로 가나는 짐의 갈 곳 표(`kit/tool-homes.conf`)가
정하고, 놓는 일은 짐의 파이썬 프로그램 `kit/tool-homes.py` 하나가 한다. 아래는 그 결과를 사람 눈으로 적은 것이다.

- `~/.paisetup/standard/` — 설치가 짐의 규범 · 룰 · 스킬로 채운다. 칸을 다 꺼도 Python 이 서 있으면 선다(어느 도구도 안 읽는다)
- `~/.paisetup/personal/` — 「내 저장소 받기」에 넣은 설정 저장소가 갈 곳 표와 원본을 든 PC 에만 선다. 그 저장소의
  배포와 세션 훅이 채우고, 규범 · 룰 · 에이전트마다, 스킬은 스킬 하나마다 이쪽이 이긴다(아래 「설정 저장소를 넣어도」)
- `~/.paisetup/placed.tsv` 는 `tool-homes.py` 가 놓은 사본의 기록이고, `~/.paisetup/backups/<시각>/` 은 그것이 덮거나 걷기 전에 떠 두는 자리다

켠 도구의 홈에는 이렇게 선다.

- **Claude** — `~/.claude/CLAUDE.md` 에 표지 두 줄(`<!-- paisetup:norms BEGIN -->` · `END`)과 그 사이 한 줄이 선다 —
  `~/.paisetup` 의 규범 파일을 읽어 오라는 가져오기 줄이다. **표지 밖에 손수 쓴 글은 그대로 둔다.** 룰은 `~/.claude/rules/` 에
  사본으로 깔린다 — 룰이 언제 걸리나가 그 파일 머리에 적혀 있어 가리킬 수 없다. 에이전트는 설정 저장소가 든 PC 에서만
  `~/.claude/agents/` 에 사본으로 깔린다(짐에는 없다)
- **Codex** — `~/.codex/AGENTS.md` 의 같은 표지 사이에 규범 본문과, 룰마다 「이 파일들을 만질 때는 이 룰을 먼저 읽는다」 한
  줄이 선다. Codex 는 다른 파일을 끌어오지 못해 본문을 싣는다. 표지 밖은 그대로다
- **안티그래비티(agy)** — `~/.gemini/config/AGENTS.md`(규범을 가리키는 한 줄)와 `~/.gemini/config/rules.json`(룰 폴더를
  가리킨다). 이 PC 홈의 절대 경로로 적힌다 — 데스크탑 앱이 그 꼴만 받는다
- **스킬** — 도구마다 제 스킬 자리(Claude `~/.claude/skills/` · Codex `~/.agents/skills/` · agy `~/.gemini/config/skills/`)에
  스킬 폴더째 사본으로 선다. 짐의 스킬이 다 가고 — 위 「칸 없이 깔리는 스킬」의 이름도 고른 제품과 상관없이 든다 — 맡기기
  스킬만 그 일을 받는 도구의 홈에는 안 간다(받는 쪽 홈에 서면 그 도구가 제게 맡기는 길을 든다). 어느 이름이 어느 홈에 안
  가나는 갈 곳 표의 `not` 줄이 든다. 그 자리에는 사람이 둔 스킬도 산다 — 같은 이름의 폴더가 `tool-homes.py` 의 기록에 없으면
  바이트가 같을 때만 그대로 두고 기록하고, 다르면 폴더째 `~/.paisetup/backups/<시각>/` 으로 옮긴 뒤 놓는다. 데스크탑 앱이 받아
  두는 `~/.claude/skills/synced/` 는 안 건드린다

⚠ **표지가 없는 `CLAUDE.md`.** Claude 칸을 켠 판에서 표지가 없는 `~/.claude/CLAUDE.md` 는 규범을 통째로 깐 사본으로 보고,
`~/.paisetup/backups/<시각>/` 에 떠 둔 뒤 표지 블록만 남긴다. 거기 손수 적은 글이 있었으면 그 백업에서 표지 밖으로 옮겨
적는다 — 표지가 선 뒤로는 표지 밖을 안 건드린다. Claude 칸을 끈 판은 표지 없는 `CLAUDE.md` 에 손대지 않는다.

**칸을 끄면 그 도구에서 `tool-homes.py` 가 놓은 것만 걷는다** — 표지 사이 블록(Claude · Codex), 우리가 쓴 꼴 그대로인 agy 파일 둘, 기록에
든 룰 · 에이전트 · 스킬 사본. 놓은 그대로면 지우고, 사람이 고쳤으면 `~/.paisetup/backups/<시각>/` 으로 옮긴다. 블록을 걷고 남은
글이 없으면 그 파일을 지운다. 표지 밖의 글과 기록에 없는 파일은 안 건드린다. 스위치는 이 칸 하나다 — 도구 폴더가 있나는 안
본다.

**칸을 켜고 끄면 스킬은 그 한 번의 설치 안에서 넘어간다** — 설치는 `tool-homes.py` 를 먼저 부르고 칸 없이 깔리는 스킬을 뒤에
깐다. 끈 홈은 `tool-homes.py` 가 제 것을 걷은 뒤 설치가 고른 제품의 스킬을 깔고(위 「칸 없이 깔리는 스킬」), 켠 홈은 설치가
전에 깐 사본을 `tool-homes.py` 가 넘겨받는다 — 바이트가 같으면 그대로 두고 기록만 하고, 다르면 폴더째 백업 자리로 옮긴 뒤
새로 놓는다. 설치의 그 홈 기록도 백업 자리로 간다.

짐에 `tool-homes.py` · 갈 곳 표나 칸 없이 깔 스킬이 없으면 **실패로 센다** — 짐이 깨졌다는 뜻이다.

**고른 도구는 사용자 환경변수 `PAISETUP_PERSONAL` 에 남는다**(예: `claude,codex` · 아무것도 아니면 `none`). `tool-homes.py` 와 설정 저장소의
배포가 이 값을 읽는다.

**설정 저장소를 넣어도 이 칸이 스위치다**(결정 0107 · 0112). 달라지는 것은 무엇이 가나뿐이다.
- **켠 도구의 규범 · 룰 · 스킬** — 설치는 비켜서지 않고 짐으로 표준 층을 채운다. 그 저장소의 갈 곳 표(`tool-homes.conf` —
  씨앗에 실려 있다)가 적은 자리에 원본을 두면 그 저장소의 배포와 세션 훅이 개인 층을 채우고, 규범 · 룰 · 에이전트마다(스킬은
  스킬 하나마다) 개인 층이 이긴다 — 원본이 없는 것은 짐의 것이 간다. 그래서 그 저장소에 없는 짐 스킬도 서고, 저장소에서 지운
  스킬도 짐에 같은 이름이 있으면 짐의 것이 간다. 홈에 놓는 것은 둘 가운데 새 판의 `tool-homes.py` 하나라 설치와 배포가 같은
  홈을 번갈아 덮지 않는다. 이 판 전에 씨앗으로 만든 저장소처럼 갈 곳 표가 아예 없으면 개인 층이 안 서고 짐의 것이 간다
- **끈 도구** — 저장소가 있어도 `tool-homes.py` 가 놓은 것을 걷고(위), 그 홈의 스킬은 설치가 칸 없이 깔리는 것만 고른 제품대로
  깐다
- **설치기를 안 돌린 자리**(원격 컨테이너 등) — 값이 없으면 규범 · 룰 · 에이전트 · 스킬은 Claude 에만 놓인다

⚠ **칸은 설치 창에서 바꾼다.** 사용자 환경변수 `PAISETUP_PERSONAL` 을 손으로 고치면 설정 저장소의 배포 · 세션 훅이 끈 도구의
홈에서 우리 스킬을 걷는데 설치는 안 돌아, 다음 설치까지 그 홈에 칸 없이 깔리는 스킬도 없다.

⚠ **이 판 전에 씨앗으로 만든 저장소의 `deploy.ps1` 은 스킬을 제 손으로 민다.** 짐에도 있는 이름이면 그 배포와
`tool-homes.py` 가 같은 폴더를 번갈아 고친다 — 그 저장소의 `deploy.ps1` · `tool-homes.conf` · `.claude/hooks/tool-homes.py` 를
홈에 깔린 새 씨앗(`~/.claude/seeds/config-repo/`)의 것으로 갈면 걷힌다.

**옛 판에서 올라오면 — 옛 칸은 Claude 로 이어받고, 한 번만 묻는다.** 예전에는 칸이 하나(「제작자의 Claude Code 규범 · 룰 ·
스킬도 깝니다」)였고, 켜면 Claude 홈에 더해 안티그래비티를 같이 고른 PC 의 agy 에도 규범을 깔았다(Codex 에는 안 깔았다). 로그온
자동 실행이 그 옛 칸으로 새 판을 부르면 **옛 칸을 Claude 로 읽고 평소처럼 설치한다** — 자동 실행은 조용히 올리려고 있는 것이라
멈추지 않는다. 그 판에서 agy 에 깔려 있던 규범 · 룰을 가리키는 둘은 우리가 쓴 꼴 그대로면 걷히고, 사람이 고쳤으면 그대로 둔다. 설치가 끝나면 자동 실행 기록을 새
꼴로 고쳐 「골랐다」로 남기고, 바꿀 수 있게 **설치 창을 한 번** 띄운다 — 닫으면 그대로(Claude)이고 다시 묻지 않는다. 받을
도구를 고르고 [설치 시작]을 누르면 그 선택이 새 기록이 된다. 그 창의 안내 상자는 이 판의 릴리스 노트를 열 수 있게 묻는다.

⚠ **덮어쓰는 것이 아니라 합친다.** 홈에 이미 있던 **다른 이름은 남는다** — 설치가 걷는 것은 제가 깔았다고 적어 둔 것뿐이다.
같은 이름의 룰 · 에이전트 파일이 우리 것과 다르면 덮기 전에 `~/.paisetup/backups/<시각>/` 에 떠 둔다. 같은 이름의 스킬 폴더는
파일 하나씩 덮지 않는다 — 우리 것과 다르면 폴더째 옮겨 두고 놓는다(위 「스킬」).

**설치는 깐 것을 기억한다.** `tool-homes.py` 가 놓은 룰 · 에이전트 · 스킬 사본은 그 기록(`~/.paisetup/placed.tsv`)에, 칸 없이 깔린
스킬 이름은 홈마다 `.paisetup-skills`(위 「칸 없이 깔리는 스킬」)에 적는다. 다음 설치 때 **전에 깔았는데 이번에 안 놓는 것**(이번
원본 — 짐 · 설정 저장소 — 에 없다 · 칸을 껐다)을 걷는다 — `tool-homes.py` 의 것은 놓은 그대로면 지우고 고쳤으면
`~/.paisetup/backups/<시각>/` 으로, 칸 없이 깔린 스킬은 그 홈의 `backups/install-skills-<시각>/` 로 옮긴다. 손수 만든 것은 그 기록에
없으니 안 건드린다.

**제 규율을 쓰려면 — 이 칸이 아니라 「내 저장소 받기」다.** 짐은 손으로 열 자리가 아니라서
(`Setup.exe` 가 제 안에서 꺼내 판마다 새 폴더에 편다) 거기 든 것을 갈아 끼워 봐야 다음 판에서
말없이 되돌아간다. 제 규범·룰·스킬은 **제 설정 저장소에 둔다** — 그 주소를 「내 저장소 받기」 칸에 넣으면
설치가 저장소를 받고, 그 저장소 뿌리의 훅이 홈에 깐다. 규범 · 룰 · 에이전트 · 스킬은 그 저장소의 갈 곳 표(`tool-homes.conf` —
씨앗에 실려 있다)가 적은 자리(`.claude/CLAUDE.global.md` · `.claude/rules.global/` · `agents/` · `.claude/skills/` ·
`.agents/skills/`)에 원본을 두면 간다 — 없는 것은 짐의 것이 간다. 꼴은 그 표의 머리가 든다. 그 저장소를 만드는 법은 아래 「내 저장소 받기」 절이 든다.

## Usage

설치 창의 기록 칸 마지막이 이렇게 찍힌다. **하나라도 `[X]` 나 `[?]` 가 서면 안 선 것이다** — 창 아래
줄도 빨갛게 바뀐다. 노란 `[?]` 는 「없다」가 아니라 「못 쟀다」라 다시 깔 일이 아니다(아래 「검증 칸이 `[X]` 일 때」).
고른 도구와 자리(사내·사외)에 따라 줄이 더 붙는다 — 아래 예는 사내에서 Claude 만 켠 판을 줄인 것이다.

```text
=== 검증 ===
  [O] VS Code
  [O] 클로드 확장
  [O] Claude Code CLI
  [O] 그림 문 몸통 (씨앗의 image-gate.py)
  [O] 그림 문 껍데기 (씨앗의 image-gate.sh)
  [O] 그림 문 배선 (홈 settings.json 의 PreToolUse)
  [O] 웹 다시 찾기 껍데기 (씨앗의 web-retry.sh)
  [O] 웹 다시 찾기 배선 (홈 settings.json 의 PostToolUse · PostToolUseFailure)
  [O] DRM 길잡이 몸통 (씨앗의 drm-guide.py)
  [O] DRM 길잡이 껍데기 (씨앗의 drm-guide.sh)
  [O] DRM 길잡이 배선 (홈 settings.json 의 UserPromptSubmit · PreToolUse · PostToolUseFailure)
  [O] DRM 길잡이 matcher (이벤트마다 진본과 같다)
  [O] 컨텍스트 알림 몸통 (씨앗의 context-alert.py)
  [O] 컨텍스트 알림 껍데기 (씨앗의 context-alert.sh)
  [O] 컨텍스트 알림 배선 (홈 settings.json 의 UserPromptSubmit)
  [O] 컨텍스트 알림 matcher (이벤트마다 진본과 같다)
  [O] Bash 겹역슬래시 보정 배선 (홈 settings.json 의 PreToolUse)
  [O] PowerShell UTF-8 BOM 보정 배선 (홈 settings.json 의 PostToolUse)
  [O] ANTHROPIC_BASE_URL
  [O] ANTHROPIC_AUTH_TOKEN

  3초 뒤에 엽니다 — 위 검증 칸을 먼저 읽는다
  VS Code — 띄웠다

=== 끝 === VS Code 를 열었습니다 — Ctrl+Shift+P → Claude 로 확장을 엽니다
```

**마지막 `=== 끝 ===` 줄이 다음에 할 일을 댄다** — 창 아래 줄에 뜨는 것도 그 줄이고, 갈래마다
다른 말을 한다(띄웠다 · 이미 떠 있다 · 못 찾았다). 띄운 것이 VS Code 면 거기서
`Ctrl+Shift+P` → `Claude` 로 확장을 연다. 설정 저장소들은 VS Code 의 신뢰 목록에 미리 적혀 있어 처음 열어도 작성자를
믿느냐고 묻지 않는다. 설치하는 동안 VS Code 가 떠 있었으면 적기를 미루고 `VS Code — 띄웠다` 아래에
`VS Code 가 이 폴더를 믿느냐고 물으면 Trust 한 번 — 확장이 함께 풀린다` 줄을 낸다 — 그때는 묻는 창에서 Trust 를 한 번
누른다. 그 전에는 제한 모드라 확장이 다 꺼져 있고, 한 번에 Claude · Codex · agy 확장이 함께 풀린다. 미룬 것은 VS Code 를
다 닫은 뒤의 다음 설치가 적는다.

### 같이 깔린 환경 자료 — 어디에 있나

| 자리 | 무엇 |
|---|---|
| `~/.claude/posco/` | **사내 게이트웨이 환경 문서 한 층.** 무엇이 되고 안 되는지는 **이 폴더 전체**가 답한다 — 한 장만 보고 판정하지 않는다 |
| `~/.claude/seeds/gateway/` | **게이트웨이 배관 씨앗.** 새 프로젝트를 시작할 때 이 폴더를 복사해 출발한다. import 해서 쓰는 라이브러리가 아니다 |
| `~/.claude/seeds/check/` | **검사 씨앗.** 새 프로젝트의 `_check/` 가 이것을 복사해 출발한다 — 판정을 내는 공용 부품 · 종료 코드 약속을 검사하는 도구 · 어느 저장소에서나 도는 커밋 게이트가 들어 있다. 복사해 간 사본에는 원본을 가리키는 설명이 붙어 있고, 원본이 바뀌면 `borrowed_check.py --receive` 로 다시 받는다 |
| `~/.claude/seeds/config-repo/` | **설정 저장소 씨앗.** 아래 「내 저장소 받기」 칸이 기대하는 저장소를 만드는 본보기이고, **그대로 돌아가는 한 벌**이 다 들어 있다. **지우지 않는다** — 설정 저장소가 없는 PC 에서는 저장소들의 세션 훅과 커밋 게이트가 여기 든 본체와 실행기를 불러 쓴다 |

### 「내 저장소 받기」 칸 — 안 넣어도 된다

빈 칸이 **기본이고 맞는 답이다** — 위에 적은 것은 이 칸과 상관없이 다 깔리고, 채워도 그대로다.
이 칸은 *제 저장소*를 **받아 두는** 자리이고, 설치는 **`~/repos/<저장소 이름>`** 으로 받는다.
그 자리는 **칸 아래 「받는자리」를 누르면 열린다** — 경로를 손으로 찾을 일이 없고, 아직
아무것도 안 받았으면 그 폴더가 없는 것이 정상이다.
**여러 개는 빈칸으로 가른다** — 주소에는 빈칸이 들지 않으므로 그것으로 가를 수 있다:

```text
https://github.com/나/설정.git  https://github.com/나/메모.git
```

받아 온 저장소 뿌리에 **`.claude/hooks/session-start.sh`**(Claude Code 의 SessionStart 훅)가
있느냐에 따라 뒤가 갈린다 — 있으면 설치가 그 훅을 불러 나머지를 잇게 하고, 없으면 받아 둔 것으로
끝난다. 여러 저장소가 그 파일을 들고 있으면 **첫 것만 부르고** 나머지는 이름만 찍는다(둘을 잇달아
부르면 뒤엣것이 앞엣것의 키·설정을 덮는다). 그 훅이 무엇을 하나는 **`~/.claude/seeds/config-repo/README.md`**
(설정 저장소 씨앗)가 든다. 설정 저장소가 무엇이고 어떻게 만드나(일곱 걸음)는 칸 옆
「설정저장소 만드는 법」 링크가 여는 안내 한 장이 든다 — 설치가 끝난 뒤에도
`~/.claude/seeds/config-repo/config-repo-howto.html` 을 더블클릭하면 같은 장이 열린다.

**옛 판 우리 훅은 먼저 지금 판으로 간다.** 옛 설치 · 배포가 저장소마다 놓은 우리 훅이 이 설치본보다
옛 판이면, 그대로 부를 때 설치가 놓은 규범 · 룰을 제 사본으로 덮는다. 그래서 설치는 그 저장소의 우리
파일 묶음을 홈 씨앗의 지금 판으로 바꿔 둔 뒤 부른다. 작업 나무에만 쓰고 커밋은 안 하니 「우리 파일을
지금 판으로 갈았다」 줄이 뜬 저장소에서 보고 커밋한다 — 그 줄이 바뀐 파일을 하나하나 대고, 보기 ·
되돌리기 명령(`git -C <저장소> diff -- <파일>` · `git -C <저장소> checkout -- <파일>`)도 댄다.

- **머리말에 우리 표지가 있는 파일은 그 사람이 고쳐 커밋했어도 덮는다.** 덮기 전 판은 git 이 들고, 바뀐
  파일은 다음 Claude 세션부터 선다. 되돌려도 다음 설치(로그온 자동 실행 포함)가 다시 간다 — 그 저장소에서
  우리 훅을 안 쓰려면 `.claude/hooks/session-start.sh` 와 `.claude/settings.json` 의 SessionStart 줄을 함께 걷는다
- **`.claude/settings.json` 은 덮지 않고 우리 항목만 고친다** — 우리 훅 등록을 지금 판으로 바꾸고,
  훅 파일이 사라진 우리 꼴 등록은 걷고, `env.PYTHONUTF8` 이 없으면 더한다. 사람이 넣은 키 · 훅 · 값은 그대로다.
  같은 줄에 「우리 항목만 고쳤다」로 따로 대고(걷은 등록의 이름도), 보기 · 되돌리기는 위와 같다. 엄격한 JSON 이
  아니거나(Claude Code 도 그 파일을 안 읽는다) 우리 키와 대소문자만 다른 키(`Hooks` 등)가 있으면 그 파일만 두고
  바로잡는 길을 한 줄로 댄다
- 머리말에 우리 표지가 없는 파일은 그 사람의 것이라 두고, 같은 줄에 「우리 표지가 없어 둔 것」으로 댄다
- 커밋 안 한 손질 · git 밖의 사본이 있거나, 설정 저장소 꼴이거나, 곁에 옛 claude-config 가 서 있으면 안
  갈거나 안 넘긴다 — 「이 저장소의 훅으로 넘기지 않는다」 줄이 까닭과 고치는 길을 대고, 다음 저장소의 훅을 부른다
- **칸에 안 넣은 저장소도 본다.** `~/repos` 바로 아래 저장소의 옛 우리 훅은 제작자 칸을 하나라도 켰으면 같은
  지킴으로 지금 판으로 간다(그 훅을 부르지는 않는다). 끄면 안 건드리고 「작업 루트의 옛 우리 훅 — 칸에 안 든
  저장소」 줄이 고치는 길을 댄다. 이 칸을 비워도 돈다. `~/repos` 밖을 가리키는 링크 폴더 너머와 git 저장소가
  아닌 폴더에는 안 쓰고 알리기만 한다
- 못 갈고 남은 옛 훅은 끝 요약 「옛 판 세션 훅이 남은 저장소」에도 댄다 — 저장소 설정이 그 훅을 안 걸어도
  홈의 세션 훅이 그것을 부른다

**칸은 창에서 고른다.** 여러 대를 같은 값으로 세워야 하면 `Setup.exe` 에 깃발을 붙여
칸을 미리 채워 둘 수 있다 — 창은 그대로 뜬다:

```powershell
.\Setup.exe -NoDevTools          # 개발 도구(Git · Python · GitHub CLI)를 빼고 깐다 — 창에는 이 칸이 없다
.\Setup.exe -PersonalFor claude,codex  # 제작자 칸에서 그 도구를 켠 채로 연다(claude · codex · agy)
.\Setup.exe -WithPersonalConfig  # 제작자 칸을 Claude 만 켠 채로 연다(옛 칸과 같은 뜻)
.\Setup.exe -NoUpgrade           # 갱신 칸을 끈 채로 연다
```

**창까지 안 띄우려면 설치 몸통을 직접 부른다.** 한 번 눌러 본 PC 면 짐이
`%LOCALAPPDATA%\Claude Code Setup\<판>\` 에 펴져 있다 — 그 자리의 `install.ps1` 이 몸통이고,
위 셋에 더해 `-NoLaunch`(끝에 창을 안 띄운다 — 물음창도 안 뜬다) · `-Yes`(묻지 않는다) ·
`-Pick claude,codex`(깔 도구 — 안 주면 설치 창의 기본값) · `-NoVsCode`(VS Code 와 확장을 뺀다)를 받는다.
로그온 자동 실행은 `-AutoRun` 이 걸고 `-NoAutoRun` 이 걷는다 — **둘 다 안 주면 지금 상태를
그대로 둔다**(값 파일의 `#autorun = yes|no` 가 기본을 들 수 있다). 창은 늘 둘 중 하나를 준다.

**여러 번 눌러도 안전하고, 누를 때마다 최신으로 올린다.** 이미 있는 것은 판 번호를 견줘 바뀐
것만 찍는다 — `올렸다 1.2.3 -> 1.2.9` 처럼. 그래서 이 설치본은 처음 세울 때만이 아니라
**갱신할 때도 같은 것을 누르면 된다.** 깔린 판을 못 읽은 것은 `(판을 못 읽었다)` 로 찍고, 판을 모른다고
다시 받거나 깔린 것 위에 새로 깔지 않는다.

## 안 될 때

**화면을 이미 닫았어도 물어볼 거리가 남는다 — 기록 파일.** 설치 한 판이 끝날 때마다(중간에
창을 닫아 멈춘 판도) 설치 창에 떴던 줄이 `%LOCALAPPDATA%\Claude Code Setup\logs\` 에
`install-<날짜-시각>.log` 로 남는다. **설치 창이 떠 있으면 경로를 찾을 일이 없다** — 단추 왼쪽의
「설치기록」을 누르면 그 폴더가 열리고 가장 최근 기록이 집혀 있다. **아래 어느 칸이든
「그 줄을 그대로 보낸다」고 할 때, 화면이 없으면 그 폴더의 가장 최근 파일을 보낸다.** 판 폴더
바깥이라 다음 판을 깔아도 남고, **키는 안 들어 있다** — 설치가 찍는 것은 심은 값이 아니라 심은
이름이다.

### 설치 창이 뜨기도 전에 — `Setup.exe` 가 낸 창

설치 창이 못 뜨고 작은 창 하나만 뜬 자리다. **그 문구가 무엇을 해야 하는지를 가른다.**

| 창에 뜬 말 | 왜 · 어떻게 |
|---|---|
| `이 설치본에 판 번호가 없습니다` | 받은 파일이 성하지 않다 — **다시 받는다.** 두 번째도 같으면 그 문구를 설치본을 보낸 사람에게 보낸다 |
| `윈도우가 제 시스템 폴더를 안 알려 줍니다` | 윈도우가 `tar.exe` · `powershell.exe` 가 사는 시스템 폴더를 못 알려 준 자리다. 이 PC 의 윈도우 쪽 문제라 그 문구를 IT 에 보낸다 |
| `윈도우가 이 계정의 자리를 안 알려 줍니다` | 이 계정에 `%LOCALAPPDATA%` 가 안 잡힌 자리다. 로그아웃했다 다시 들어와 보고, 같으면 IT 에 사용자 프로필을 묻는다 |
| `설치 짐을 꺼내지 못했습니다` · `설치 짐이 반쪽만 풀렸습니다` | 짐이 펴지다 말았다. **다시 누른다** — 끝까지 안 펴진 자리는 `Setup.exe` 가 알아보고 그 판 폴더(`%LOCALAPPDATA%\Claude Code Setup\<판>`)를 지운 뒤 처음부터 다시 편다. 같으면 디스크가 찼는지, 백신이 파일을 들어냈는지 본다 |
| `설치 짐을 푸는 데 실패했습니다 — 이 윈도우가 너무 옛 판일 수 있습니다` | 짐은 윈도우에 딸려 오는 `tar.exe` 가 푸는데 **Windows 10 1803 보다 옛 판에는 그것이 없다.** 그보다 옛 판이면 IT 에 윈도우 업데이트를 요청한다. 그보다 새 판인데도 나면 다시 누른다 |
| `설치 화면을 띄우지 못했습니다` | PowerShell 이 정책에 막힌 자리다. 그 줄을 그대로 설치본을 보낸 사람에게 보낸다 |
| `설치 자리의 경로가 너무 깁니다` | 계정 폴더 경로가 너무 길어 설치 자리의 경로가 윈도우 한도를 넘었다. 그 문구를 설치본을 보낸 사람에게 보낸다 |
| `이미 더 새 판이 깔려 있어 그 자리는 그대로 둡니다` | 오류가 아니다 — 다운로드 폴더에 남은 옛 `Setup.exe` 를 누른 자리다. 설치는 그 판으로 이어서 하고, 바탕화면 아이콘은 더 새 판을 그대로 가리킨다 |

**아무 창도 없이 파일이 사라졌다면 — 백신이다.** 서명을 안 산 설치 파일이라 백신이
생김새만 보고 잡는 경우가 있다. 브라우저가 「위험한 파일」이라 하거나, 받아 둔 파일이
말없이 없어지거나, 백신이 격리했다는 알림이 뜬다. **백신이 붙이는 탐지 이름은 판마다 달라
우리가 미리 못 알려 준다** — 백신이 낸 문구를 **그대로 복사해 설치본을 보낸 사람에게 보낸다.**
그 문구가 있어야 IT 에 예외를 요청할 수 있고, 다음 판을 그 탐지를 피해 만들 수 있다.

### 설치가 도는 중

| 화면 | 왜 · 어떻게 |
|---|---|
| `winget 이 없다` | 설치가 먼저 되살려 본다 — 프로필에 다시 등록 → PowerShell 모듈로 고치기 → GitHub 에서 받기 차례로. 그래도 안 되면 계속 가되, 못 깐 것 이름과 IT 에 무엇을 요청할지(「앱 설치 관리자」)를 끝에 알려 준다 |
| winget 이 정책에 막힌다 | 사내 PC 정책이다. IT 에 문의한다 |
| **`지정한 경로가 존재하지 않습니다`** 창이 뜬다 | winget 이 받아 둔 설치기가 **실행 직전에 사라졌다.** 사내에서만 겪은 일이다 — 보안 프로그램이 갓 받은 파일을 지우는 것으로 보인다. **「확인」을 누르면 설치는 이어서 돈다** (안 누르면 그 자리에서 멈춰 있다). 그 앱만 나중에 손으로 깔고, 되풀이되면 IT 에 `%TEMP%\WinGet` 예외를 요청한다 |
| `! Claude 데스크탑 — 못 찾았다. 시작 메뉴에서 직접 연다` (다른 앱 이름으로도 뜬다) | 깐 데스크탑 앱을 윈도우 시작 메뉴에서 못 찾았다. 시작 메뉴에서 직접 열면 되고, **그 줄을 그대로 설치본을 만든 사람에게 보낸다** — 앱이 깔리는 방식이 자리마다 달라서 나는 일이다 |
| 확장은 도는데 응답이 안 온다 | 낡은 창이다. VS Code 를 **전부 닫고** 새로 연다 |
| `! gh 로그인이 무효다 …` · `! gh 로그인이 없다 …` (검증 칸 아래 노란 줄) | 저장소 주소를 넣었거나 사외에서 Copilot 을 고르면 설치가 끝에 gh 로그인을 잰다 — 내 저장소의 gh · git 과 Copilot CLI 가 쓰는 로그인이다. 다른 기기에서 같은 계정으로 gh 에 로그인하면 이 PC 의 로그인이 죽는 일이 흔하다. **새 터미널에서 `gh auth login` 한 번이면 된다.** 줄이 `GH_TOKEN` 같은 환경변수 이름을 대면 그 이름이 선 셸에서는 gh 가 로그인을 안 받는다 — 그 줄의 명령으로 먼저 비운다. `! gh 로그인 — 못 쟀다 (…)` 는 망이 끊겼거나 gh 가 옛 판이라 못 잰 것이다 — 괄호의 까닭을 본다 |
| `! ~/…/skills/<이름>/ — 받는 쪽 홈에 러너가 있다 · 우리 것이 아니라 안 걷는다` (노란 줄) | 맡기기 스킬이 제가 일을 맡기는 상대 도구의 스킬 자리에 서 있다 — 그 도구가 제게 맡기는 길이 생긴다. 어느 기록에도 없는 것(손으로 뒀거나 기록이 서기 전의 옛 판이 깐 것)이라 설치가 안 걷는다. 그 폴더를 지운다 |

### 검증 칸이 `[X]` 일 때

**칸마다 다음 걸음이 다르다.** 위에서부터 보고 **첫 번째 `[X]` 를 먼저 고친다** — 아래 것은
대개 그것에 딸린 것이다.

**노란 `[?]` 는 `[X]` 가 아니다 — 「없다」가 아니라 「못 쟀다」다.** 그 칸을 재는 명령이 20초 안에 안 끝나 설치가
거두고 지나갔거나 그 답을 못 읽었다는 뜻이라(줄이 까닭을 댄다) **다시 깔지 않는다.** 줄이 대는 명령을 터미널에서 한 번 쳐 본다 — 거기서도 멎으면 그 도구나
보안 프로그램 쪽이고, 바로 답하면 설치를 다시 누른다. `[?]` 는 빨강으로 안 세지만 하나라도 서면 설치는 「끝내지
못했습니다」로 끝난다. 데스크탑 앱의 `안 한 걸음` 은 그 앱이 깔렸는지를 못 잰 것이다 — 시작 메뉴와 윈도우 설치 목록에 안 보이고
`winget list` 가 졌다. 줄이 그 까닭을 댄다 — 종료 값(회사 망의 소스 인증서 오류 `0x8A15005E` 가 흔하다)이거나 한도를 넘긴 것이다.
깔린 앱 위에 다시 깔면 옛 판으로 내려갈 수 있어 손대지 않았다 — 앱이 있으면 그대로 쓰고, 없으면 줄이 대는 `winget list` 를
터미널에서 쳐 본다. `안 한 걸음` 의 까닭이 넘김이 아니면(종료 값 · 오류) 그 줄은 멎은 것이 아니라 그 명령이 진 것이다.

```text
  [?] VS Code — 못 쟀다: `code --version` 이 20초 안에 안 끝났다
  [?] 클로드 확장 — 못 쟀다: VS Code 와 한 전제 — `code --version` 이 20초 안에 안 끝났다
  [?] 안 한 걸음 · 파이썬 패키지(Pillow) — 못 쟀다: `python --version` 이 20초 안에 안 끝나 깔지 않았다
```

한 명령에 걸린 칸들은 「한 전제」를 댄다 — 위처럼 `code --version` 하나를 못 쟀으면 VS Code 와 고른 확장이 다 그 하나에
걸린 것이라, 그 명령 하나만 보면 된다. `안 한 걸음` 은 끝 검증에 짝 칸이 없는 걸음이다 — 있는지 몰라 깔지도 「없다」로
건너뛰지도 않았다. 그 아래 `! 울타리를 넘긴 프로브` 줄은 이 설치에서 넘긴 명령을 자리 수 · 한도와 함께 모은 것이다 —
위쪽에 「안 선다 · 없음」으로 적힌 줄이 그 명령에 걸렸으면 그 줄도 없는 것이 아니라 못 잰 것이다.

| `[X]` 가 뜬 칸 | 다음에 무엇을 하나 |
|---|---|
| `VS Code` | winget 이 못 깔았다. 위쪽 빨간 줄이 까닭을 든다 — 정책이면 IT, 아니면 다시 누른다 |
| `클로드 확장` · `Codex 확장` · `안티그래비티 확장` | VS Code 가 먼저 안 선 것이다. 위 칸을 먼저 고치고 다시 누른다. VS Code 는 `[O]` 인데 확장만 `[X]` 면 사내망이 확장 장터를 막은 자리라 IT 에 문의한다 |
| `Claude Code CLI` · `Codex CLI` · `Copilot CLI` · `Playwright (브라우저 MCP)` | npm 이 못 깔았다. Node.js 줄이 위에서 실패했는지 먼저 보고, 멀쩡했으면 위쪽 「설치 실패」 빨간 줄이 npm 이 뱉은 끝 줄을 든다 — 망 · 인증서 문제면 그 줄대로 고치고 다시 누른다. 이 줄은 npm 의 기록(`npm ls -g`)으로 잰 것이다 — CLI 를 띄워 재지 않는다(첫 실행에 제 짐을 푸느라 수십 초를 쓰는 CLI 가 있다). 창을 닫은 뒤 새 터미널에서 이름으로 서나는 아래 `npm 전역 자리` 줄이 잰다 |
| `안티그래비티 CLI` | 이것만은 npm 이 아니라 winget 이 깐다. 위쪽 빨간 줄이 까닭을 든다 — 정책이면 IT. 그 줄이 「안 잡힌다」면 그 줄대로 새 터미널에서 `agy --version` 을 다시 쳐 보고, 그래도 없으면 그 줄의 `winget install` 명령을 친다 |
| `npm 전역 자리 — 사용자 PATH (…)` | npm 으로 깐 CLI 가 서는 폴더가 사용자 PATH 에 없다 — 설치 창 안에서는 CLI 가 서도 **창을 닫고 새로 연 터미널에서는 이름으로 안 잡힌다.** 위쪽 「npm 전역 자리」 빨간 줄이 까닭을 든다: 「한도를 넘는다」면 사용자 PATH 에서 안 쓰는 자리를 걷고 다시 누르고, 그 밖이면 그 줄을 그대로 보낸다. 그 줄이 없으면 폴더가 아직 없는 것이다 — 위 CLI 줄을 먼저 본다 |
| `pip 사용자 자리 — 사용자 PATH (…)` | pip 가 사용자 자리에 깐 명령(`markitdown` 등)이 서는 폴더가 사용자 PATH 에 없다 — 새로 연 터미널에서 그 명령이 이름으로 안 잡힌다. 바로 위 `npm 전역 자리` 줄과 같다 — 위쪽 「pip 사용자 자리」 빨간 줄이 까닭을 든다 |
| `VC++ 런타임 (msvcp140.dll … · 14.40 이상)` | 런타임이 아직 14.40 보다 옛 판이다 — PPT 검수 패키지가 이 PC 에서 안 선다. 위쪽 「VC++ 런타임」 줄이 까닭을 든다: 노란 줄(「누를 사람이 없는 판이라 안 올렸다」)이면 설치 창으로 다시 눌러 승인 창에서 승인한다. 「관리자 승인이 안 났다」면 승인할 수 있을 때 다시 누른다. 「다시 시작해야」면 PC 를 다시 시작한 뒤 다시 누른다. 「관리자 승격이 안 선다」 · 「winget 이 없다」면 IT 에 「Microsoft Visual C++ 재배포 가능 패키지(x64) 14.40 이상」을 요청한다 |

| `ANTHROPIC_BASE_URL` · `ANTHROPIC_AUTH_TOKEN` | 키를 안 넣었거나 빈 값이다. 다시 눌러 넣는다 |
| `OPENAI_API_KEY` · `GEMINI_API_KEY` | 같은 회사 키를 Codex · 안티그래비티가 읽는 이름으로도 심는 자리다. 위의 `ANTHROPIC_AUTH_TOKEN` 이 같이 `[X]` 면 그것만 고치면 된다 |
| `Codex config.toml` · `안티그래비티 settings.json` | 회사 설정을 그 자리에 못 썼다. `~/.codex/` · `~/.gemini/` 가 읽기 전용인지 보고 다시 누른다. Codex 줄이 틀과 다른 키를 대면 그 키를 사람이 고친 것이다 — 다시 누르면 틀의 값으로 맞춘다 |
| `Codex 설정 (틀 병합 실패 · 틀 병합기가 없다 · python 없음)` | 있던 `~/.codex/config.toml` 에 회사 틀의 자리를 못 맞췄고, **파일은 그대로다.** 병합 실패면 그 아래 줄이 까닭을 댄다(TOML 로 안 읽히는 파일 · 병합기가 다룰 줄 모르는 꼴). python 이 없으면 설치를 한 번 더 누른다 — 앞 걸음이 python 을 깐다 |
| `자동 모드 기본값` · `agy 러너 허락` · `Codex · Copilot 러너 허락` | `~/.claude/settings.json` 의 `permissions` 에 그 값이 없다. `permissions` 가 표가 아니거나 `allow` 가 목록이 아니면 설치가 안 건드리고 위에 노란 줄로 알린다 — 그 꼴을 고친 뒤 다시 누른다. 자동 모드 줄이 사람 값을 대면 [O] 다(안 덮는다) |
| `묻지 않고 돌기 · <도구> (…)` | 괄호의 설정 파일에 그 키가 없다 — 위쪽 같은 이름의 빨간 줄이 까닭을 댄다. 「JSON 으로 못 읽었다」 · 「TOML 로 못 읽었다」 · 「… 가 표가 아니다」면 그 파일의 꼴이 깨져 설치가 안 건드린 것이다 — 고친 뒤 다시 누른다. Codex 줄이 「파이썬 3.11 이상(tomllib)이 안 선다」면 위쪽 Python 줄을 먼저 본다. 괄호가 사람이 둔 값을 대면 [O] 다(안 덮는다) |
| `로컬 프록시 (/health)` | **프록시가 안 떴다** — 사내에서 Claude Code 와 안티그래비티가 게이트웨이에 못 붙는다. Python 이 제대로 깔렸는지 보고 다시 누른다. 왜 이 프록시가 있고 손으로 어떻게 세우나는 `~/.claude/posco/pgpt-proxy/README.md` 가 든다 |
| `Opus 5 문 — prefill …` | **프록시는 떴는데 Opus 5 요청이 안 통한다** — 뜬 것과 통하는 것은 다른 문제라 따로 잰다. 괄호 안 숫자가 게이트웨이가 돌려준 응답 코드다: **500 이상이면 게이트웨이 너머에서 끊은 것이라 이 PC 문제가 아니고**(잠시 뒤 다시 누른다), 그보다 작으면 프록시가 제 일을 못 한 것이다. 재는 법은 같은 `~/.claude/posco/pgpt-proxy/README.md` 가 든다 |
| `로컬 프록시 단일 프로세스 …` · `와치독 감시 등록 …` | 프록시가 둘 이상 떴거나, 감시 작업이 윈도우 스토어의 가짜 `python` 껍데기(`WindowsApps`)를 가리킨다 — 그러면 프록시가 죽어도 감시 작업이 모른다. 다시 누르고, 같으면 그 줄을 그대로 보낸다 |
| `부팅 시 자동 실행 (PAISetup-AutoRun · PAISetup-AutoRun-Night)` | 자동 실행 작업 둘 가운데 하나라도 못 걸었다. 위쪽 「자동 실행 스케줄러 등록 실패」 · 「밤 자동 실행 스케줄러 등록 실패」 줄이 까닭을 든다 — 회사 정책이 작업 스케줄러를 막았으면 IT 에 문의한다 |
| `… 없음 (사외)` · `… — 프록시 주소 없음 (사외)` | 사외인데 사내에서 쓰던 값이 남아 있다. 설치가 우리 것인지 못 가려 안 지운 것이다 — 위쪽 「사내 잔재」 칸이 무엇을 지우고 무엇을 남겼는지 댄다. 남은 것이 사내 값이 맞으면 아래 「무를 때」 표대로 손으로 지운다 |

## 무를 때

**되돌리는 스위치는 아직 없다** — 아래를 손으로 지운다. PC 를 반납하거나, 부서를 옮기거나,
회사 게이트웨이를 떠나 개인 구독으로 돌아갈 때다.

⚠ **가장 급한 것은 게이트웨이 주소다.** `ANTHROPIC_BASE_URL` 이 사내 프록시(`127.0.0.1:18901`)를
가리킨 채로 남으면, **사외로 나간 노트북의 Claude 가 돌지도 않는 프록시로 요청을 보낸다** — 프로그램을
다 지워도 이 줄 하나가 남으면 그렇다. 이 값은 사용자 환경변수와 홈 설정(`~/.claude/settings.json`)
두 곳에 있다 — 둘 다 지운다.

| 지울 것 | 어디서 |
|---|---|
| **사용자 환경변수** — 펴진 짐의 `install.env` 에 값이 적힌 이름 전부(`ANTHROPIC_BASE_URL` · `GOOGLE_GEMINI_BASE_URL` · `ANTHROPIC_MODEL` 등)와 키 셋 `ANTHROPIC_AUTH_TOKEN` · `OPENAI_API_KEY` · `GEMINI_API_KEY` | 시작 메뉴에 「환경 변수」로 검색 → 「계정의 환경 변수 편집」. 지우고 창을 새로 연다 |
| **워드의 PDF 변환 안내 끄기** — 워드가 깔린 PC | `HKCU\Software\Microsoft\Office\<판>\Word\Options` 의 `DisableConvertPdfWarning` 을 지운다(판은 대개 `16.0`). 명령으로는 `Remove-ItemProperty 'HKCU:\Software\Microsoft\Office\16.0\Word\Options' -Name DisableConvertPdfWarning`. 지우면 PDF 를 워드로 열 때 안내가 다시 뜨고, 스킬 `drm-office-read` 는 그 PC 에서 PDF 를 워드로 못 연다. 설치를 다시 누르면(로그온 자동 실행도) 다시 1 로 둔다 |
| **홈 설정의 설치가 넣은 줄** — `~/.claude/settings.json` | `env` 칸에서 위와 같은 이름들, `modelPicker` 칸, `skipWebFetchPreflight` 칸, 설치기 폴더의 기록(`%LOCALAPPDATA%\Claude Code Setup\claude-settings.tsv`)에 적힌 `permissions` 의 값(`defaultMode` 와 `allow` 의 `pythonw` 러너 줄 — 그 기록 파일도), `hooks` 의 `PreToolUse` 안 `image-gate` · `bash-backslash-deny` 줄 · `PostToolUse` 안 `utf8-bom` 줄 · `PostToolUse` 와 `PostToolUseFailure` 안 `web-retry` 줄 · `UserPromptSubmit` 과 `PreToolUse` 와 `PostToolUseFailure` 안 `drm-guide` 줄을 지운다. 나머지는 사람이 쓰던 설정일 수 있으니 둔다. 훅 줄만은 설치 창에서 Claude 를 빼고 한 번 더 누르면 `tool-homes.py` 가 우리 것만 걷는다 |
| **로그인마다 뜨는 프록시 감시 작업** — 작업 이름은 `PGPTProxy-Watchdog` | 「작업 스케줄러」를 열어 그 이름을 지운다. 명령으로는 `Unregister-ScheduledTask -TaskName PGPTProxy-Watchdog -Confirm:$false`. 프록시가 도는 폴더 `%LOCALAPPDATA%\PGPT-Proxy` 도 지운다. (옛 판이 남긴 것은 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 의 `PGPTProxy`) |
| **홈에 깔린 환경 자료** | `~/.claude/posco/` · `~/.claude/seeds/` 폴더를 지운다. 씨앗 곁에 깔린 파이썬 패키지는 `python -m pip uninstall pillow` — 다른 프로그램도 쓸 수 있으니 필요할 때만 |
| **칸 없이 깔린 스킬** — 제작자 칸을 끈 도구의 홈 | 홈마다 기록에 적힌 이름의 폴더 · 그 기록 · 걷은 스킬을 옮겨 둔 `backups/install-skills-*` · 같은 이름이라 비켜 둔 `backups/install-aside-*`(사람 것이면 되살린다). Claude 는 `~/.claude/skills/` · 기록 `~/.claude/.paisetup-skills` · `~/.claude/backups/`, Codex 는 `~/.agents/skills/` · `~/.agents/.paisetup-skills` · `~/.agents/backups/`, 안티그래비티는 `~/.gemini/config/skills/` · `~/.gemini/.paisetup-skills` · `~/.gemini/backups/` 다. 스킬 폴더에는 사람이 둔 스킬도 사니 기록에 없는 이름은 둔다 |
| **안티그래비티의 훅** | 설치 창에서 안티그래비티를 빼고 한 번 더 누르면 설치가 걷는다. 손으로는 `~/.gemini/config/hooks.json` 의 `paisetup-drm-guide` · `paisetup-utf8-bom` · `paisetup-context-alert` 항목. 다른 항목은 사람이 넣은 것일 수 있으니 둔다. 고치기 전 것은 곁의 `hooks.json.before-paisetup-*` |
| **브라우저 MCP** | 설치 창에서 그 도구를 빼고 한 번 더 누르면 설치가 우리 등록만 걷는다. 손으로는 `claude mcp remove -s user playwright` · `codex mcp remove playwright` · `agy mcp remove playwright` — 지우기 전에 그 항목이 우리 것(명령 `node` · 첫 인자가 `browser-mcp.mjs`)인지 본다. Codex 를 고치기 전 것은 `config.toml.before-browser-mcp-<시각>` 에 있다. 꾸러미는 `npm uninstall -g playwright`, 받은 브라우저는 `%USERPROFILE%\.cache\ms-playwright\chromium-snapshot-*` 폴더 |
| **묻지 않고 돌기** — 고른 agy · Copilot · Codex | 설치가 걷지 않는다. 손으로는 `~/.gemini/antigravity-cli/settings.json` 의 `toolPermission` · `~/.gemini/config/config.json` 의 `userSettings` 세 칸 · `~/.copilot/settings.json` 의 `defaultPermissionMode` · `defaultMode` · `~/.codex/config.toml` 맨 위의 `approvals_reviewer` 줄을 지우거나, 그 도구의 설정 화면에서 다른 값을 고른다 |
| **제작자 칸의 규범 · 룰 · 에이전트 · 스킬** — `tool-homes.py` 가 놓은 것 | 설치 창에서 제작자 칸을 다 끄고 한 번 더 누르면 `tool-homes.py` 가 제가 놓은 것을 걷는다 — `~/.claude/CLAUDE.md` 와 `~/.codex/AGENTS.md` 의 표지(`<!-- paisetup:norms BEGIN -->` · `END`) 사이, `~/.gemini/config/AGENTS.md` · `~/.gemini/config/rules.json`, 기록 `~/.paisetup/placed.tsv` 에 든 룰 · 에이전트 · 스킬 사본. 손으로 할 때도 이 자리들이다 — 표지 밖은 사람이 쓴 글이다 |
| **규범 · 룰 한 벌 · 고른 도구 값** | `~/.paisetup/` 폴더(두 층 `~/.paisetup/standard/` · `~/.paisetup/personal/` · 기록 `~/.paisetup/placed.tsv` · 덮거나 걷기 전에 떠 둔 백업 `~/.paisetup/backups/` — 사람 것이 들었으면 되살린다)와 사용자 환경변수 `PAISETUP_PERSONAL` · `PAISETUP_PICK` · `PAISETUP_SITE`. 위 칸을 먼저 하고 지운다 — 홈의 가져오기 줄 · 가리킴 파일 · Claude 훅 등록이 이 폴더를 가리킨다 |
| **agy 묶음** (Claude · 안티그래비티를 골랐을 때) | 사용자 환경변수 `AGY_DEFAULT_MODEL` · `AGY_FALLBACK_MODELS` · `AGY_MODEL_DELEGATE` · 옛 판이 옛 스킬 목록을 떠 둔 `~/.claude/backups/install-agy-*` |
| **Codex · Copilot 맡기기** (Claude · Codex 를 골랐을 때) | 사용자 환경변수 `CC_BG_AGENTS` · `CC_BG_CODEX_WEB_SEARCH` · `CC_BG_CODEX_WIN_SANDBOX` · 맡기기 모델 표가 Codex 모델 이름을 준 자리면 `CC_BG_CODEX_MODEL` · `CC_BG_CODEX_MODEL_DELEGATE` |
| **Codex 훅** | 설치 창에서 Codex 를 빼고 한 번 더 누르면 설치가 우리 훅만 걷는다(파이썬 3.11 이상이 있을 때 — 없으면 노란 줄로 알리고 남긴다). 뒤에 사람 항목이 남으면 그 자리를 지키느라 빈 항목(`{ hooks = [] }`)을 두고, 적어 둔 신뢰(`[hooks.state]` 의 우리 훅 열쇠)는 둔다 — 남아도 해가 없다. 손으로는 `~/.codex/config.toml` 의 `[hooks]` 안에서 `drm-guide.py` · `codex-context-alert.py` · `codex-image-gate.py` · `codex-safety-hooks.py` 를 가리키는 UserPromptSubmit · PreToolUse · PostToolUse 항목과 그 빈 항목을 지운다. 다른 Codex 설정과 사람이 넣은 훅은 둔다 |
| **Codex · 안티그래비티 회사 설정** | `~/.codex/config.toml` · `~/.gemini/antigravity-cli/settings.json`. Codex 는 회사 틀이 든 자리만 지우면 된다 — 맞추기 전 것은 `config.toml.before-pgpt-<시각>` 에 있다. 안티그래비티 것은 `modelProvider` 줄만 지우면 로그인 갈래로 돌아간다 |
| **옛 판이 깐 Gemini CLI** — 옛 판에서 Gemini 칸을 켰던 PC | 이 설치는 깔지도 걷지도 않는다 — 안 쓰면 손으로 지운다: `npm uninstall -g @google/gemini-cli` · VS Code 확장 「Gemini CLI Companion」 · `~/.gemini/settings.json`. 같은 폴더의 `~/.gemini/antigravity-cli/` · `~/.gemini/config/` 는 안티그래비티 것이라 둔다 |
| **사용자 PATH 의 npm 전역 자리 · pip 사용자 자리 줄** — `%APPDATA%\npm` · `%APPDATA%\Python\Python<판>\Scripts`(펴진 경로 `C:\Users\<이름>\AppData\Roaming\…` 으로 적힌다) | 설치가 걷지 않는다 — 같은 자리를 Node · Python 설치나 사람이 넣었을 수 있어 누가 넣었는지 못 가른다. npm · pip 로 깐 명령을 남기면(아래 「남겨도 된다」) 이 줄도 둔다. 지우려면 시작 메뉴에 「환경 변수」로 검색 → 「계정의 환경 변수 편집」 → `Path` → 그 줄을 지우고 창을 새로 연다. 그 폴더가 남아 있으면 설치를 다시 누를 때(로그온 자동 실행도) 다시 더한다 |
| **바탕화면·시작 메뉴의 「PAI Setup Wizard」** | 바로가기를 지운다 |
| **로그온 · 밤마다 도는 자동 실행** — 작업 이름은 `PAISetup-AutoRun` · `PAISetup-AutoRun-Night` | 「작업 스케줄러」를 열어 두 이름을 지운다. 명령으로는 `Unregister-ScheduledTask -TaskName PAISetup-AutoRun,PAISetup-AutoRun-Night -Confirm:$false`. **폴더보다 이것을 먼저 지운다** — 짐을 먼저 지우면 작업만 남아 로그인 · 밤마다 헛돈다 |
| **펴 둔 짐** — 판마다 폴더가 하나씩 쌓인다(로그온 자동 실행을 켰으면 최근 셋만 남는다) | `%LOCALAPPDATA%\Claude Code Setup\` 를 통째로 지운다 (자동 실행이 쓰던 `autorun.ps1` · `autorun-gate.ps1` · `autorun.args` · `.autorun-site` · `.autorun-night.env` · `.autorun-last` · `install.env` 사본과 설치 기록 폴더도 그 안이다) |

프로그램(VS Code · Node · Git · Python · GitHub CLI · 고른 도구의 CLI · 데스크탑 앱)은 **남겨도 된다** — 회사와 무관한 것들이고,
지우려면 윈도우의 「앱」 화면이나 `winget uninstall` 이 든다. **VC++ 런타임은 지우지 않는다** — 그 PC 의 다른 프로그램도 같은 런타임을 쓴다.

⚠ **사내에서 쓰던 기계를 사외에서 다시 누르면 위 표의 사내 값은 설치가 걷어 낸다** — 게이트웨이
주소 · 키 · 사내 전용 값(환경변수와 홈 설정 양쪽)과 프록시 감시 작업 · 그 폴더. 옛 값이 남아 새 값을
가리는 것은 값이 없는 것보다 나쁘기 때문이다.
다만 우리가 넣은 값이라는 근거가 설 때만 지우고, 모르는 값은 알리기만 한다. 그렇게 가릴 수 없는
경우(회사를 아주 떠날 때)를 위해 위 표를 둔다.

## 새 판이 나오면

모델 이름이 바뀌거나 게이트웨이가 옮겨지면 **깔린 것이 낡는다.** 로그온 자동 실행 칸을 켰으면
로그인할 때 새 판을 받아 저절로 따라간다. 안 켰으면 바탕화면의 「PAI Setup Wizard」 를 누른다 —
새 판이 있는지 봐 주고, 있으면 그 자리에서 받는다. 새 `Setup.exe` 를 릴리스에서 받아 눌러도 같다.
**여러 번 눌러도 안전하다** — 이미 맞는 것은 안 건드리고 달라진 것만 고친다.

지금 든 판 번호는 설치 창 제목줄에 뜬다. 판마다 무엇이 바뀌었는지는 릴리스 쪽에 적혀 있다.

## 문의

이 설치본을 낸 사람에게. 설치 화면을 **통째로 복사해서** 보내면 빠르다 — 어느 칸에서
멈췄는지가 거기 다 찍힌다. 창이 아직 떠 있으면 단추 왼쪽의 「설치기록」이 보낼
파일을 집어 주고, 창을 닫았으면 위 「안 될 때」의 기록 파일을 보낸다.

## 쓰임 제한

**포스코 사람용이다.** 회사 키·프록시·회사 설정은 게이트웨이가 닿는 사내에서만 뜻이 있고,
사외에서는 그것들을 안 세우고 구독이나 개인 계정 로그인으로 쓴다. 키는 사람마다 제 것이고, 받는 짐에는
안 들어 있다.
