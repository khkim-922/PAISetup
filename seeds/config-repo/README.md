# 설정 저장소 씨앗

**제 설정 저장소를 만들 때 복사해서 출발하는 골든이다** — 설치가 넘겨받을 자리 한 벌. 여기
든 것은 **원저자가 세 PC 에서 실제로 돌리는 파일 그대로**이고, 개인 값만 견본으로 갈렸다.
배포되지도 임포트되지도 않는다. 복사한 순간부터 그 저장소의 것이다.

⚠ **대부분은 이것이 필요 없다.** 설치 창의 「설정 저장소」 칸은 **비우는 것이 기본이고 맞는
답이다** — 프로그램·확장·키·사내 문서·게이트웨이 씨앗은 그 칸과 무관하게 다 깔린다. 이 씨앗이
드는 자리는 **여러 PC 를 쓰면서 제 설정을 저장소 하나로 들고 다니려는 사람**뿐이다.

## 왜 씨앗인가

설치는 마지막 칸에서 **파일 이름 하나**로 갈린다 — 받아온 저장소 뿌리의 `bootstrap-vdi.sh`.
**그 이름이 없어도 실패가 아니다**: 설치는 저장소를 `~/repos/<이름>` 에 받아 두고 끝낸다.
저장소만 들고 다니려면 그것으로 충분하고, 이 씨앗은 필요 없다.

**이 씨앗이 드는 자리는 그 뒤다** — 받은 뒤에 손이 저절로 가게 하려는 사람. 그런데 맨바닥에서
짜면 이미 값을 치른 함정을 처음부터 다시 겪는다: 창이 PATH 를 못 물려받는다는 것 · 윈도우가
깔아 둔 파이썬 껍데기가 「있음」을 낸다는 것 · 마지막 `echo` 로 끝내면 판정이 늘 0 이 된다는
것 · 홈 설정을 그냥 덮으면 심긴 훅이 조용히 사라진다는 것 · 자리가 갈릴 때 저쪽 환경변수를
**지우지 않으면** 설정은 맞아 보이는데 안 닿는다는 것. 그 함정들이 곁말에 「왜」와 함께 박혀
있고, **그것이 이 씨앗의 값이다.**

## 무엇이 들어 있나

| 파일 | 무엇인가 |
|---|---|
| `bootstrap-vdi.sh` | **익명 몸통.** 설치가 마지막에 부른다. 일곱 칸을 돈다 |
| `bootstrap.conf` | **당신 값** — git 신원 · 저장소 목록 · 받을 주소 꼴 · 재 볼 도구 |
| `deploy.ps1` | 저장소의 규범·룰·스킬·훅을 **홈과 형제 저장소로 뿌리는 자** |
| `deploy.repofiles.conf` | 저장소마다 한 벌씩 둘 파일 목록 — 뿌리는 자와 재는 자가 같이 읽는다 |
| `deploy.targets.d/` | **어느 PC 의 어디로 뿌리나.** 파일 하나가 PC 하나다 (견본 한 장) |
| `mcp-servers.json` | MCP 서버 선언. **키는 안 든다** — 환경변수 이름만 든다 |
| `vdi-home-settings.json` | 홈 `~/.claude/settings.json` 의 씨앗 |
| `.claude/hooks/session-start.sh` | 세션이 열릴 때 도구를 재고 갖추는 훅 |
| `.claude/hooks/utf8-bom.sh` | 편집 뒤 인코딩을 지키는 훅 |
| `.claude/settings.json` | 위 훅 둘을 **거는** 자리 |
| `.claude/tools.global.conf` | 전역 도구 선언 — 훅이 이것을 읽고 돈다 |
| `.claude/get-browser.sh` | 브라우저를 받아 오는 **뒷길**. 도구 선언의 `browsers-fallback` 이 저장소 기준 경로로 가리킨다 |
| `.githooks/pre-commit` · `commit-msg` | **커밋 게이트 몸통.** 익명이다 — 무엇을 재는지 모른다 |
| `.githooks/gates-run.sh` | 몸통 둘이 같이 쓰는 러너. 선언을 읽어 조각을 부른다 |
| `.githooks/gates.d/` | **검사 조각** 다섯 — 인코딩 · 마크다운 · 링크 · 결정 색인 · 커밋 형식 |
| `.githooks/claude-config-path.sh` | 설정 저장소가 이 기계 어디 붙었나를 **한 자리에서** 잰다 |
| `.claude/markdownlint.global.jsonc` | 우리 글 문체가 낳는 마크다운 오탐 |
| `.claude/commitlint.global.mjs` | 같은 축 — 커밋 제목 문체가 낳는 오탐 |
| `bootstrap-flow.svg` | **그림** — 몸통이 도는 일곱 칸을 위에서 아래로 |
| `session-start-flow.svg` | **그림** — 세션을 열면 무엇이 저절로 도나 |
| `deploy-flow.svg` | **그림** — 돌리면 무엇이 어디로 가나 |

⚠ **키를 든 파일은 여기 없다.** 원저자 저장소는 `secrets.env` · `secrets.d/<자리>.env` 로 값을
들지만 그건 나갈 것이 아니다. 없으면 몸통이 「자리를 못 정했다」로 말하고 **그 칸만 건너뛴다** —
지고 끝나지 않는다. 필요해지면 그때 만든다(꼴은 몸통 5·6 칸 곁말이 든다).

## 먼저 그림 셋을 연다

**코드를 읽기 전에 그림부터 본다.** 세 파일이 각각 무슨 일을 어떤 순서로 하는지 한 장씩
그려 뒀다 — 더블클릭하면 브라우저가 열고, 밖으로 나가는 주소가 한 자도 없어 사내망에서도 뜬다.

| 그림 | 무엇이 보이나 |
|---|---|
| `bootstrap-flow.svg` | 열이 **사람 · 선언 · 몸통 · 딴 프로그램**. 내 손이 드는 자리가 처음과 로그인 **둘뿐**이라는 것이 색으로 보인다 |
| `session-start-flow.svg` | 열이 **세션 · 홈 · 훅 · 내 저장소 · 바깥**. 가운데 게이트에서 갈라져 **대개 침묵으로 끝나고**, 어긋난 세션만 설치 여섯을 돈다 |
| `deploy-flow.svg` | 열이 **자리**다 — 사람 · 설정 저장소 · 홈 · 형제 저장소 · 이 PC. 색 덩어리가 「어디서 어디로」를 그대로 낸다 |

칸마다 붉은 `⚠` 줄이 붙은 것이 있다. **그것이 이 씨앗의 값이다** — 다 실측으로 얻은 함정이고,
그 자리를 모르면 제 PC 에서 같은 사고를 다시 겪는다.

⚠ **그림은 생성물이라 손으로 고치지 않는다.** 고칠 자리는 원저자 저장소의 재료
(`docs/<이름>.steps.json`)이고, 이 폴더에 든 것은 구운 것 한 장씩이다 — 여기에는 그리는 자가
같이 오지 않는다(8.1MB 라 zip 만 무거워진다).

## 출발하는 법

1. **저장소를 하나 만든다** — 이름은 아무래도 된다. 비공개를 권한다
2. **이 폴더를 그 뿌리에 통째로 복사한다.** ⚠ **`.claude/` 는 숨은 폴더라 그냥 끌면 빠진다** —
   `cp -r seeds/config-repo/. <새 저장소>/` 처럼 **점까지** 담아 복사한다. 빠뜨리면 훅이
   안 걸리고, 그 부재는 세션을 열어 봐야 드러난다
3. **`bootstrap.conf` 를 고친다** — git 이름·메일, 들고 다닐 저장소 목록, 받을 주소 꼴
4. **`deploy.targets.d/example-pc.conf` 를 제 PC 것으로 고치고 이름을 바꾼다.** 그리고 견본은
   지운다 — 안 지워도 없는 경로는 조용히 건너뛰지만, 남으면 어느 쪽이 제 것인지 매번 다시 읽게 된다
5. **몸통과 `deploy.ps1` 은 안 고친다** — 값을 몸통에 박으면 그 파일이 당신 것이 되어, 다음에
   upstream 을 당길 때 그 자리에서 문다. 고칠 자리는 늘 선언이다
6. **커밋하고 올린다**
7. **설치 창의 「설정 저장소」 칸에 그 주소를 넣고** [설치 시작] 을 누른다

받아 가는 자리는 `~/repos/<저장소 이름>` 이다. 설치가 clone 한 뒤 Git Bash 로 몸통을 부른다.

## 커밋 게이트를 켜는 법

게이트는 **몸통 + 조각 + 선언** 셋으로 갈려 있다. 몸통과 조각은 여기 실려 있고 어느 저장소에
가도 같다 — **갈리는 것은 선언 하나뿐이다.**

저장소마다 `.githooks/gates.conf` 를 두고 켤 것을 적는다. 이 파일은 **배포가 안 건드린다** —
저장소가 커밋하는 것이라, 당신이 고른 판이 다음 배포에 덮이지 않는다.

```ini
[pre-commit]
encoding      # .ps1 에 BOM 이 있나 · .cmd 에 없나 — 남의 PC 에서만 깨지는 자리
markdown      # 담긴 .md 만 잰다
links         # 깨진 링크·앵커 (--offline)
adr-index     # 결정 목록이 결정 기록의 머리말과 어긋났나

[commit-msg]
commit-format # Conventional Commits + 제목 BOM
```

- **파일이 없으면 아무것도 안 잰다** — 게이트를 아직 안 켠 저장소도 정당하다. 다만 훅이
  「선언이 없다」고 한 줄 말하고 지나간다: 있다고 믿은 채 없는 것이 제일 나쁘다
- **선언에 있는데 조각이 없으면 커밋을 막는다** — 배포가 안 닿은 자리다. 조용히 건너뛰면
  그 저장소는 게이트가 도는 줄 알면서 아무것도 안 재게 된다
- **도구가 없는 검사는 그것만 건너뛴다** — 다만 「못 쟀다」를 판정 옆에 찍는다. 「전부 통과」는
  *여기까지* 통과인데 안 적으면 전부로 읽힌다
- 알면서 통과시켜야 할 때는 `git commit --no-verify`

⚠ **훅이 걸리려면 `core.hooksPath` 가 서야 한다** — `.git/hooks/` 는 clone 을 안 따라온다.
`deploy.ps1` 과 세션 훅이 `.githooks/` 를 든 저장소에 자동으로 건다. 손으로 걸려면:

```bash
git config core.hooksPath .githooks
```

⚠ **`node_modules/` 를 무시 목록에 넣는다 — node 축을 안 지는 저장소도 그렇다.** 커밋 형식
검사의 규칙 파일(`extends`)이 **저장소 기준으로** 풀려서, 전역 설치만으로는 안 선다. 그래서
세션 훅이 전역 패키지를 저장소 안으로 링크하고(도구 선언의 `wiring = node-link`) 그 폴더가
실제로 생긴다. **그 안은 전역 설치를 가리키는 심링크라 커밋하면 남의 기계에서 깨진다.**

⚠ **제외 목록은 조각에 안 적는다.** 어디를 빼나는 저장소마다 다르므로 그 도구의 표준 자리가
든다 — 마크다운은 `.markdownlint-cli2.jsonc` 의 `ignores`, 링크는 `lychee.toml` 의
`exclude_path`. 조각에 적으면 저장소마다 조각이 갈리고, 그 순간 손사본이 된다.

## 손으로도 재 본다

설치를 안 거치고 그 자리에서 돌려도 된다 — 여러 번 돌려도 안전하다.

```bash
bash ~/repos/<저장소 이름>/bootstrap-vdi.sh; echo "종료코드 $?"
```

**종료코드가 눈금이다.** 화면의 마지막 줄만 보지 않는다 — 안내는 다 찍히고 판정은 코드로 난다.

| 코드 | 뜻 |
|---|---|
| `0` | 섰다. **안 선 것이 있으면 그 이름을 판정 옆에 같이 찍는다** — 안 닿는 런타임 · 안 된 로그인 |
| `1` | git 신원 · 저장소 · 배포에서 졌다. 위쪽 `!` 줄이 어느 칸인지 댄다 |

⚠ **경계와 실패는 다르다.** 런타임을 깔 자는 `install.ps1` 이고 로그인을 누를 자는 사람이라,
둘 다 이 몸통이 질 일이 아니어서 `0` 으로 끝난다 — 대신 **판정 옆에 이름을 찍어** 「됐다」가
「전부 됐다」로 읽히지 않게 한다.

## 몸통이 도는 일곱 칸

| 칸 | 무엇을 하나 |
|---|---|
| 1 git 전역 설정 | 신원 · 줄끝 · 긴 경로 · 자격 관리자. **빈 값은 안 심는다** |
| 2 저장소 | 선언의 목록을 clone·pull. 진 것은 판정에 담긴다 |
| 3 런타임 확인 | PATH 배선 뒤 **불러 본다.** 안 닿아도 안 멈추고 끝에서 이름을 댄다 |
| 4 슬러그 폴더 | 배포가 메모리를 넣을 자리를 미리 만든다. **접두사까지 파생한다** |
| 5 자리 · 홈 설정 | 사내·사외를 **이름이 아니라 닿음으로** 가르고, 홈 설정을 깐다 |
| 6 키 | 자리 파일의 이름들을 심고, **저쪽 자리 것은 지운다** |
| 7 deploy | `deploy.ps1` 을 부르고 **종료코드를 잰다** |

4·5·6 칸은 **원저자 저장소에 값이 있을 때만 실제로 일한다** — 없으면 그 칸이 「못 정했다」로
말하고 넘어간다. 그래도 몸통에 남겨 둔 까닭은 **그 안의 곁말이 함정 지도**라서다: 필요해진
날에 맨바닥에서 다시 겪지 않게.

로그인 칸이 특히 미묘해서 규율을 그대로 담았다. **재고 나서 세운다**(안 그러면 이미 선 PC 에서도
매번 떠서 사람이 그 칸을 넘겨 읽기 시작한다) · **tty 가 없어도 띄운다**(끝내는 것은 stdin 이
아니라 브라우저 콜백이다) · **띄우고 다시 재서 말한다**(안 재고 「떴다」로 끝내면 안 누른 기계가
성공으로 보고된다) · **시간을 끊는다**(안 누르는 것도 정당한 선택이다).

⚠ **토큰을 저장소에 두지 않는다.** 장기 토큰이면 손이 아예 안 가지만 그것은 돌고(만료·회전),
커밋해 두면 낡은 뒤에도 「설정된 것처럼 보인다」 — 부재보다 나쁘다. 데스크탑 앱을 쓰는 PC 는
이 칸이 대개 안 걸린다: 앱 로그인이 CLI 까지 세운다(둘이 `~/.claude` 를 같이 쓴다).

**프로그램은 여기서 안 깐다.** 무엇을 깔지는 `install.ps1` 한 자리가 들고 이 몸통은 확인만
한다 — 목록을 둘로 두면 한쪽이 낡고, 그 어긋남은 낡은 쪽이 먼저 깔 때만 드러난다.

⚠ **자리 판정을 여기에 또 쓰지 않는다.** `install.ps1` 이 이미 재고 있어서, 여기서 다시 재면
같은 사실이 두 자리에 산다 — 한쪽만 고쳐지는 날 어느 쪽이 맞는지 아무도 모른다.

## 왜 몸통을 고치지 말라고 하나

이 씨앗의 몸통은 **손으로 옮겨 적은 사본이 아니라 원저자 진본에서 굽힌 것이다.** 전에는
손으로 다시 지었는데, 그때 **몸통이 둘이 되어** 진본에서 고친 사고가 이쪽으로 안 왔다 —
407 줄을 다시 쓰면서 실제로 지운 개인 정보는 7 줄이었다. 그래서 지금은 진본 한 자리만
고치면 이 씨앗도 같이 고쳐진다.

같은 까닭으로 **당신도 몸통을 고치지 않는 쪽이 낫다.** 값은 선언에 있고, 선언만 당신 것이면
upstream 이 고친 함정이 당신에게도 온다.

## 선언에 무엇이 사나

몸통은 **이름을 모른다** — 옆 `bootstrap.conf` 에 묻는다. 그래서 저장소가 늘 때도 도구가 늘
때도 고칠 자리가 선언 하나다. 무엇이 있나는 그 파일이 주석과 함께 든다 — **여기 목록을 두면
사본이 하나 더 늘고, 늘어난 사본은 조용히 낡는다.**

⚠ 파서는 순정 `sh` 라 문법이 단순한 만큼 관대하지 않다 — **이름 오타는 조용히 빈 값이 된다.**
마지막 그물은 종료코드다: 빠뜨린 것이 git 신원이면 `1` 로 진다.

⚠ **이 저장소 안의 자리는 선언에 안 든다** — 몸통이 `$HERE`(제가 사는 폴더)로 파생한다.
그래서 저장소 이름을 무엇으로 짓든, 나중에 바꾸든 안 깨진다.
