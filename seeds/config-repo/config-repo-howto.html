설치 창의 「내 저장소 받기」

설정 저장소 만드는 법

내 규범 · 룰 · 스킬 · 에이전트 · 메모리 · 홈 설정 · 키를 비공개 git 저장소 하나에 담아 두는 방법입니다. 설치 창에 그 주소를 넣으면 어느 PC · VDI 에서든 설치 한 번으로 같은 환경이 서고, 비워 두면 제작자의 세트가 깔립니다.

넣으면 달라지는 것담는 것만들기설치 창에 잇기지킬 것
이름표 읽는 법항목마다 붙은 종류 · 받는 도구 표시의 뜻 — 표시에 마우스를 올려도 뜹니다

넣으면 달라지는 것

「내 저장소 받기」는 비워 두는 것이 기본입니다. 프로그램 · 확장 · CLI · 회사 키 · 사내 문서는 이 칸과 상관없이 다 깔리고, 달라지는 것은 규범 · 룰 · 스킬을 누구 것으로 받느냐입니다.

비워 두면 — 제작자의 세트
  • 설치 묶음에 든 제작자의 규범 · 룰 · 스킬이 깔립니다.
  • 「자세히 설정」의 「규범 · 룰 · 스킬을 받을 모델」 칸에 「설정 저장소를 넣지 않았으니, 고른 모델에 제작자의 규범 · 룰 · 스킬이 깔립니다」가 뜹니다.
  • 따로 할 일이 없습니다. PC 를 하나만 쓴다면 대개 여기서 끝입니다.
주소를 넣으면 — 내 세트
  • 설치 끝에 저장소를 받고, 그 안의 세션 훅이 git 이름 · 함께 쓰는 저장소 · 키 · 홈 설정을 맞춥니다.
  • 이어서 저장소의 deploy.ps1 이 내 규범 · 룰 · 스킬 · 에이전트 · 메모리를 놓습니다. 내 저장소에 없는 것은 제작자의 것이 채웁니다.
  • 같은 칸의 글이 「설정 저장소를 넣었으니, 고른 모델에 내 규범 · 룰 · 스킬(claude-config)이 깔립니다」로 바뀝니다.

어느 모델이 받느냐는 두 경우 모두 「규범 · 룰 · 스킬을 받을 모델」 칸이 정합니다. 저장소를 넣어도 그 칸에서 끈 모델에는 내 것도 제작자 것도 가지 않습니다. 처음에는 Claude 만 켜져 있습니다.

설정 저장소가 아닌 저장소(코드 · 문서 저장소)를 넣어도 됩니다 — 그때는 C:\Users\<내 이름>\repos\<저장소 이름> 에 받아 두기만 합니다. 여러 개면 주소 사이를 빈칸으로 띄웁니다.

담는 것

견본을 복사하면 돌아가는 데 필요한 파일은 이미 다 들어 있습니다. 내 것은 아래 자리에 파일을 두는 만큼 늘어나고, 자리가 비어 있는 항목은 제작자의 것이 갑니다. 왼쪽 칸의 회색 글씨가 저장소 안의 자리입니다.

규범.claude/CLAUDE.global.mdNormClaudeCodexagy
모든 세션에 늘 읽히는 원칙 한 편입니다. 도구마다 제 규범 파일(Claude 는 CLAUDE.md, Codex · agy 는 AGENTS.md)이 이것을 읽어 옵니다.
룰.claude/rules.global/*.mdRuleClaudeCodexagy
정해진 파일을 만질 때만 걸리는 규칙입니다. 어느 파일에 걸리는지는 룰 파일 머리말에 적습니다.
스킬.claude/skills/<이름>/SkillClaudeCodexagy
그 일을 말하면 불러 쓰는 절차입니다. 폴더 하나가 스킬 하나이고, 스킬은 하나씩 따로 이깁니다 — 같은 이름이면 내 것이, 내게 없는 이름은 제작자의 것이 갑니다.
에이전트agents/*.mdAgentClaude
일을 나눠 맡길 서브에이전트의 정의입니다. 설치 묶음에는 없어 내 저장소가 들 때만 섭니다. 저장소 뿌리의 agents/ 이고, .claude/agents/ 가 아닙니다.
공용 메모리memory/global/MEMORY.mdMemoryClaude
어느 프로젝트에도 안 매인 교훈의 목차입니다. 모든 Claude 세션에 함께 실립니다. 설치 묶음에는 없습니다.
프로젝트 메모리memory/<저장소 이름>/*.mdMemoryClaude
그 저장소를 열었을 때만 읽히는 메모리입니다. personal.conf 의 REPOS 에 적은 저장소와 이 설정 저장소 자신이 대상입니다.
git 이름 · 함께 쓰는 저장소personal.confSettingPC 전체
커밋에 박히는 이름 · 메일과, 이 PC 의 repos 아래에 같이 받아 둘 저장소 목록입니다. 설치 때 없는 저장소만 받고, 이미 있으면 건너뜁니다. 만들기의 3번이 칸을 하나씩 풉니다.
개인 키secrets.envSettingPC 전체
GitHub 토큰 같은 키를 이름=값 한 줄씩 적으면 사용자 환경변수로 심습니다 — PC 마다 다시 칠 일이 없습니다. 값이 같으면 건너뛰고, 빈 값은 심지 않습니다. 견본에는 이 파일이 없어 필요할 때 만듭니다.
홈 설정vdi-home-settings.jsonvdi-home-settings.private.jsonSettingClaude
Claude Code 의 홈 설정(~/.claude/settings.json)에 얹을 것입니다. 설치가 홈 설정을 먼저 만들어 두므로 보통은 통째로 덮지 않고, .private.json 의 허용 규칙(permissions.allow) 가운데 홈에 없는 줄만 더합니다. 덮는 경우는 아래 「홈 설정은 언제 덮이나」가 적습니다.
Claude 훅.claude/hooks/HookClaude
견본에 이미 든 세션 훅과 안전 훅(그림 크기 재기 · 셸 실수 막기 같은 것)입니다. 고치지 않고 둡니다 — 이 폴더가 있으면 통째로 내 저장소의 것이 가서, 견본이 새 판이 되면 내가 올려 줘야 합니다(견본 새 판으로 올리는 법).
제작자 것에서 출발하려면이 PC 에 깔린 제작자의 규범 · 룰 · 스킬을 복사해 와 고칩니다

설치는 제작자의 세트를 C:\Users\<내 이름>\.paisetup\standard\ 에 모아 둡니다. 거기서 복사해 와 내 저장소의 자리에 두면 그때부터 내 것입니다.

무엇가져올 곳둘 곳
규범~/.paisetup/standard/norms/norms.md.claude/CLAUDE.global.md
룰~/.paisetup/standard/norms/rules/.claude/rules.global/
스킬 하나~/.paisetup/standard/skills/<이름>/.claude/skills/<이름>/

복사한 것은 내 파일이 되어, 제작자가 그 파일을 고쳐도 따라오지 않습니다. 규범 · 룰은 항목째 이기니 룰을 한 파일만 둬도 제작자의 룰은 더 오지 않습니다 — 제작자 룰을 같이 쓰려면 폴더째 가져옵니다. 스킬은 고칠 것만 가져오면 나머지는 제작자 것이 그대로 갑니다.

홈 설정은 언제 덮이나더하기는 어디서나, 통째로 덮기는 자리 파일이 정한 PC 에서만
  • 더하기 — vdi-home-settings.private.json 을 두면 그 permissions.allow 줄 가운데 홈에 없는 것만 더합니다. 다른 키는 읽지도 쓰지도 않고, 더할 줄이 없으면 파일을 건드리지 않습니다.
  • 덮기 — 홈 설정이 아직 없는 PC 이거나, 자리 파일(secrets.d/<자리>.env)이 #home-settings = overwrite 를 든 PC 에서만 vdi-home-settings.json 으로 홈 설정을 갑니다. 그때도 설치가 심은 훅 · env 값은 지키고, 덮기 전 판은 곁에 settings.json.bak-<시각> 으로 남깁니다.
  • 자리 파일은 그 자리를 알아보는 줄(#site-probe = 호스트:포트 · #site-path = 폴더 · #site-default = yes)과 함께 둡니다. 셋 가운데 망이 답한 자리가 가장 셉니다.
  • Python 을 못 부르면 있는 홈 설정을 덮지 않고 그 까닭을 한 줄로 말합니다 — 설치가 심은 훅을 지킬 수 없어서입니다.

만들기

맨바닥에서 짜지 않습니다. 설치가 모든 PC 에 견본을 깔아 둡니다 — C:\Users\<내 이름>\.claude\seeds\config-repo\. 이것을 복사해 내 값만 적으면 됩니다. 명령은 Git Bash 에서 칩니다.

  1. GitHub 에 비공개 저장소를 만듭니다 — 이름은 claude-config 다른 저장소를 연 세션과 커밋 검사가 옆자리에서 이 이름으로 설정 저장소를 찾습니다. 이름이 다르면 설치는 되지만, 다른 저장소에서는 견본으로 대신 돕니다. 키가 들어가니 반드시 비공개(Private)로 만듭니다.
  2. 내 PC 로 받고, 견본을 통째로 복사합니다 숨김 폴더 .claude · .githooks 까지 같이 가야 합니다 — 탐색기로 끌면 빠지기 쉬워 명령으로 합니다. memory 폴더는 비어 있어도 지우지 않습니다. 
    git clone https://github.com/<내 아이디>/claude-config.git ~/repos/claude-config
cp -r ~/.claude/seeds/config-repo/. ~/repos/claude-config/
  3. personal.conf 에 내 값을 적습니다 줄마다 위에 설명 주석이 있습니다. 형식은 이름=값 이고 값에 따옴표를 두르지 않습니다. 칸 이름에 오타가 나면 그 값은 조용히 빕니다.
    칸무엇적는 법
    GIT_NAME커밋에 박히는 이름보통 GitHub 아이디
    GIT_EMAIL커밋에 박히는 메일GitHub 의 noreply 메일을 권합니다 — GitHub → Settings → Emails 에 있습니다
    REPOS같이 받아 둘 저장소 이름들빈칸으로 띄웁니다. 없으면 비워 둡니다
    REPO_URL그 저장소들을 받을 주소아이디만 내 것으로 바꾸고 <이름> 은 그대로 둡니다 — REPOS 의 이름이 하나씩 그 자리에 들어갑니다
    ROOT받아 둘 자리그대로 둡니다($HOME/repos) — 설치가 받는 자리와 같아야 합니다
  4. 키가 있으면 secrets.env 를 만듭니다없으면 건너뜀 저장소 뿌리에 한 줄에 하나씩 적습니다. # 으로 시작하는 줄은 주석입니다. 
    GH_TOKEN=<내 토큰>
  5. 내 규범 · 룰 · 스킬 · 에이전트 · 메모리를 둡니다나중에 해도 됨 담는 것의 자리에 둡니다. 비워 두면 그 항목은 제작자의 것이 갑니다.
  6. 무시 목록을 두고, 커밋해 올립니다 세션 훅이 저장소 안에 이 PC 의 상태 파일과 링크 폴더를 만들어서, 무시 목록이 없으면 다음 커밋에 함께 들어갑니다. git 이 이름을 물으면 personal.conf 에 적은 값으로 git config --global user.name · user.email 을 한 번 칩니다 — 다음부터는 설치가 맞춥니다. 
    cd ~/repos/claude-config
printf 'node_modules/\n.claude/install-*\n.claude/settings.local.json\n' > .gitignore
git add -A
git commit -m "chore: 설정 저장소 시작"
git push
  7. 설치 창에 주소를 넣고 설치합니다 다음 절 설치 창에 잇기가 적습니다. 새 PC 에서는 이 걸음 하나만 하면 됩니다.

설치 창에 잇기

새 PC 나 비워진 VDI 에서는 이것만 하면 됩니다. 넣은 주소는 기억되어 다음 설치 창과 로그온 자동 실행이 그대로 씁니다.

  • 「연결」 칸의 「내 저장소 받기」 입력란에 저장소 주소를 붙여 넣습니다 — https://github.com/<내 아이디>/claude-config. 이 장을 연 「설정저장소 만드는 법」과 「받는자리」가 그 입력란 바로 아래 오른쪽에 있습니다.
  • 「자세히 설정」을 펴서 「규범 · 룰 · 스킬을 받을 모델」에서 내 세트를 받을 모델을 고릅니다. 그 칸에 「설정 저장소를 넣었으니, 고른 모델에 내 규범 · 룰 · 스킬(claude-config)이 깔립니다」가 뜨고, 접어 두어도 머리의 한 줄이 「규범: Claude ← 내 저장소」로 바뀝니다(비워 두면 「규범: Claude ← 제작자」).
  • [설치 시작]을 누릅니다.

설치가 그 뒤에 하는 일

설치 기록의 「설정 저장소」 걸음에서 차례로 일어납니다.

받기→세션 훅→deploy.ps1→고른 모델의 홈
받기Installer
C:\Users\<내 이름>\repos\claude-config 에 받습니다 — 설치 창의 「받는자리」가 그 폴더를 엽니다. 이미 받아 둔 PC 면 새 커밋을 당겨 옵니다. GitHub CLI 로그인이 안 돼 있으면 받기 직전에 일회용 코드 창이 뜹니다 — [브라우저 열기]를 누르고 그 코드를 넣으면 스스로 닫힙니다.
세션 훅session-start.sh --installHook
받은 저장소 뿌리의 이 파일을 부릅니다. personal.conf 대로 git 이름 · 메일과 기본 설정을 맞추고, REPOS 가운데 없는 저장소를 받고, secrets.env 의 키를 사용자 환경변수로 심고, 홈 설정을 맞춥니다.
배포deploy.ps1 -YesInstaller
세션 훅이 이어서 부릅니다. 함께 쓰는 저장소를 원격에 맞춰 당기고(main 에서 빨리감기로만), 저장소마다 세션 훅 · 커밋 검사 입구를 한 벌씩 놓고, 내 규범 · 룰 · 스킬 · 에이전트 · 메모리를 고른 모델의 홈에 놓습니다.
끝의 한 줄
설치 끝 점검 아래에 「규범 · 룰 · 스킬 — 내 저장소(claude-config)의 훅에 넘겼다 — …」가 뜨면 내 세트가 간 것입니다. 훅이 졌거나 넘길 훅이 없었으면 같은 자리에 「설치 묶음의 제작자 세트」가 놓였다고 말합니다.
git 에 거는 설정이 PC 의 git 전역 설정을 바꿉니다 — 이미 다른 값이 있었으면 이 값이 됩니다
  • user.name · user.email — personal.conf 의 값. 둘 중 하나라도 비어 있으면 안 심고 그 칸 이름을 댑니다
  • init.defaultBranch main · core.autocrlf input · core.longpaths true · credential.helper manager · pull.rebase false

설정 저장소를 연 세션에서도 다시 맞춥니다. 다른 git 이름 · 메일을 쓰려면 personal.conf 를 고칩니다.

고친 것은 언제 들어오나

저장소에 고쳐 올리면, 다른 PC 에는 아래 가운데 먼저 오는 때에 들어갑니다.

로그온할 때PAISetup-AutoRunTask
자동 실행을 켜 둔 PC 는 하루 한 번 로그온 뒤 같은 설치를 다시 돌며, 저장소를 당기고 세션 훅을 다시 부릅니다. 새 키 · 새 규범 · REPOS 에 더한 저장소가 이때 들어옵니다 — 저장소를 새로 받는 일은 세션이 아니라 설치 때 합니다.
설정 저장소를 연 세션
Claude Code 로 설정 저장소를 열면 세션을 열 때마다 뒤에서 당겨 오고, 홈의 규범 · 룰 · 스킬을 다시 놓습니다. 당기기가 뒤에서 돌아서 방금 당긴 것은 그다음 세션부터 실립니다. 바뀐 키 · git 이름도 이때 맞춥니다.
다른 저장소만 연 세션
홈에 놓인 것이 설정 저장소와 다르면 한 줄로 알리기만 합니다. 설정 저장소를 한 번 열면 다음 세션부터 맞춰집니다.
지금 바로
설정 저장소 폴더에서 당긴 뒤 세션 훅을 손으로 부릅니다. 종료코드 0 이면 섰고, 1 이면 위쪽의 ❌ 줄이 안 선 자리를 댑니다 — 화면 마지막 줄이 아니라 종료코드로 읽습니다. 
cd ~/repos/claude-config && git pull --ff-only
bash .claude/hooks/session-start.sh --install; echo "종료코드 $?"

지킬 것

설치와 세션 훅이 이렇게 움직이기 때문에 생긴 약속입니다. 어기면 대개 오류 없이 조용히 어긋납니다.

내 것이 이기고, 빈 자리는 제작자 것이 채웁니다 규범 · 룰 · 에이전트 · 메모리 · 훅은 항목째 이깁니다 — 룰 파일을 하나만 둬도 제작자의 룰은 더 오지 않습니다. 스킬만 하나씩 이깁니다.
받을 모델은 설치 창이 정합니다 저장소에는 그것을 적는 자리가 없습니다. 「규범 · 룰 · 스킬을 받을 모델」에서 고르고, 에이전트 · 공용 메모리는 그 칸의 Claude 를 켰을 때만 갑니다.
키는 secrets.env 한 곳에, 저장소는 비공개로 secrets.env 는 평문 그대로 커밋되어 저장소를 따라다닙니다. 저장소가 비공개인 것이 유일한 울타리라, 공개로 돌리면 키가 그대로 드러납니다. 다른 파일에는 키를 적지 않습니다.
값은 personal.conf 에, 스크립트는 그대로 견본에서 온 deploy.ps1 · .claude/hooks/ · .githooks/ · tool-homes.conf 는 고칠 일이 없습니다. tool-homes.conf 맨 끝의 stamp 줄도 그대로 둡니다.
이름은 claude-config, memory/ 는 남깁니다 세션 훅과 커밋 검사는 deploy.ps1 과 memory/ 를 함께 든 폴더를 설정 저장소로 알아봅니다. 하나라도 빠지면 개인 설정과 배포가 서지 않습니다.
견본이 새 판이 되면 직접 올립니다 설치는 내 설정 저장소를 고치지 않습니다. 옛 견본으로 만든 저장소면 설치 기록에 「이 저장소의 훅으로 넘기지 않는다」가 뜨고 그 훅을 부르지 않습니다 — 올리는 법.
세션 훅은 하나만 돕니다 주소를 여럿 넣으면 다 받되, 세션 훅을 든 저장소가 여럿이면 앞의 것 하나만 부릅니다. 설정 저장소 주소를 맨 앞에 둡니다.
그만 쓰려면 칸과 폴더를 함께 걷습니다 「내 저장소 받기」를 비우고 repos 의 그 폴더를 지우거나 옮긴 뒤 다시 설치하면 제작자 세트로 돌아갑니다. 칸만 비우고 폴더를 두면 내 것이 계속 이기고, 폴더만 지우면 다음 설치가 다시 받습니다.
견본 새 판으로 올리는 법홈의 견본을 덮어 복사하고, 내 값이 든 파일만 되돌립니다

설치본이 새 판으로 오르면 홈의 견본(~/.claude/seeds/config-repo/)도 새 판이 됩니다. 그것을 내 저장소에 덮어 복사한 뒤 personal.conf 를 되돌립니다. secrets.env 와 무시 목록은 견본에 없어 그대로 남습니다.

cd ~/repos/claude-config
cp -r ~/.claude/seeds/config-repo/. .
git checkout -- personal.conf
git status

git status 에 뜬 파일 가운데 내가 고쳤던 것(손댄 vdi-home-settings.json 같은 것)이 있으면 같은 git checkout -- <파일> 로 되돌립니다. 나머지는 견본의 새 판이니 그대로 커밋해 올리고, 설치를 한 번 더 누릅니다.

안 될 때설치 기록에 뜨는 줄로 어디가 막혔는지 가립니다

설치 기록은 설치 창 아래 띠 왼쪽 끝의 「설치기록」이 엽니다.

  • 「어느 뿌리에도 .claude\hooks\session-start.sh 가 없어 훅은 안 돌았다」 — 받기는 됐는데 훅 파일이 없습니다. 견본을 복사할 때 숨김 폴더가 빠졌는지 봅니다.
  • 「못 받았다 — 주소 · 계정 · 망을 본다」 — 주소에 오타가 있거나, 비공개 저장소를 읽을 수 있는 계정으로 로그인하지 않았거나, 망이 막혔습니다.
  • 「git 이 안 닿아 못 받는다」 — 개발 도구를 빼고 깐 PC 입니다. Setup.exe -DevTools 로 한 번 돌리면 git 이 깔립니다.
  • 「이 저장소의 훅으로 넘기지 않는다」 — 옛 견본으로 만든 저장소입니다. 위 견본 새 판으로 올리는 법대로 올립니다.
  • 「personal.conf 에 GIT_NAME · GIT_EMAIL 이 없다」 — 칸 이름에 오타가 났거나 값이 비었습니다.

파일 하나하나가 무엇인지는 견본 폴더의 README.md 가, 세션을 열 때와 배포할 때 무슨 일이 어떤 차례로 일어나는지는 같은 폴더의 그림 둘 (session-start-flow.svg · deploy-flow.svg)이 보여 줍니다. 더블클릭하면 브라우저가 엽니다.

이 장은 설치 묶음과 함께 오는 한 장입니다 — 설치 창의 「설정저장소 만드는 법」이 열고, 견본 폴더(.claude\seeds\config-repo\)에도 같은 것이 있습니다. 밖으로 나가는 주소가 없어 사내망에서도 열립니다.

어디에 무엇이 깔리는지는 설치 창 「규범 · 룰 · 스킬을 받을 모델」 칸의 글 끝 「?」가 여는 INSTALLED.md 가 자세히 적습니다.
