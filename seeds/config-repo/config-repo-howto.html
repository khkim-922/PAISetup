내 저장소 받기 · 설정 저장소 만들기

설치 창의 「내 저장소 받기」 칸이 하는 일과, 내 Claude Code 설정을 여러 PC 에 들고 다니는 법입니다.

대부분은 여기까지주소를 넣으면 받아 두고, 비워 두어도 설치는 다 됩니다. 1번만 읽으면 됩니다.
PC 가 여럿이면같은 설정을 어디서나 쓰고 싶을 때만 설정 저장소를 봅니다.

1이 칸은 무엇을 하나

git 저장소 주소를 넣으면, 설치의 마지막 걸음에서 그 저장소를 내 PC 에 받아 둡니다. 그게 전부입니다. 코드 저장소든 문서 저장소든 아무거나 됩니다.

저장소 주소 붙여 넣기→설치 마지막에 받기→C:\Users\<내 이름>\repos\<저장소 이름>
  • 여러 개면 주소 사이를 빈칸으로 띄웁니다.
  • 비워 두어도 됩니다. 프로그램 · 확장 · CLI · 회사 키는 이 칸과 상관없이 깔립니다.
  • GitHub 에 로그인하지 않았으면 받기 직전에 코드 창이 뜹니다. [브라우저 열기]를 누르고 그 코드를 넣습니다.

2설정 저장소란

Claude Code 는 작업 규칙 · 스킬 · 메모리 · 개인 키 · git 이름 같은 설정을 PC 마다 홈 폴더 (C:\Users\<내 이름>\.claude\)에 따로 둡니다. PC 가 둘이면 둘이 따로 놀고, 로그인할 때마다 비워지는 VDI 에서는 아예 사라집니다.

설정 저장소는 그 설정을 git 저장소 하나에 넣어 두고, 새 PC 에서 설치 한 번으로 되살리는 방법입니다. 설치는 받은 저장소의 뿌리에 .claude\hooks\session-start.sh 가 있으면 설정 저장소로 알아보고 그 파일을 실행합니다. 나머지는 그 파일이 합니다.

3넣으면 무엇이 더 일어나나

무엇어떻게
git 이름 · 메일저장소에 적어 둔 값으로 git config --global 을 맞춥니다
같이 쓰는 저장소적어 둔 목록을 repos\ 아래에 받아 둡니다 — 이미 있으면 건너뜁니다
개인 키secrets.env 에 적은 키(Tavily · GitHub 토큰 등)를 사용자 환경변수로 심습니다
도구 연결GitHub · Tavily 웹 검색을 Claude Code 에 붙입니다 — 목록은 mcp-servers.json
홈 설정Claude Code 홈 설정 파일이 없으면 vdi-home-settings.json 으로 깔고, 있으면 그대로 둡니다
규칙 · 스킬 · 메모리저장소의 deploy.ps1 이 홈과 각 저장소로 뿌립니다

그 뒤로는 설정 저장소를 연 Claude Code 세션과 로그온 자동 실행(설치 창의 「로그온할 때…」 칸)이 다시 맞춥니다. 저장소에서 키나 규칙을 고치면 다음 번에 새 값이 들어옵니다. 다른 프로젝트만 연 세션은 맞출 것이 있으면 알리기만 합니다.

4설정 저장소 만드는 법

맨바닥에서 만들지 않습니다. 설치가 견본 폴더를 깔아 둡니다 — C:\Users\<내 이름>\.claude\seeds\config-repo\. 필요한 파일이 다 들어 있고, 고칠 것은 내 값을 적는 파일 둘뿐입니다.

  1. GitHub 에 비공개 저장소를 만든다 — 이름은 claude-config 다른 저장소를 열었을 때 그 옆자리에서 이 이름으로 설정 저장소를 찾습니다. 이름이 다르면 설치는 되지만, 다른 저장소에서는 홈에 깔린 견본으로 대신 돕니다. 개인 키가 들어가니 반드시 비공개(Private)로 둡니다.
  2. 내 PC 로 받고, 견본 폴더를 통째로 복사한다 숨김 폴더 .claude · .githooks 도 같이 옮기고, memory 폴더는 지우지 않습니다 — 그 폴더가 있어야 설정 저장소로 알아봅니다. 탐색기로 끌면 숨김 폴더가 빠지기 쉬우니 Git Bash 에서 합니다. 
    git clone https://github.com/<내 아이디>/claude-config.git ~/repos/claude-config
cp -r ~/.claude/seeds/config-repo/. ~/repos/claude-config/
  3. personal.conf 에 내 값을 적는다 git 이름과 메일, 같이 받아 둘 저장소 이름들, 저장소 주소의 틀 — 셋입니다. 줄마다 위에 설명이 있고, 나머지 줄은 그대로 둡니다.
  4. 개인 키가 있으면 secrets.env 를 만든다 한 줄에 이름=값 하나씩. 키가 없으면 안 만들어도 됩니다.
  5. 커밋하고 올린다
  6. 설치 창의 「내 저장소 받기」에 그 주소를 넣고 설치한다 다음부터는 새 PC 에서 이 한 번으로 설정이 다 되살아납니다.
견본에서 온 스크립트는 고치지 않습니다 — deploy.ps1 · .claude\hooks\ · .githooks\. 내 값은 personal.conf 와 secrets.env 에만 들어가고, 스크립트는 그 두 파일을 읽습니다. 스크립트를 고치면 다음에 새 판을 받을 때 그 자리에서 부딪힙니다.

5더 알고 싶으면

견본 폴더의 README.md 가 파일 하나하나가 무엇인지, 커밋할 때 도는 검사는 무엇인지, 안 될 때 어디를 보는지를 적고 있습니다. 같은 폴더의 그림 둘(session-start-flow.svg · deploy-flow.svg)은 세션을 열 때와 뿌릴 때 무슨 일이 어떤 순서로 일어나는지 보여 줍니다. 더블클릭하면 브라우저가 엽니다.

이 문서는 설치 폴더에 같이 온 한 장입니다. 밖으로 나가는 주소가 없어 사내망에서도 열립니다.
