# 검사 씨앗

**새 저장소가 제 `_check/` 폴더를 만들 때 복사해서 출발하는 검사 한 벌이다.** 여기 든 검사들은
어느 저장소에서나 똑같이 생기는 결함을 잡는다 — 검사가 제 결론을 잘못 내보내는 결함, 문서가
없는 파일을 가리키는 결함, 만들어 낸 HTML 이 조용히 깨지는 결함.

임포트해서 쓰는 라이브러리가 아니다. 폴더를 복사하면 그때부터 그 저장소의 것이다. 다만 받아
간 파일은 **사본**으로 남아 진본을 가리킨다 — 아래 「진본과 사본」 절이 그 규율을 든다.

## 왜 이런 것이 따로 있나

검사를 저장소마다 새로 쓰면 같은 사고를 저장소마다 다시 겪는다. 수고는 그 정도로 끝나지만,
그보다 비싼 것이 하나 더 있다 — **검사가 결론을 내보내는 방식이 저장소마다 갈리는 것.**

커밋 훅과 CI 가 읽는 것은 화면에 찍힌 문구가 아니라 종료코드 하나다. 그래서 그 갈림은 사람
눈에 한 번도 안 띈 채 돈다 — 자격이나 검체(검사에 먹일 표본)가 없어 **아무것도 못 잰 판**이
「통과」로 세어지고, 아무도 그 사실을 모른다. 검사를 늘려 놓고 안심하는데 실제로 잰 것은 하나도
없는 판이다.

그래서 한 벌을 진본(원본)으로 둔다. 여기서 고친 사고는 받아 간 저장소가 고친 판을 다시 받아
가면 되고, 안 받으면 그 저장소가 같은 사고를 처음부터 다시 겪는다.

## 이 검사들이 무는 결함 — 전부 「조용한」 것이다

한 줄로 묶으면 이렇다. **터지지 않으므로 아무도 모르는 결함.** 터지는 결함은 어차피 걸리니
검사를 따로 세울 값이 없다.

| 무는 결함 | 왜 조용한가 |
|---|---|
| 못 쟀는데 「통과」로 나간다 | 화면은 못 쟀다고 맞는 말을 하는데, 훅과 CI 는 종료코드만 읽는다 |
| 「전부 통과」가 몇 건을 쟀는지 안 말한다 | 판정 절이 통째로 사라져도 그 문구와 종료코드가 안 바뀐다 |
| 검사 목록 문서가 실물과 어긋난다 | 없는 검사를 있다고 적은 줄을 읽은 사람은 재지도 않은 자리를 봤다고 여긴다 |
| 문서가 없는 파일·없는 설정 이름을 가리킨다 | 파일은 멀쩡히 열리고 읽는 사람만 틀린다 |
| 만들어 낸 HTML 속 스크립트가 깨진다 | 글자는 다 있어서, 글자를 세는 눈으로는 영영 안 보인다 |
| 자식 프로세스가 남긴 실패 까닭이 사라진다 | 까닭이 필요한 바로 그 자리에서만 사라진다 |
| 한꺼번에 찍힌 로그 줄이 서로 붙는다 | 사고 뒤에 읽을 기록이 그 자리에서 어긋난다 |
| 받아 간 사본이 진본과 조용히 갈린다 | 사본을 손댄 사람은 진본이 있는 줄 모른다 |

**어느 파일이 이 중 무엇을 물고 언제 돌리는지는 곁 문서 `_check/README.md` 의 표가 든다.**
그 목록을 여기 한 벌 더 두면 둘이 어긋나고, 어긋난 줄은 아무도 모른다.

## 그 표를 열기 전에 알아야 할 것 둘

1. **초록의 뜻이 검사마다 다르다.** 어떤 초록은 *우리 코드가 약속을 지킨다*는 말이고, 어떤
   초록은 *바깥이 지금은 그렇게 하더라*는 말이다. 뒤엣것은 판마다 흔들리고 돌릴 때 값을
   치른다(자격·요금). 갈래 넷과 각 갈래의 뜻은 `_check/README.md` 의 첫 표가 든다.
2. **결론은 종료코드로 온다** — `0` 쟀고 맞다 · `1` 어긋났다 · `2` **못 쟀다.** `2` 는 초록이
   아니다. 이 갈림을 아래에서는 **계약**이라고 부른다(코드가 지키기로 한 약속이라는 뜻이다).
   전문과, 어겼을 때 무엇이 새는지는 `_check/README.md` 의 종료코드 절이 든다.

## 출발하는 법

1. `_check/` 폴더를 통째로 새 저장소에 복사한다 — 검사들, 밑줄로 시작하는 공용 부품,
   그리고 지도 노릇을 하는 `_check/README.md`.
2. 지도의 표에 제 저장소 검사를 적는다. **「무엇을 재나」 칸은 손으로 안 적는다** — 각 검사
   파일의 머리 첫 줄이 그 칸의 진본이고, 그 줄을 표로 옮겨 적는 것은 `map_check.py --write` 다.
3. 받아 온 파일마다 머리말 끝에 **사본 표식**을 붙인다 — 진본이 어디인지 적는 한 줄이다.
   꼴은 바로 아래에 있다.
4. 저장소마다 갈리는 값을 곁 선언 파일에 적는다 — 아래 「값은 사본이 아니라 곁 선언에
   적는다」 절이 무엇을 어디에 적는지 든다.
5. 돌린다.

### 사본 표식의 꼴

기계가 찾는 것은 둘뿐이다 — 굵은 글자 `**빌려 온 자다**`, 그리고 백틱으로 싼 진본 상대경로
(`seeds/check/_check/<파일 이름>`). 그 앞에 저장소 이름을 맨글자로 적어도 되고, 그 부분은 안
읽힌다. 파이썬 파일이면 머리말 독스트링의 첫 문단 끝에 이렇게 붙는다.

```text
⚠ **빌려 온 자다** — 진본은 `seeds/check/_check/exit_code_check.py`(<커밋> 판)이고,
  고침은 **진본에서 받는다** — 이 사본을 손으로 고치지 않는다.
```

**자리는 머리말 문단의 끝, 첫 빈 줄 바로 앞이다.** 표식으로 읽히는 범위가 「표식 줄부터 다음
빈 줄까지」라서다 — 문단 머리에 두면 그 문단이 통째로 표식으로 읽혀 어긋남이 뜬다.

이 줄을 검사 코드와 지도에서는 **곁말**이라고 부른다 — 본문 옆에 붙어 본문을 설명하는 한
줄이라는 뜻이고, 이 문서의 「사본 표식」과 같은 것이다.

`.mjs` 파일은 자리가 하나 더 까다롭다. 머리 주석 블록 **안**이 아니라 **그 블록 뒤 첫 빈 줄
앞에 `//` 줄로** 둔다. 블록 주석 안에 두면 표식 범위가 주석을 통째로 삼키고, 파일 맨 머리에
두면 표식을 닫는 빈 줄이 몸통에 더해져 진본과 갈린다.

### 돌려 보기

복사 직후 인자 없이 바로 도는 것들이다. 다 `0` 이면 틀이 선 것이다.

```bash
python -X utf8 _check/exit_code_check.py       # 파이썬 검사가 종료코드 계약을 지키나
python -X utf8 _check/verdict_line_check.py    # 「전부 통과」 줄이 잰 건수를 스스로 세나
python -X utf8 _check/shell_exit_check.py      # .mjs·.sh·.ps1 검사의 같은 자리를 글자 꼴로
python -X utf8 _check/map_check.py             # 지도의 줄과 실제 파일이 맞나
```

사본 표식을 세운 뒤(위 3) 하나가 더 선다.

```bash
python -X utf8 _check/borrowed_check.py        # 사본이 진본과 같은가
```

표식이 든 파일이 한 장도 없으면 이 검사는 초록이 아니라 `2`(못 쟀다)로 나간다 — 잴 것이 없는
것과 다 맞는 것은 다른 말이라서다.

나머지 검사는 인자나 선언이 있어야 돌고, 없으면 `2` 로 나가며 어떻게 주는지 화면에 말한다.

## 이 씨앗이 드는 것과 그 저장소가 얹는 것

| 이 씨앗이 든다 | 그 저장소가 얹는다 |
|---|---|
| 판정을 찍고 세는 부품 한 벌 — 계약 판정 · 값 대조 · 통과할 때도 보여야 하는 경고 · 아예 못 잰 자리 | 그 저장소에만 있는 계약을 재는 검사 |
| 종료코드 계약(`0`·`1`·`2`)과 그 계약을 어긴 검사를 잡는 검사 | 훅과 CI 에 무엇을 태우나 — 태울 목록을 뽑는 손은 있다(`map_check.py --gates`). 무엇을 켜나는 그 저장소가 정한다 |
| 「전부 통과」 줄이 잰 건수를 스스로 세게 하는 규율과 그것을 어긴 검사를 잡는 검사 | 한국어 수사로 적은 범위(「계약 아홉」)가 맞는 말인가 — 글자가 곧 뜻이라 사람이 읽는다 |
| 브라우저 띄우기 · 서버 세우고 두드리기 · 제 뿌리와 파이썬 묻기 · 검체 파일 굽기 | 그 앱에만 있는 값 — 요청 머리 이름 · 임시 자리 · 판단이 필요한 대역 |
| 받아 간 사본이 진본과 같은지 재는 검사 | 표식을 안 붙이고 베낀 사본이 갈렸나 — 그 검사 밖이라 그 저장소가 제 손으로 본다 |

## 진본과 사본 — 받아 간 파일을 손으로 고치지 않는다

받아 간 파일은 사본이다. 머리말의 표식 한 줄이 진본을 가리키고, `borrowed_check.py` 가 그
표식을 읽어 진본 글자와 견준다. 줄끝(CRLF)과 파일 머리의 BOM 과 표식 블록은 빼고 본다 —
그 셋은 받는 저장소의 체크아웃이 정하는 것이라 갈려도 뜻이 없다.

진본이 사는 자리는 기본값이 `~/.claude/seeds/` 다(설치가 거기 깔았다). 딴 데 두었으면
`--seeds <뿌리>` 로 준다.

**어느 판의 진본과 견줬나는 판정 줄이 말한다.** 진본 뿌리의 판은 뿌리에 놓인 `.version` 한
줄(`<짧은 해시> <ISO 날짜>` · 홈에 씨앗을 까는 쪽이 남긴다) → 뿌리가 git 저장소면 `HEAD` →
둘 다 없으면 **「판 모름」** 차례로 읽는다. 「판 모름」은 빨강이 아니라 알림이다 — 「지금 이
뿌리와 같다」까지는 쟀고 **그 뿌리가 낡았나는 안 쟀다**는 뜻이다. 그 자리에 오늘 날짜를 찍으면
낡은 홈 씨앗과 견준 초록이 최신과 견준 것처럼 읽힌다 — 옛 판이 실제로 그랬다.

```bash
python -X utf8 _check/borrowed_check.py              # 사본이 낡았나
python -X utf8 _check/borrowed_check.py --receive    # 어긋난 사본을 진본 글자로 되받고 표식의 판 번호를 올린다
```

되받기(`--receive`)는 **표식이 든 사본만** 건드린다. 표식에 적힌 판 번호는 진본 뿌리가 git 저장소일
때만 잰다 — 몸통 글자가 지금 진본과 같아도, 표식이 가리키는 판에서 꺼낸 진본과 다르면 「도장이 옛 판」
빨강이고 `--receive` 가 판 번호를 올린다. 홈 씨앗처럼 git 저장소가 아닌 뿌리에서는 그 항을 「못 쟀다」로
말한다.

표식을 달 수 없는 사본도 하나 잰다 — 설정 저장소가 저장소마다 뿌린 커밋 게이트 파일(`.githooks/`)이다.
셸 조각에는 가리킬 `seeds/…` 자리가 없어, 표식 대신 **같은 자리의 진본**과 글자로 견준다. 진본 저장소가
이 기계에 안 붙었으면 판정 없이 안 잰 자리로 찍고, 저장소가 제 손으로 드는 `gates.conf` 는 견주지 않는다.

**일부러 갈랐으면 표식을 걷고 그 자리에 왜 갈랐는지 적는다.** 표식과 갈림이 함께 서 있으면
어긋남이다 — 「진본에서 받는다」고 약속한 파일이 진본과 다른 상태라서다.

## 값은 사본이 아니라 곁 선언에 적는다

저장소에 매인 값은 이 씨앗의 검사 안에 한 글자도 안 박혀 있다. 전부 인자나 선언으로 열려
있고, 안 주면 **초록을 내지 않고 `2` 로 나가며 어떻게 주는지 말한다.** 기본값을 안 박는
까닭은 이렇다 — 좁게 박으면 검사가 조용히 아무것도 안 물고, 넓게 박으면 남의 자리를 물어
거짓 빨강이 나며, 거짓 빨강을 본 사람은 검사를 끈다.

**그 값을 사본 머리에 채워 넣으면 안 된다.** 사본은 진본과 글자가 같아야 하므로, 값은 곁
선언 파일 `_check/<이름>.conf` 에 산다. 씨앗은 선언을 안 싣는다 — 실으면 받은 저장소가 남의
저장소 좌표를 재고도 초록을 본다.

| 선언 | 무엇을 적나 |
|---|---|
| `part_map.conf` | `[part_map]` 의 `doc`·`app`·`section` — 부품 지도 문서, 부품 폴더, 그 표가 앉은 절 제목 |
| `env_names.conf` | `[env_names]` 의 `doc`·`ours`·`skip` 과 `[not_ours]` 의 「이름 = 까닭」 — 환경변수 문서와, 어디까지가 우리가 지은 이름인가 |
| `doc_span.conf` | 제 문서 나무와 코드 나무가 어디인가, 그리고 경로처럼 보이지만 좌표가 아닌 머리글자. 절 목록은 `doc_span_check.py` 머리말의 선언 절이 든다 |
| `map_check.conf` | `[needs_arg]` 의 「이름 = 까닭」 — 인자가 있어야 도는 검사를 훅 목록에서 뺄 것. 씨앗 기본값은 비어 있다 |
| `child_decode.conf` | `[skip]` 의 「파일:줄 = 까닭」 — 근거를 대고 뺄 자리. 구분자는 `=` 하나다 |

선언 대신 인자로만 받는 것도 있다. 카드 폭(`boundary_edge_check.py --width`)과 로그 배관
(`log_race_check.py --plumb`)이 그렇고, 둘 다 환경변수로도 받는다. 검체를 굽는 부품
`_bake.mjs` 의 `drmFile` 에 넘길 머리 바이트는 **부르는 검사가 제 저장소 진본에서 읽어**
넘긴다 — 여기 옮겨 적으면 규격이 바뀐 날 검사만 옛 바이트를 물고 초록을 낸다.

**빈 목록이 통과의 조건이 아니다.** 근거를 대고 뺀 자리는 판정 옆에 이름과 까닭이 함께 찍힌다
— 그 목록은 줄이려고 두는 것이지 채우려고 두는 것이 아니다.

## 게이트웨이 배관은 다른 씨앗이다

사내 게이트웨이에 붙는 배관과 그 검사는 곁 폴더 `gateway/` 가 든다. 그쪽 `_check/` 의
`_verdict.py` 와 `exit_code_check.py` 는 이쪽 사본이라, 두 씨앗을 다 받으면 그 두 파일이
겹친다(표식 줄 말고는 글자가 같다). 씨앗끼리도 같은 규율이 도는지는 씨앗 뿌리에서 이렇게 잰다.

```bash
python -X utf8 check/_check/borrowed_check.py gateway/_check --seeds .
```
