# 에이전트에게 일을 맡긴다

**이 스킬은 일을 맡기는 부모 세션이 읽고, 맡기기는 여기서 시작한다.** 일을 받는 쪽(이하 **레인**)은 Claude
서브에이전트든 agy · Codex 든 부모가 써 준 작업 지시서(이하 **봉투**)만 받는다. 이 대화는 레인에게 건너가지 않으니
레인이 알 것과 지킬 것은 모두 봉투에 싣는다.

## 1. 누구에게 맡기나

### 일의 성격부터 묻는다

도구에서 출발하면 늘 가장 익숙한 도구로 간다. **일이 무엇을 요구하나**에서 출발한다 — 무게를 먼저 가르고, 그 일을
질 수 있는 쪽 가운데서 계열을 고른다. **무게가 문턱이고 계열은 그 안의 선호다** — 무게를 못 지는 쪽의 답은 독립돼
있어도 얕아서, 부모가 다시 재야 하는 인상만 남긴다.

1. **무게를 가른다** — 둘 가운데 하나고, 괄호 안 낱말은 모델 표(2)의 무게 칸이다
   - **깊은 판단**(`deep`) — 검증 · 원인 · 설계 가운데 하나가 든다: 결함인지 가르기 · 남이 만든 것의 검증 · 원인을 가르는
     조사 · 설계
   - **심부름**(`errand`) — 그 셋이 안 든다: 목적과 가르는 기준이 주어진 찾기 · 재기 · 훑기 · 요약, 차례가 정해진 고치기.
     차례가 스크립트로 되면 레인 대신 스크립트로 한다(규범 [Determinism First])
   - 긴 맥락은 무게가 아니라 꼴이다 — 저장소 통째 · 여러 파일 · 긴 문서는 쪼개기를 가를 뿐 모델을 바꾸지 않는다. 쪼개기는
     긴 맥락을 덜지 깊은 판단을 덜지 않는다 — 판단을 잘게 나누면 판단 조각이 될 뿐이다
2. **그 일을 질 수 있는 쪽만 남긴다**
   - 무게 — 자리마다 어느 무게를 어느 도구의 어느 모델에 대나는 이 스킬 폴더의 모델 표 [`models.conf`](models.conf) 가
     든다. 자리는 사용자 환경변수 `PAISETUP_SITE`(설치기가 심는다)가 대고, **그 자리 줄에 그 무게 칸이 없는 도구는 뺀다.**
     어느 모델이 어느 무게를 지나는 자리마다 다르고(구독 한도 · API) 판이 오를 때마다 바뀌어 표 한 곳만 고친다
   - 자리를 모르면 두 자리에 다 있는 칸만 남긴다 — 모를 때 넓게 남기면 계열 선호(3)가 무게를 건너뛴다
   - 닿는 데 — 이 PC 의 실물(앱 · 홈 · 설정 · 세션 도구)을 만지는 일은 **맡기는 앱의 서브에이전트만** 남는다 — 세션의
     도구와 승인을 물려받는 것은 그쪽뿐이다
   - 한도가 바닥이거나 그 자리에 안 깔린 도구는 뺀다
3. **남은 쪽에서 계열을 고른다**
   - 남이 만든 것(코드 · 고침 · 설계 · 다른 레인의 답)을 검증하나 → **만든 계열과 다른 쪽.** 같은 계열은 같은 자리를
     놓쳐, 같은 계열의 초록은 독립된 확인이 아니다. 남은 쪽이 같은 계열뿐이면 그쪽에 맡기고 보고에 「같은 계열의
     검증」이라고 적는다 — 독립성이 빠진 초록을 독립된 확인처럼 내밀지 않는다. 검증을 **할지**는 룰 [Review Triage] 가
     가른다
   - 아니면 계열은 열려 있다 — 한도와 값이 남는 쪽으로 간다

### 맡길 곳마다 다른 것

러너로 띄우는 곳은 그 러너 스킬이 깔린 자리에서만 고른다. 웹 조사는 넷 다 한다 — Codex 는 자리 값이 검색을 켠
곳에서만.

| | Claude 서브에이전트 | agy | Codex(한도면 Copilot) | Claude(Codex · agy 가 맡길 때) |
|---|---|---|---|---|
| 띄우기 · 이어 묻기 | Agent 도구 · SendMessage | agy-background | codex-copilot-background | claude-background |
| 모델 고르기 | `model` 인자에 모델 표의 `claude` 이름을 준다 | 러너가 자리 값으로 고른다 — 무게를 주는 법은 러너 스킬의 「모델」 절 | 러너가 자리 값으로 고른다 — 무게를 주는 법은 러너 스킬의 「자리 값」 절 | `--model` 에 모델 표의 `claude` 이름을 준다 |
| 쓰는 힘 · 가두는 법 | 쓴다 — 고치기는 worktree 격리와 소유 선긋기로 가둔다(2절) | 묻지 않고 쓴다 — 블록은 부탁일 뿐이고 울타리는 작업 자리다 | 기본은 읽기만이라 저장소를 통째로 가리켜도 된다. 고치기는 `--write` 로 작업 자리 안만 — Copilot 이 받으면 셸이 없어 검사는 부모가 돌린다 | 기본은 읽기만이라 저장소를 통째로 가리켜도 된다. 고치기는 `--write` 로 작업 자리 안만 — 셸이 없어 검사는 부모가 돌린다 |

**같은 계열에게 맡기기로 했으면 셸보다 그 앱의 서브에이전트로 띄운다** — 세션의 승인 방식과 도구를 물려받는다.

**이어 묻기와 새로 띄우기는 다음 걸음이 무엇을 쓰나로 가른다** — 레인이 쥔 기억을 쓰면 잇고, 파일을 더 쓰면 작업 트리 ·
파일을 가리키는 새 봉투를 띄운다. 잇기는 그 레인의 기록을 통째로 다시 읽히므로, 기록이 크고 캐시가 식었으면 잇는 값이
그만큼 든다.

## 2. 가르기 전 — 병렬을 열 수 있나

- **찾기 · 재기는 언제든 병렬로 연다. 고치기는 한 손으로 하거나, 셋이 함께 설 때만 병렬로 연다** — worktree
  격리 · 봉투에 소유 선긋기 · 부모 한 손 머지. 같은 트리에 쓰는 손이 둘이면 늦게 쓴 쪽이 이기고, 검사는 서로의
  반쯤 고친 코드 위를 돈다
- **소유는 파일과 함께 실행 중에 붙잡는 자원으로도 가른다** — 한 번에 하나만 뜨는 자동화 서버 · 포트 · 기준
  스냅샷(골든) · 공용 검사는 파일 표에 안 잡히고, worktree 격리도 파일만 가른다
- 같은 트리에서 여럿이 재면 **재는 자가 제 소스 지문(해시)을 산출에 같이 찍게 한다** — 재는 도중 트리가
  움직이면, 지문 없는 측정은 어느 판 위에서 났는지 증명이 안 된다
- **레인을 한꺼번에 죽이는 것을 띄우기 전에 센다** — 세션 토큰 한도(429)와 동시 실행 상한은 한꺼번에 띄운 묶음을
  통째로 죽이므로 무거운 일은 나눠 띄운다. 상한 · 리셋 시각은 재 봐야 나오는 수라 그 저장소 메모리가 든다

## 3. 봉투를 짓는다

**과업 원본이 곧 봉투다** — 문제 · 실측 · 갈래 · 재는 법 · 경계는 원본(이슈)이 든다(이슈 골격은 issue-write
스킬). 봉투에는 원본의 주소와 이 판의 규율만 싣고, 원본은 레인이 직접 연다. 본문이나 이력을 봉투나 사본 파일로
옮기면 그 순간 두 벌이 되고(낡는 쪽은 늘 사본) 봉투마다 일이 겹친다 — 봉투는 대화 내내 컨텍스트에 살아, 붙여넣은
이력은 값이 아니라 비용이다. *(➔ 규범 [Single Source · Point or Derive])*

봉투에 미리 가르는 것 — 뒤늦게 가르면 머지에서야 드러난다:

| 칸 | 무엇 |
|---|---|
| 소유 | **쓰는 레인만 가른다** — 파일/구역 + 붙잡는 자원 + **그 실물을 역산한 Reference 문서**(코드를 고친 손이 같은 봉투에서 문서도 고친다) · **안 볼 것**까지. 겹침은 소유가 아니라 「안 봄」이 막는다. **찾기 · 재기 레인에는 목적과 가르는 기준을 주고 어디를 얼마나 볼지는 맡긴다** — 이름 댄 대상은 출발점이지 울타리가 아니고, 겹친 발견은 거둘 때 걷는다(5절) |
| 이름 | 표찰(라벨·앵커) · 산출/보고 파일 경로 — **레인마다 다르게.** 같은 이름은 서로 덮는다 |
| 자료 · 도구 | 레인이 열 원본과 쓸 도구 — 맡길 곳마다 닿는 데가 달라(1절) **못 닿는 원본은 작업 자리에 파일로 내려 두고 그 경로를 준다** |
| 무게 | 1절에서 가른 무게를 한 낱말로 — 거둘 때 무게에 맞는 모델이었나를 견준다 |
| 산출 계약 | 발견마다 `파일:줄` + 실패 시나리오 — 둘이 다 있어야 발견이고, 없으면 인상이다 · **안 잰 것 · 안 본 것을 이름으로** · **0건도 유효한 보고다** — 없으면 없다고 쓰고 어디까지 봤나를 댄다(채우려고 지어낸 것도 인상이다) · 화면이면 그림 경로와 「무엇이 보이나」를 사람 말로 · **탐침은 트리를 인자로 받게 짓는다** — 경로를 박으면 부모의 전/후 재기가 헛돈다 |

⚠ **봉투가 가리키는 좌표가 실재하는지 부모가 먼저 확인한다** — 원본 본문이 낡았을 수 있다.
레인에도 같은 확인을 시키고, 없으면 보고만 하라고 적는다.

**레인이 다른 저장소의 규격을 옮겨 오는 판이면 봉투에 borrow-spec-as-pair 를 이름으로 싣는다** — 짝을 세는
규율도 레인은 봉투로만 받는다.

**봉투와 레인의 보고는 영어로 쓰고, 레인이 사람이 직접 열 파일을 남길 때만 그 파일을 한국어로 시킨다** — 모델 안의
매체가 영어라, 한국어 봉투는 레인이 매 문장과 중간 산출을 옮기며 다루고, 보고는 어차피 부모가 풀어 전하므로
한국어로 시키면 옮김만 한 번 는다(옮김의 규율은 규범 [Cross-Cultural Recoupling]). 좌표 · 이름 · 따옴표 안의
실물 문자열은 원문 그대로 둔다 — 옮기면 못 찾는다.

## 4. 레인 절대 규칙 — 이 블록을 봉투에 그대로 싣는다

레인이 읽는 말이라 영어다(3절). 부모는 뜻을 알고 글자 그대로 싣는다. *(➔ 규범을 못 받는 레인용 사본이다 — ④⑤⑦ 은 규범
[Goal-Driven Execution] · 코드 룰 [Guardrail] 의 거울)*

    ① Edit only what you own — reading anywhere is fine; another lane may be editing next to you. Report defects outside your ownership; do not fix them.
    ② A "could not measure" mark counts as red — never say "done" while one stands.
    ③ Never change state through git. The parent commits — leave changes uncommitted in the worktree.
    ④ Never derive expected values from what you measured, and never bless goldens or snapshots — a human approves those. Write why the value must be what it is; if the measurement differs, report it.
    ⑤ Before reporting "absent", run a positive control — first ask whether the specimen really has that shape.
    ⑥ Never run commands that print the environment or the process list (env, printenv, set, ps aux, pgrep -af) — they write secrets into the transcript.
    ⑦ A check and its specimen are one pair — when tightening a check turns a specimen red, fix both in the same pass.
    ⑧ Lanes share one machine. Run your long checks one at a time, in the background, and wait for the finish notification instead of polling or starting a second copy — overlapping copies slow every run.

읽기 레인에는 ①③ 을 빼고 싣는다 — 쓰기는 샌드박스와 보이는 도구가 막는다. 이 판에만 걸리는 지시는 블록 밖 봉투
본문에 적고, 모든 레인에 걸 규칙이면 이 블록을 고친다.

## 5. 레인 결과 거두기 — 부모가 지는 것, 레인에 못 넘긴다

- **부모 확인은 재검이 아니라 시야다** — 봉투가 좁힌 시야 밖을 부모가 본다. 제 손으로 재는 것은 넷: 소유 밖
  형제(레인이 고친 무늬를 grep) · 레인 목록 밖 곁 검사 전수 · 레인이 옮겨 적거나 다시 쓴 덩어리의 원본 대조 ·
  레인이 올린 「부모가 가를 것」. 그림은 눈으로 연다 *(➔ 규범 [Goal-Driven Execution] — 초록은 본 데까지다)*
- **레인이 돌린 검사와 물림은 보고로 받는다** — 물림은 일부러 틀린 표본을 넣어 검사가 정말 빨강을 내는지 보는
  단계고, 새 판정은 작아도 레인이 물며 봉투가 시킨다. 보고에 건수 · 물림 결과 · 트리 지문이 있으면 받는다.
  diff 는 읽는다 — 커밋 안 된 worktree 에서 `git checkout` 으로 되돌리면 곧 지우는 것이라, 되돌려 볼 일은
  사본에서 한다
- 저장소의 게이트 러너가 **작업 트리를 재고** 판정 도장을 남기면 **봉투에 검사를 그 러너로 돌리라고 적는다**(씨앗
  러너는 `--run-gates --only <이름>`) — 검사 파일을 직접 부르면 도장이 없어, 거둔 트리가 같아도 푸시가 다시 잰다.
  담긴 것만 재는 게이트는 커밋 안 하는 레인이 못 돌리니 검사 파일을 부르게 하고 게이트는 부모가 돌린다
- 레인 여럿의 산출은 **교차 중복부터 걷는다** — 같은 자리를 두 축이 문다
- **소유 밖 발견은 부모가 가른다**(갈래 셋은 issue-write) — 지금 고칠 것이면 그 자리를 쥔 레인에게, 없으면
  발견한 레인에 소유를 넓혀 맡긴다. 넓힌 소유는 봉투에 적는다. 잇나 새로 띄우나는 1절이 가른다
- **넘김은 받는 이슈에 줄을 남긴다** — 마감 코멘트에만 적으면 증발한다
- **worktree 레인의 변경은 파일로 거둔다** — 봉투가 소유를 갈라 두었으면 레인이 손댄 파일은 본 클론의 것과
  겹치지 않고, 겹치지 않는 변경은 병합기 없이 그 파일들을 그대로 복사하면 된다. 거둔 것이 레인 트리와 같은지는
  **해시로** 견준다 — 줄 수는 같은 수로 다른 내용이 지나간다. 복사해 오면 부모 커밋이 훅을 그대로 탄다.
  ⚠ **복사 전에 레인 트리의 출발 커밋을 지금 main 과 견준다**(`git -C <트리> rev-parse HEAD`) — 다르면 그 사이
  main 에서 바뀐 파일은 레인 판이 옛 판 위에 선 것이라, 복사하면 main 의 새 내용을 덮는다. 그 파일은 main 과
  견줘(`git -C <트리> diff main -- <파일>`) 레인의 고침만 얹는다.
  ⚠ **패치는 소유가 겹쳐 진짜 병합이 필요할 때만 쓴다** — 작업 사본의 줄끝이 색인과 다른 설정에서는 트리에서
  뽑은 diff 가 본 클론에 안 붙는다. 그 길은 `git -C <트리> diff --cached --binary` → `git apply --index --3way`
  이고(새 파일까지 실으려면 트리에서 먼저 담는다), 셋을 더 한다: 충돌을 스크립트로 풀었으면 끝에 충돌
  표식(`<<<<<<<` · `=======` · `>>>>>>>`)을 **반드시 grep 한다**(리졸버가 한 파일에서 멈추면 뒤 파일이
  미해결인 채 담긴다) · 줄끝을 바꿔 쓰는 설정(autocrlf)이면 **얹힌 작업 파일의 줄끝을 저장소 줄끝으로
  되돌린다** — `apply` 는 작업 사본을 바꾼 줄끝으로 써서, 줄바꿈 무늬를 찾는 검사가 안 바뀐 코드에서 빨강을
  낸다(색인은 같다고 봐 `checkout` 도 안 고친다) · `apply` · `cherry-pick` 은 커밋 훅을 안 타므로 게이트를
  본 클론에서 손으로 돌린다
- **남은 작업 트리를 걷는다** — 격리 트리는 저장소 **안** `.claude/worktrees/<이름>/` 에 서고, 변경이 남은
  트리는 옛 판의 사본이라 저장소를 통째로 훑는 검사가 그것까지 잡는다. 거두기가 끝나면
  `git worktree remove --force` 와 `git branch -D worktree-*` 로 걷는다

## 갈리는 자리

| 갈리는 자리 | 어느 쪽 |
|---|---|
| 무게가 애매하다 | 검증 · 원인 · 설계 가운데 하나를 이름으로 댈 수 있나로 가른다 — 대면 깊은 판단, 못 대면 심부름. 「판단이 들어 보인다」는 이름이 아니다. 틀린 답을 거두는 값과 깊은 판을 쓰는 값은 자리마다 달라 한쪽으로 미리 기울이지 않는다 — 구독 자리의 값은 돈이 아니라 한도고, 한도가 바닥나면 모든 레인이 멈춘다 |
| 레인이 곁 결함을 고쳐 왔다 | 시키지 않은 소유 밖 고침은 걷고 보고로 받는다 — 가름은 5절 「소유 밖 발견」이 맡는다 |
