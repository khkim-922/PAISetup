# 회사 일정은 일정 손으로 보고 · 넣고 · 지운다

사내 일정 앱은 메일함 밖의 따로 선 앱이고, 그 앱의 내 일정함을 이 스킬의 일정 손(`scripts/agenda.py`)이
읽고 바꾼다. 이 스킬은 그 손을 부르는 명령 하나와, 대화에서 지킬 차례를 든다. 회사 일정은 남이 보는 공유 시스템이고 지운
일정은 되돌릴 손이 없다 — 그래서 **넣기 · 지우기는 그 한 건을 사람에게 보이고 「네」를 받은 뒤에만 부른다.** 무엇을 넣을지 ·
무엇이 급한지 같은 판단은 여기 없다.

## 1. 명령은 하나다

```bash
python -X utf8 -I "<이 스킬>/scripts/company_calendar.py" show [오늘|내일|모레|YYYY-MM-DD] [끝 날] [--shared] [--who <이름>]
python -X utf8 -I "<이 스킬>/scripts/company_calendar.py" calendars
python -X utf8 -I "<이 스킬>/scripts/company_calendar.py" preview --title "…" --start "YYYY-MM-DD HH:MM" --end "YYYY-MM-DD HH:MM" [--note "…"]
python -X utf8 -I "<이 스킬>/scripts/company_calendar.py" add     --title "…" --start "YYYY-MM-DD HH:MM" --end "YYYY-MM-DD HH:MM" [--note "…"] --seen <preview 의 seen>
python -X utf8 -I "<이 스킬>/scripts/company_calendar.py" delete <handle>
python -X utf8 -I "<이 스킬>/scripts/company_calendar.py" remember "<일정 화면 주소창의 주소>"
```

시각은 다 서울 벽시계다. `show` 는 날을 안 주면 오늘 · 내일, 하나 주면 그날, 둘 주면 그 사이다. 「금요일」처럼 요일로 들은 날은 `show`
답의 `today` · `today_weekday`(서울의 오늘과 그 요일)에서 세고, `preview` 답의 `day` · `weekday` 를 확인에 「11월 13일(금)」처럼
드러내 사람이 바로잡게 한다 — 요일은 답에 실린 값을 쓰고 제 셈으로 짐작하지 않는다. 일정 줄에도 `weekday` 가 든다. 답은 표준 출력의 JSON 하나이고, 내 일정 줄마다 `handle` 이 든다 — 지우기에 넘기는
손잡이라 사람에게 보이지 않고 대화 속에 들고 간다. 내 일정 줄의 `pending` 이 참이면 아직 참석 답을 안 한 받은 초대다 — 「참석 답 전」을
붙여 보이고, 참석 답은 여기서 하지 않는다(초대 메일이나 회사 일정 화면). `preview` · `show` · `calendars` · `remember` 는 일정을 안 바꾸고, `add` · `delete` 만 바꾼다.

| 종료 값 | 뜻 | 할 일 |
|---|---|---|
| 0 | 됐다 | 넣기 · 지우기는 답의 `state` 를 아래 3 · 4 대로 말한다 |
| 1 | 도구 고장 | `message` 를 그대로 알린다 — 다시 시도하거나 우회하지 않는다 |
| 2 | 인자가 틀렸다 | 고쳐 다시 부른다 |
| 3 | 사내 세션이 없거나 끊겼다 | 스킬 **ep-login** 을 불러 사람을 이끈 뒤 같은 명령을 다시 부른다 |
| 4 | 준 주소가 틀렸거나, 잰 기본 주소로 이 사람의 일정함이 안 읽힌다 | 아래 2 의 주소 받기로 간다 |

### 공유받은 일정함 — 물을 때만 본다

`show` 는 두 깃발 없이는 내 일정함만 읽는다. 사람이 남의 일정을 물을 때만 공유받은 일정함(일정 화면 왼쪽 「공유 캘린더」)을 연다 — 「○ 팀장님
내일 일정」은 `show 내일 --who <그분 이름>`(이름의 한 부분이면 된다 · 내 일정은 빠진다), 「팀 사람들 일정까지 같이」는 `show … --shared`
(내 일정 `events` 와 공유 `shared` 가 따로 온다). 둘을 함께 주면 `--who` 가 이긴다 — 걸린 일정함만 오고 내 일정은 빠진다. 누가 있나는 `calendars` 가 든다 — 사람마다 다르니 이름을 짐작하지 말고 그 답에서 고른다.
`--who` 가 아무 일정함에도 안 걸리면 종료 2 와 있는 이름들이 온다.

공유 줄에는 `calendar`(누구 일정함인가)가 붙고 `handle` · `pending` 이 없다 — 읽기만 하고, 참석 답은 그 일정함 주인의 것이다. 보일 때 누구 일정인지 함께 말하고, `private` 이 참인 줄은
주인이 비공개로 든 일정이니 「비공개」를 붙여 보인다. 한 일정함만 못 읽었으면 그 이름이 `shared_failed` 에 오고 나머지는 보인다 —
못 읽은 이름을 알린다.

## 2. 준비 — 세션과 주소

**세션** — 명령이 부를 때마다 먼저 쓰는 사람의 Edge 에 붙어 그때의 사내 세션을 받는다(스킬 ep-login 의 받는 손). Edge 가 디버깅 포트로
떠 있고 로그인돼 있으면 사람은 아무것도 안 한다. Edge 에 못 붙으면 남은 세션 파일로 한 번 해 보고, 그 세션도 끊겼거나 남은 것이
없거나 로그인이 안 됐으면 종료 3 이 온다. 세션 파일 자리는 받는 손의 기본
자리이고 저장소 밖이다.

**일정 앱 주소** — 사람에게 먼저 묻지 않는다. 명령은 `--url` → `CALENDAR_URL` → 남긴 주소 → 잰 기본 주소(`agenda.DEFAULT_APP_URL`)
차례로 쓰고, 기본 주소를 쓸 때는 그 주소로 이 사람의 일정함이 읽히나 먼저 본다. 일정 DB 가 다른 서버(`http://pcfca0N.posco.net/02/cal/calperson<NN>.nsf`)에
있는 사람은 거기서 종료 4 가 난다 — 그때만 이렇게 청한다 —
「Edge 에서 메일을 열고 위의 일정 메뉴를 눌러 주세요. 열린 일정 화면의 주소창 주소를 그대로 붙여 주시면 됩니다.」 받은 주소로
`remember` 를 부른다. 그 주소로 내 일정함이 읽혀야 남기고, 남는 자리는 `~/.company-calendar.json` 이다(주소만 든다). 비영속 VDI 는
로그온마다 홈이 새로 서서 그 파일도 사라진다 — 기본 주소로 안 읽히는 사람에게만 그때 다시 청한다.

## 3. 넣기 — 보이고, 확인받고, 넣는다

1. 사람의 말에서 제목 · 날 · 시작 · 끝 · 설명(장소 같은 것)을 짓는다. 끝 시각이 없으면 지어 넣지 말고 확인에 「1시간으로 넣을까요」처럼
   드러내 묻는다
2. `preview` 를 부르고 그 답으로 보인다 — 회사 일정에 남을 제목(잘린 꼴 그대로) · 날 · 시각 · 설명 · 그 시각에 겹치는 일정(`clash`) ·
   같은 일정이 이미 있나(`already` — 있으면 넣지 않는다고 말하고 멈춘다). 함께 말한다 — 「내 일정함에만 들어가고 참석자는 없어 누구에게도
   알림이 안 갑니다. 공개로 들어가 다른 분이 제목을 볼 수 있습니다.」
3. 사람이 **그 한 건**을 두고 넣으라고 분명히 답한 뒤에만 `add` 를 `preview` 와 같은 값과 그 답의 `seen` 으로 부른다. 사람이 무엇이든
   바꾸면 `preview` 부터 다시 간다. 여러 건이면 건마다 보이고, 사람이 그 목록에서 고른 것만 넣는다
4. 끝을 `state` 로 말한다 — `added` 「넣었습니다(다시 읽어 확인했습니다)」 · `already` 「같은 일정이 이미 있어 넣지 않았습니다」 ·
   `clashed` 「확인하신 뒤 그 시각에 다른 일정이 들어와 넣지 않았습니다」 — `preview` 를 다시 불러 새 겹침을 보이고 다시 묻는다 ·
   `unsure` 「넣었는지 확인하지 못했습니다」 — 다시 넣지 말고 `show` 로 그날을 읽어 보인다. 넣은 일정의 `handle` 을 들고 있다가 「방금
   것 지워 줘」에 쓴다

## 4. 지우기 — 지울 수 있는 줄만, 확인받고 지운다

1. `show` 로 그날을 읽어 그 일정을 찾는다. 후보가 둘 이상이면 고르게 묻는다
2. 그 줄의 `keep` 이 비었으면 지울 수 있다 — 날 · 시각 · 제목을 보이고 「지우면 되돌릴 수 없습니다」를 붙여 묻는다. `keep` 이 찼으면
   까닭을 말하고 지우지 않는다:

   | `keep` | 말 |
   |---|---|
   | `invite` | 받은 회의 초대입니다 — 지우면 곧 참석 답이 됩니다. 참석 답은 초대 메일이나 회사 일정 화면에서 해 주세요 |
   | `meeting` | 회의로 든 일정입니다 — 지우면 참석하실 분께 알림이 갈 수 있어 여기서는 지우지 않습니다. 회사 일정 화면에서 지워 주세요 |
   | `repeat` | 반복 일정입니다 — 지우기가 그날 하나만 걷는지 아직 확인하지 않아 여기서는 지우지 않습니다. 회사 일정 화면에서 지워 주세요 |
   | `all_day` | 하루 종일 일정입니다 — 지우기를 아직 확인하지 않아 여기서는 지우지 않습니다. 회사 일정 화면에서 지워 주세요 |
   | `locked` | 고칠 수 있는 일정으로 읽히지 않았습니다 — 일정 앱이 막은 것인지 그 표시를 못 알아본 것인지 가리지 못해 여기서는 지우지 않습니다. 회사 일정 화면에서 지워 주세요 |
   | `shared` | 공유받은 일정함의 일정입니다 — 여기서는 읽기만 합니다 |

3. 사람이 **그 한 건**을 두고 지우라고 분명히 답한 뒤에만 `delete <handle>` 을 부른다
4. 끝을 `state` 로 말한다 — `deleted` 「지웠습니다(다시 읽어 사라진 것을 확인했습니다)」 · `gone` 「그날 일정에 없습니다 — 이미
   지워졌거나 다른 날로 옮겨졌습니다」 · `changed` 「보여 드린 뒤 그 일정이 바뀌었습니다」 — 답의 `event`(지금의 꼴)를 보이고 다시
   묻는다 · `unsure` 「지웠는지 확인하지 못했습니다」 — 다시 부르지 말고 `show` 로 보인다 · `refused` 위 표의 말

## 안 하는 것

- 공유받은 일정함에 넣기 · 지우기, 공유받지 않은 남의 일정 · 회의실 · 참석 답 · 참석자를 넣은 일정 · 반복 · 하루 종일 일정 넣기
- 일정 옮기기 · 고치기 — 일정 줄의 `url` 은 편집 화면이라 열지 않는다(읽는 손이 그 주소를 막는다). 사람에게 회사 일정 화면을 권한다
- 회사 일정 앱 화면을 브라우저로 조작하거나, 일정 손을 거치지 않고 일정 주소를 직접 부르기
