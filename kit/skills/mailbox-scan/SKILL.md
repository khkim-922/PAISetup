# 메일함을 미리 읽어 쌓아 둔다

업무 파악 · 일일 보고 · 메일함 정리가 부를 때마다 메일함을 처음부터 읽으면 몇 분이 들고, 사용자가 그 사이 메일함에서 한 일(연 메일 · 옮긴 메일 ·
지운 메일)은 그 순간의 읽음 표시로만 보인다. 이 스킬은 PC 가 켜져 있는 동안 몇 분마다 회사 메일 손을 불러 메일함의 머리를 쌓고, 지난번
모습과 견주어 그 사이 바뀐 것을 누가 했나(사용자 · 비서 · 모름)와 함께 적는다. 읽는 쪽은 그 기록에서 「지난번 뒤」와 「지금 모습」을 받고,
본문이 필요한 메일만 회사 메일 스킬로 연다.

```bash
python -X utf8 -I "<이 스킬>/scripts/reader.py" status | new --since "YYYY-MM-DD HH:MM" | now | changes --since … | mails … | signals
python -X utf8 -I "<이 스킬>/scripts/scan.py" register | status | unregister             # 걸기 · 보기 · 끄기(--dry-run 은 보이기만)
python -X utf8 -I "<이 스킬>/scripts/scan.py" register --brief-at 07:30                  # 아침 보고도 함께 건다
python -X utf8 -I "<이 스킬>/scripts/scan.py" brief --at 08:00 | brief --off                # 보고 시각만 바꾸기 · 보고만 내리기
python -X utf8 -I "<이 스킬>/scripts/scan.py" run [--now]                                  # 한 판을 지금
```

인자와 종료 값은 `--help` 가, 다음 걸음은 출력의 끝 줄이 말하니 그 말대로 간다.

## 읽는 쪽은 reader.py 만 쓴다

- **스캔 파일을 직접 열지 않는다** — 읽는 명령이 시각으로 잘라 내고, 판 사이에 자리를 확인 중인 메일을 수에서 빼고, 메일함의 글을 자료
  구역에 싸서 낸다. 파일의 꼴은 스캔이 바꾼다
- **마지막으로 다 본 때를 함께 본다** — 출력 머리가 새 메일 · 메일함 전체를 마지막으로 다 본 때를 댄다. 그 뒤에 온 메일과 바뀜은 아직
  안 들었다. 스캔 파일이 없거나(종료 3) 너무 낡았으면 지금처럼 회사 메일 스킬로 읽는다
- **멈췄다는 줄은 사용자께 전한다** — 「⚠ 멈춤」 줄은 언제부터 왜 멈췄나를 댄다. 사내 세션이 끊긴 것이면 대화에서 스킬 ep-login 으로 EP 로그인을
  하시게 이끌고, 된 뒤 `scan.py run --now` 로 한 판을 돌린다. 스캔은 스스로 로그인하지 않는다
- 바뀜의 「비서」는 메일함 정리 스킬이 기록에 적은 바꿈이고, 「모름」은 그 스킬이 잡아 둔 채 아직 맺지 못한 바꿈이다 — 둘 다 사용자가 한
  일로 말씀드리지 않는다

## 정리를 권할지 가를 재료 — signals

`signals` 는 메일함이 정리를 부르는 모습인가를 가를 셈만 낸다 — 받은편지함의 지금 통 수 · 안 읽음과 판 기록 속 흐름(가장 늦은 판 · 하루쯤 전 ·
이레쯤 전, 기록이 어디까지 닿나), 규칙이 채우는 폴더마다 통 수 · 안 읽음, 폴더마다 가장 새 메일의 때(메일에 찍힌 때라 옮겨 넣은 옛 메일은 제
때를 지닌다 — 폴더에 든 때가 아니다), 그 셈이 기댄 메일함 전체를 본 판의 때다.
「정리할 때다」 · 「죽은 폴더」 같은 말은 안 붙인다 — 지난 정리 · 지난 권유 때와 견주어 권할지는 읽는 쪽(모델)이 가른다. 흐름은 메일함 전체를
다 본 판마다 쌓이니, 스캔을 건 지 얼마 안 됐으면 「거기까지 안 닿는다」로 선다.

## 걸고 · 보고 · 끈다

주기의 기본은 새 메일 · 메일함 전체가 따로 있고 값은 `register --help` 가 댄다 — 메일 서버가 사람이 웹메일을 가끔 여는 정도의 부담만 받게 잡은
값이다. 사용자가 다른 주기를 청하시면 `--every <분>` · `--full-every <분>` 으로 준다(메일함 전체 주기는 다 못 본 판을 잇는 기한보다 짧아야
걸린다). 걸고 나면 걸린 주기 · 마지막 판을 말씀드린다.

걸기 · 끄기는 작업 스케줄러를 바꾸는 일이라 사용자가 청하신 때만 한다. 보통은 일일 보고(스킬 daily-brief)가 사용자의 첫 「보고해 줘」에서
스캔 · 아침 보고 · 업무 파일을 사람 없이 고쳐 쓰는 것을 한 번 설명하고 확인받은 자리에서 `register --brief-at` 을 부른다 — 그 확인이 사람 없는
아침 보고의 미리 받은 승인이다. 먼저 `--dry-run` 으로 무엇이 걸리는지 보여 드려도 된다. 작업은 로그온한 사용자의 세션에서만 창 없이 돌고,
앞 판이 도는 동안 온 주기는 건너뛴다.

## 아침 보고를 함께 건다

「아침 보고도 사람 없이 돌려 줘」에는 `register --brief-at <시각>`(기본 07:30 · 서울)을 부른다. 작업은 스캔 하나뿐이다 — 그 시각
뒤 스캔 판이 사내 세션이 살아 있는 것을 보면 일일 보고(스킬 daily-brief)를 사람 없이 한 번 띄우고, 그날의 보고 창과 보고 글이 사용자 폴더에
남는다. 시각만 바꾸실 때는 `brief --at`, 보고만 내리실 때는 `brief --off` 이고 `unregister` 도 내린다. 걸기 전에 `--dry-run` 이 띄울 명령 ·
열린 명령 · 막은 명령을 보인다.

- **스캔은 로그인하지 않는다** — 그 시각부터 5분 넘게 띄어 하루 세 번까지 사내 세션을 살펴보고, 세 번 다 없으면 그날 보고는 건너뛴다.
  `status` 의 「오늘」 줄이 띄웠나 · 안 띄웠으면 왜 · 살펴본 때를 댄다. 건너뛰었다는 줄은 그대로 전하고, 대화에서 스킬 ep-login 으로 EP 로그인을
  하신 뒤 보고를 청하시면 대화에서 짓는다
- **띄운 보고는 업무 파악부터 한다** — 업무 파악(스킬 mailbox-work)으로 업무 파일을 그날까지 고친 위에서 보고를 짓는다. 업무 파일 `work.md` 는
  그 스킬의 쓰는 손(`work.py write`)으로만 쓴다 — 띄운 보고에는 파일을 쓰는 도구가 없다
- **띄운 보고는 읽는 명령만 연다** — 열린 것은 손의 읽는 명령 · 이 스킬의 읽는 명령 · 보고 창 · 업무 파일의 쓰는 손이다. 메일함 · 일정을
  바꾸는 명령, 내보내는 명령, 파일을 받아 쓰는 명령(첨부 · 본문 그림), 문서함(ECM), EP 로그인은 막혀 있다. 문서함을 가리키는 첨부는 보고
  글에 「첨부는 대화에서 여실 것」으로 남는다
- **claude 명령줄이 있어야 건다** — 못 찾으면 걸지 않고 그렇다고 말한다. VS Code 확장만 깐 PC 면 확장 폴더의
  `resources/native-binary/claude.exe` 를 `--claude` 로 줄 수 있다

## 이 스킬이 안 하는 것

메일함을 바꾸지 않는다(읽음 표시도) · 스캔 판은 모델을 부르지 않는다(아침 보고는 띄우고 기다리지 않는다) · 본문을 받지 않는다 · EP 로그인을
하지 않는다 · 청함인가 · 기한 · 누구
차례 · 무엇이 중요한가를 가르지 않는다 — 그것은 읽는 쪽(모델)의 몫이다. 「지울 만하다 · 죽은 폴더」 같은 딱지도 안 붙인다 — 셈은 색인이다.
휴지통의 수는 손에 목록 명령이 없어 모른다.
