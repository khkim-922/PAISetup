## 견준 표준

- **Chrome DevTools Protocol** — 브라우저 자리의 `Storage.getCookies` · `Storage.setCookies` · `Target.createTarget`(`background`) ·
  `Target.closeTarget`. 받는 손이 탭에 안 붙고 쓰는 도메인이다(chromedevtools.github.io/devtools-protocol)
- **Chrome 136 의 디버깅 포트 바꿈** — 기본 데이터 폴더에는 `--remote-debugging-port` 를 안 받고 `--user-data-dir` 이 들어야
  한다(developer.chrome.com/blog/remote-debugging-port). Edge 는 공지가 없고 같은 증상의 사용자 보고가 있다
  (learn.microsoft.com 의 Q&A 「Microsoft Edge Remote Debugging is Not Working When Using the Default User Profile」). 입구(`scripts/ep_login.js`)는 늘 따로 사는 프로필로 띄워 이 선에 안 걸린다
- **RFC 6265** — 받는 손이 SSO 넘김을 따라갈 때 쿠키를 싣고 받는 규칙(도메인 · 경로 · 만료)
- **Windows UI Automation** — .NET `System.Windows.Automation` 의 InvokePattern(단추 누르기). 포트 없는 평소 Edge 를
  보는 눈(`scripts/ordinary_edge.ps1`)이 쓴다(learn.microsoft.com 「UI Automation Overview」)

## 잰 것 — 손의 꼴을 정한 측정

- **Playwright 의 `connectOverCDP` 로 붙지 않는다** — 2026-11-06 이 PC(Edge 146 · 검사처럼 임시 프로필)에서 쟀다. 듣는 손이 없으면
  붙어 있는 동안 사람의 탭에 뜬 확인 창을 「취소」로 닫았고(`answered:false`), 한 탭이라도 확인 창을 띄운 채면 붙기 자체가 시한
  (5초 · 15초)까지 멈췄다. 브라우저 자리의 웹소켓(`Storage.getCookies`)은 같은 판에서 0.2초에 끝났고 그 확인 창은 그대로 떠 있었다.
  사내 화면은 확인 창을 띄운다(ECM 의 「세션이 종료되었습니다」 · SSO 의 「EP 접속 정보」) — 그래서 받는 손은 브라우저 자리에만 붙는다
- **136 의 선** — Chrome 은 136 부터 기본 데이터 폴더에 디버깅 포트 플래그를 안 받는다고 공지했다. Edge 의 공지는 없고 같은 증상의
  사용자 보고만 있다. 잰 회사 자리의 판은 데스크톱 131 · VDI 107 이다(mail-secretary 결정 0009 · 0023). 판은 깔린 폴더 이름으로 못
  가린다 — 회사 데스크톱의 Application 폴더에 아직 적용 안 된 업데이트의 판 폴더(143)가 도는 판(131)과 함께 있었다. 띄우는 손이
  늘 따로 사는 프로필로 띄우는 까닭 하나다 — 판을 가리지 않아도 포트가 선다
- **입구가 붙는 자리** — 로그인 탭 하나의 페이지 자리에만 붙는다. 브라우저 자리에 자동 붙기를 걸면 로그인 도중 SSO 가 여는 팝업
  (사내 SSO 의 ssoframe 페이지)이 디버거를 기다리며 멈추고, EP 가 빈 화면에 선다 — 회사 데스크톱에서 그렇게 멈췄다
- **따로 사는 프로필의 창으로 로그인하면 메일이 서로를 끊는다** — 그 로그인이 「EP 접속 정보」로 같은 사람의 다른 세션을 끊고, 사람이
  다시 로그인하면 받아 둔 쿠키도 죽는다. 입구는 이 대가를 지고 그 창으로 띄운다 — 평소 Edge 의 세션을 빌리려면 떠 있는 Edge 를 끝내고
  포트로 다시 띄워야 하는데, 그러면 사람의 창 · 탭 · 쓰던 글이 한꺼번에 닫힌다. 끊기는 것은 메일(Domino)이다 — 2026-11-09 회사
  데스크톱(Edge 131)에서 따로 사는 프로필의 Edge 를 포트 9223 으로 띄워 통합 인증으로 로그인하니, 새 창은 메일 · ECM 이 다 섰고
  평소 Edge 는 EP 포털 · ECM 은 그대로인데 메일만 로그인이 풀렸다(쓰던 메일은 임시보관함에 남았다). 앞서 받은 평소 Edge 의 세션 파일도
  메일 서버가 거절했다

- **사람이 평소 Edge 에서 한 로그인이 먼저 있어야 파수 에이전트에 물린 것(문서함의 DRM 문서 열기)이 선다** — 쓰는 사람이 회사 PC 에서
  겪어 알린 것이다(2026-11-19). 평소 로그인 없이 디버깅 포트 창의 로그인만 먼저 하면 DRM 문서를 하나도 못 열었고, 평소 로그인을 먼저
  한 뒤 디버깅 포트 창으로 로그인하면 그 뒤로는 문제없이 돈다. 뒤 로그인이 앞 로그인을 끊으면 평소 Edge 의 EP 포털과 메일이
  죽고 문서함 같은 나머지는 산다 — 위 2026-11-09 판은 EP 포털도 살았다고 적어 어긋난다(어느 쪽이 늘 맞는지는 모른다). 그래서 차례는 「사람의 평소 로그인 → 디버깅 포트 창 로그인」이다. 확인한 것은 문서함까지이고 다른 사내 앱(MES 따위)은
  모른다. 까닭은 안 쟀다 — 로그인 하나가 웹 세션과 이 PC 의 프로그램 로그인 둘을 하는데 디버깅 포트 창은 앞엣것만 하는 것으로 보인다
  (추정). 입구의 `--trace` 가 그것을 가른다(아래)
- **「EP 접속 정보」 창은 어디든 산 세션이 있을 때 뜬다** — 쓰는 사람이 겪어 알린 것이다(2026-11-19). 밤에 VDI 에서 일한 다음에는 회사 PC 의
  로그인에 그 창이 늘 뜨고, 회사 PC 만 쓸 때는 창 없이 바로 선다. 그래서 그 창은 「다른 자리에 세션이 살아 있다」까지만 말하고, 이 PC 의
  평소 Edge 에서 사람이 오늘 로그인했다는 뜻은 아니다

평소 Edge 를 포트 없이 보는 눈(2026-11-19 · 이 PC · Edge 157 한국어판 · 디버깅 포트 없이 띄운 버리는 프로필 — 쓰는 사람의 Edge 는 안 열었다):

- **물음 창은 UI 자동화에 보이고 첫 단추가 「확인」이다** — `confirm()` 창은 브라우저 창 바로 아래(깊이 2)의 「<호스트>의 메시지」 이름의 창
  (RootView)이고, 그 안에 `JavaScriptTabModalDialogViewViews` · 글(Label) · 단추 「확인」 · 「취소」가 이 차례로 선다. 첫 단추를 Invoke 하니
  페이지의 confirm 이 true 를 받았다(창이 앞에 안 와도). 창이 떠 있는 동안은 브라우저의 나머지(주소창 · 탭 줄)가 UI 자동화에 안 보이고, 닫히면
  다시 보인다
- **화면 밖에 둔 창의 물음 창도 UI 자동화가 보고 누른다** — 2026-11-20 같은 버리는 프로필을 `--window-position=-32000,-32000` 으로 띄우고(창의 자리
  −32768,−32768 · 1701×1415) 입구처럼 둘째 `msedge.exe` 로 주소를 넘기니, `ordinary_edge.ps1` 이 첫 look 에 「localhost:…의 메시지」 창을 단추 둘로

- **앞 탭이 바뀌면 다른 탭의 물음 창은 닫힌다** — 새 프로필이 처음 뜰 때 정책 확장의 설치 안내 탭이 앞으로 나오자, 다른 탭에 떠 있던 confirm 을
  Chromium 이 「취소」로 닫았다. 검사의 대역 Edge 는 확장을 끄고(`--disable-extensions`) 띄운다
- **떼지 않고 띄운 Edge 는 15초쯤에 스스로 끝난다** — node 에서 `spawn` 을 떼지 않고(`detached` 없이) 띄운 버리는 프로필의 Edge 가 15초쯤에 종료 0 으로
  끝났고, 뗀 것은 2분 넘게 살았다. 입구가 평소 Edge 에 주소를 넘기는 것도 늘 뗀다
- **바깥에서 주소창 · 탭으로 「로그인이 넘었다」를 가리는 것은 흔들렸다** — 주소창(`OmniboxViewViews`)과 탭 줄을 0.2초마다 읽어 로그인 화면에서 회사
  화면으로 옮겼나를 가린 판을 같은 가짜로 여러 번 돌리니, 넘김이 보기 사이에 다 지나가거나 · 창의 UI 자동화 나무가 브라우저 칸 없이 페이지들만
  세우거나 · 새로 뜬 Edge 가 몇 초 동안 주소창을 안 내놓아 판마다 갈렸다. 이것은 탭을 연 직후 몇 초 안의 **넘어감**을 잡으려던 읽기다 — 이미 선
  탭이 무엇인가를 읽는 것(아래 줄)과는 다른 잼이다. 남는 교훈은 하나다 — 한 번 읽은 것으로 정하지 않는다(입구는 여러 번 잇달아 같아야 믿는다)
- **이미 선 탭은 바깥에서 고르게 읽힌다** — 2026-11-20 이 PC(사외 VDI · Edge 157)에서 버리는 프로필을 디버깅 포트 **없이** 화면 밖(-32000)에 띄우고

  `OmniboxViewViews`)의 ValuePattern 값으로 왔다 — 한 번에 0.36초쯤, 잇달아 세 번 같았다(맡긴 쪽이 잰 판 · 탐침은 저장소에 안 남겼다). 입구의
  눈(`ordinary_edge.ps1` 의 `tabs`)이 이 둘을 읽는다
- **탭의 이름 끝에 Edge 가 메모리 사용량을 붙이는 때가 있다** — 2026-11-21 이 PC(Edge 157 · 한국어)에서 버리는 프로필의 대역 창 하나에 탭
  다섯을 연 채 `TabItem` 이름을 떠 보니, 같은 판 차례에서 열두 판 가운데 다섯 판은 `EP 포털 - 메모리 사용량 - 47.6 MB` · `localhost:4802/mark
  - 메모리 사용량 - 21.3 MB` 처럼 모든 탭에 꼬리가 붙었고, 나머지는 `EP 포털` 처럼 제목만 왔다. 꼬리가 붙은 판에서 제목을 통째로 견주면 있는 포털
  탭을 「없다」로 읽어 포털을 또 연다. 눈은 그 꼬리(` - <낱말> - <수> KB|MB|GB`)를 떼고 견준다. 영문판의 꼬리 꼴(` - Memory usage - …`)은 안
  쟀다 — 같은 꼴이라 보고 같은 식으로 뗀다

  `Chrome_RenderWidgetHostHWND` 가 셋 선 판 · 문서 둘과 글 둘만 잡혔다). 같은 때 창 바로 아래 BrowserRootView 에서 찾으니 자손 55 개가 다 있었고 주소창도
  읽혔다. 판마다 갈렸다(같은 차례에서 서기도 안 서기도 했다). 눈은 BrowserRootView 에서 찾는다. 앞의 줄(물음 창 누르기가 전체 판에서 「못 봤다」)의

  판이 여럿이었지만, 전체를 돈 한 판에서는 틈 안에 그 창을 못 봤다(「못 봤다」). 2026-11-20 대역을 화면 밖에 두고(사람이 창을 닫을 일이 없다)
  다시 쟀다 — 그 판정만 돌면 평소 걸음 1.1초쯤에 눌렀고, 전체를 돈 세 판은 다 「못 봤다」였다. 못 본 판에서 4초째 대역 창의 UI 자동화 나무를 떠 보니

  갈랐다. 그래서 누르기는 영구 판정으로 안 두고 사람 자리 한 판과 회사 줄이 잰다

  붙어 로그인 주소로 넘기는 것은 about:blank 이니, 로그인 뒤에 남는 것은 그 새 탭이다. 새 프로필은 0.9초쯤에 `edge://sync-confirmation-dialog/`
  (계정 동기화 물음)가 따로 섰다
- **VDI 에서 사람이 한 판 봤다** — 닫혀 있던 ep-login 창으로 로그인하니 함께 뜬 빈 창이 로그인 뒤 닫혔고, 「EP 접속 정보」 창은 입구가 받아 사람 손 없이
  넘어갔다(그 창이 뜬 주소는 안 적었다). 그 뒤 사람이 EP 에서 로그아웃해도 받아 둔 세션은 살아, 다음 부름이 창을 안 띄우고 세션 파일로 돌았다 —
  EP 로그아웃은 그 브라우저의 로그인을 끝낼 뿐 받아 둔 메일 세션을 끊지 않는다(어느 창에서 로그아웃했는지는 안 적었다). 평소 Edge 에서 먼저 로그인한
  판이라 DRM 문서는 열렸다 — ep-login 창만 로그인한 판은 이 판에 없다

## 회사에서 잴 것 — 가짜로는 못 잰다

회사 PC 에서 한 판씩 잰다. mail-secretary 의 회사 확인 대장(#28)이 Node 판 · 136 판 · SSO 만 선 Edge 에서 Domino 따라가기를 들고,
아래 줄들은 아직 거기 없다.

- 조용한 ECM 받기가 못 따라갈 때 `--ecm-tab` 이 서나
- ep-login 창(따로 사는 프로필)이 평소 Edge 가 떠 있는 데스크톱 · VDI 에서 포트를 열고 통합 인증 · 평소 EP 로그인으로 서나 · 디버깅
  포트로 뜬 Edge 와 같이 못 도는 사내 앱이 그 창에도 걸리나
- 데스크톱에서 통합 인증이 안 서는 자리(입력 칸 있는 로그인 화면에 머무는 판)를 입구가 평소 EP 로그인 화면으로 넘기는 시한(`SESSION_FALLBACK_SECONDS` · 기본 8 초)이 실물
  통합 인증의 넘김보다 넉넉한가
- 포트가 열렸는데 로그인이 끊긴 Edge 에 `/json/new`(PUT)로 로그인 탭을 여는 것이 데스크톱 131 · VDI 107 에서 서나
- 끊긴 세션에 Domino 의 세션 확인 주소(`checksessionstatus`)가 무엇을 답하나 — 산 답 `{"status":"login"}` 만 쟀다
- 실물 「EP 접속 정보」 창(데스크톱 · Edge 131)은 `confirm` 이고 글에 「다른 PC에서 EP 접속 정보」가 들며(띄어쓰기는 보통 공백),
  로그인 화면(`swpsso.posco.net/idms/U61/jsp/login/VDI_loginProc.jsp`) 안의 틀 `swpsso.posco.net/idms/U61/jsp/manysession.jsp` 에서
  통합 인증이 넘자마자 뜬다 — 뜬 주소가 로그인 경로 밖이라 받을 창은 로그인 화면 호스트로 가린다. 입구가 붙기 전에 뜬 창은 붙은 뒤의
  `Page.enable` 이 다시 알리지 않는다(쟀다). 빈 탭에 먼저 붙고 호스트로 가리는 입구가 그 창을 받나는 입구 한 판(`login.sh` 를 다른
  자리에서 로그인해 둔 채)의 경과 줄 「「EP 접속 정보」 창을 「확인」으로 받았다」로 잰다. VDI 에서 그 창이 뜨는 주소는 안 쟀다
- 사람 없는 부름(`--unattended`) — 메일함 스캔의 작업이 창 없이 부른 자리에서 ep-login 창이 사람의 화면에 뜨고 통합 인증이 넘나 · 화면이
  잠긴 채(출근 전)에도 넘나 · 그렇게 뜬 창의 탭으로 아침 보고 창이 서나. 스캔의 `status` 「오늘」 줄이 「스스로 로그인했다」 · 「안 섰다」와
  입구의 끝말을 댄다
- 디버깅 포트 창의 로그인이 이 PC 의 프로그램에 무엇을 보내고 무엇이 막히나 — `bash login.sh domino --trace` 의 「trace …」 줄(이 PC 로
  간 요청 · 웹소켓 · 막힘 · 다른 프로그램으로 가는 넘김 · 화면 오류). 견줄 짝은 사람이 평소 Edge 에서 F12 → 네트워크 탭의 「로그 보존」을
  켜고 EP 에 로그인해 `127.0.0.1` · `localhost` · `ws` 로 거른 줄이다. 평소 Edge 에는 있고 디버깅 포트 창에는 없거나 막힌 줄이 까닭이다 —
  허락이 없는 새 프로필인가 · 디버깅 포트를 연 브라우저를 보안 프로그램이 거르나 · 입구가 타는 로그인 길이 그 화면을 안 지나나를 가른다
  (새 프로필 쪽은 두 창의 `edge://extensions` 를 견주면 보이고, 길 쪽은 입구가 EP 포털이 아니라 `COMPANY_LOGIN` 을 바로 여는 데서 갈린다)
- **회사 PC 에서 평소 Edge 의 탭 줄이 읽히나** — 입구는 사용자의 평소 Edge 에 EP 포털 탭이 있나를 윈도에서 읽는다. 평소 Edge 를 최소화한 채 ·
  다른 가상 데스크톱에 둔 채 · 다른 창 뒤에 둔 채 「EP 로그인 해 줘」라고 하고, 경과 줄이 「평소 Edge 에 EP 포털 탭이 이미 있다」(포털 탭을 둔 채면)나
  「EP 포털 탭이 없다」를 대나, 아니면 「평소 Edge 를 읽지 못했다」를 대나 본다. 못 읽었다면 그 창이 어떤 상태였는지를 적는다. VDI 에서도 한 번
- 메일 서버(`DOMINO_URL` 의 기본)가 사람마다 같은가

평소 Edge 를 먼저 여는 로그인 — 회사 데스크톱 · VDI 에서 한 판씩. 입구의 경과 줄(「평소 Edge …」)이 무엇을 보고 무엇을 했나를 댄다 — 어긋나면 그
줄들을 그대로 적는다(EP 의 두 화면 말고는 주소 · 제목을 안 낸다). 빈 탭 줄은 VDI 에서도 잰다. 첫 셋은 이 입구가 처음 도는 날 사용자가 겪는 그대로다:

- 이미 로그인해 둔 판 — 평소 Edge 에서 EP 에 로그인해 포털 탭을 둔 채 「EP 로그인 해 줘」라고 하면 평소 Edge 에 탭이 새로 안 열리고 경과 줄이 「EP
  포털 탭이 이미 있다」를 대나, 세션이 살아 있으면 창이 하나도 안 뜨나. 그 포털 탭을 다른 탭 뒤에 둔 채로도 한 번 — 첫 부름이 포털 제목을 배운
  뒤(경과 줄 「탭 제목을 배웠다」)라야 뒤쪽 탭도 알아본다
- 데스크톱 · 아직 안 한 판 — 아침에 로그온한 뒤 평소 Edge 를 열지 않은 채 부르면 평소 Edge 에 EP 탭이 하나 열려 통합 인증으로 넘어가고, 곧 경과 줄
  「EP 탭이 EP 포털로 넘어갔다」가 선 뒤 EP 로그인용 창이 로그인하나(30 초를 다 안 기다린다) · 그날 문서함의 DRM 문서 하나가 열리나(스킬 company-ecm
  으로 받아 스킬 drm-office-read 로 읽는다)
- VDI — 로그온한 뒤 처음 「EP 로그인 해 줘」라고 하면 평소 Edge 에 EP 탭 하나가 열리고, 거기서 평소 아이디로 로그인하면 대화에 「됐다」고 말하지
  않아도 EP 로그인용 Edge 창이 떠 거기서 한 번 더 치게 되나 · 그 뒤 DRM 문서 하나가 열리나

- 스스로 로그인한 아침에 문서함의 DRM 문서가 열리나 — 이 길을 지은 까닭이다. 스캔의 `status` 「오늘」 줄이 「스스로 로그인했다」인 날, DRM 문서 하나를 스킬 company-ecm 으로 받아 스킬 drm-office-read 로 읽는다. PC 를 끄고 켠 아침(빠른 시작으로
  끈 날도)에도 본다
- 평소 Edge 에 EP 포털을 열고 포털로 넘어가기를 보는 상한 30초(`SESSION_ORDINARY_SECONDS` · 탭을 못 읽는 PC 에서는 고정 틈)가 넉넉한가 · 곧바로 디버깅 포트 창으로 로그인하면 이 PC 의 프로그램 로그인을
  잃나 — 평소 Edge 에서 EP 에 로그인한 뒤 초를 세며 문서함의 DRM 문서를 열어 보고(5초 · 20초 · 1분), 같은 판을 넘어가자마자 `login.sh` 를 불러
  한 번 더 본다
- 한 로그온 안에서 이 PC 의 프로그램 로그인이 풀리나 — 평소 Edge 에 EP 포털 탭이 남아 있으면 입구는 다시 안 연다. 아침에 스스로 로그인한 날,
  오후에 DRM 문서가 여전히 열리나 본다
- EP 포털(`http://swp.posco.net/`)을 평소 Edge 에서 열면 데스크톱에서 통합 인증으로 입력 없이 넘나 · 그 주소가 http 인가 https 인가 — 그 탭이
  로그인 화면에 머물면 사람이 친다
- 작업 스케줄러가 부른 자리 · 화면이 잠긴 채(출근 전)에도 평소 Edge 가 뜨고 UI 자동화가 그 Edge 의 물음 창을 찾아 누르나 — 평소 Edge 가 안 떠
  있던 아침과 떠 있던 아침을 한 번씩. 잠근 채 `scan.py run --now` 를 띄우거나 보고 시각을 잠긴 때로 둔다
- 실물 「EP 접속 정보」 창이 평소 Edge 에서도 같은 꼴인가(제목 「swpsso.posco.net의 메시지」 · 단추 둘 · 글에 「다른 PC에서 EP 접속 정보」) — VDI 를
  쓴 다음 날 아침이 그 창이 뜨는 자리다. 경과 줄 「평소 Edge 의 「EP 접속 정보」 창을 바깥에서(UI 자동화) 「확인」으로 눌렀다」가 서면 맞다. 창이 떴는데
  경과 줄이 「못 봤다」면 그 창의 제목과 글을 적는다 — 그것이 실물의 꼴이다
- 로그온 열쇠 — 평소 Edge 를 못 읽는 PC 에서, 빠른 시작으로 끄고 켠 PC · 다시 시작한 PC · 로그오프 뒤 다시 로그온한 PC 의 첫 부름이 평소
  로그인을 다시 묻나(탐색기가 뜬 때가 바뀌나). 잠금 · 절전에서 깬 뒤에는 안 묻는 것이 맞다
- 닫혀 있던 ep-login 창으로 로그인한 뒤 그 창에 빈 탭이 남나 · 경과 줄이 「「EP 접속 정보」 창을 「확인」으로 받았다」를 그대로 냈나 — 남았으면
  그 탭의 주소(about:blank · edge://newtab · 그 밖)를 적는다. 입구는 로그인 뒤 띄운 창의 about:blank · edge://newtab 탭을 닫고 「띄운 창에 남은 빈
  탭 N 개를 닫았다」를 낸다
- 회사 정책이 `powershell -ExecutionPolicy Bypass -File` 을 막지 않나 — 막으면 입구가 경과 줄 「평소 Edge 를 보는 눈 … 이 안 선다」를 내고,
  EP 포털은 연 채 확인 창만 못 누르고 디버깅 포트 창으로 이어 간다
