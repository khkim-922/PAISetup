# 세션 손

**회사 PC 의 스크립트 · 스킬이 사내 앱(메일 · 일정 · 다른 Domino 앱 · ECM)을 부를 때 쓸 세션 쿠키를, 쓰는 사람의 Edge 에서 받아
파일로 남기는 손과 그것을 무는 검사다.**

- **받는 손** `edge_session.js` — 디버깅 포트로 떠 있는 Edge 에 붙어 그 Edge 의 사내 세션 쿠키를 세션 파일로 남긴다. 새로
  로그인하지 않고 창 · 탭을 열지 않아 사람의 세션도 화면도 안 건드린다. 그래서 사내 앱을 다루는 손은 **세션 파일을 읽기 전에
  매번 이 손을 인자 없이 부르고, 종료 0 의 끝 줄에서 세션 파일의 경로를 읽는다** — 세션 파일의 기본 자리는 이 손에만 있다. 3 이면
  사람에게 스킬 ep-login 을 가리키고, 2 면 끝 줄에 남은 파일의 경로가 있을 때 그 파일을 써 보고 서버가 안 받을 때만 가리킨다.
  메일함 주소 없이도 선다(일정 · ECM 이 부르는 꼴). ECM 쿠키는 없거나 서버가 안 받을 때만 SSO 넘김 주소를 이 손이 따라가 받는다
- **띄우는 손** `edge_start.js` — 쓰는 사람의 Edge 를 디버깅 포트(127.0.0.1 에만)로 **EP 로그인 탭 하나와 함께** 띄우고, 그 탭의
  로그인을 한 번 넘긴다(로그인 화면의 「EP 접속 정보」 확인 창만 받고 탭이 EP 로 넘어가면 떨어진다). 띄운 창은 사람이 그대로 쓴다.
  포트가 이미 열려 있으면 아무것도 안 띄운다. 이미 포트 없이 도는 Edge 는 닫지 않고 「닫아 달라」로 끝난다. 기본 프로필로 띄웠는데
  포트가 안 열리는 판(Chromium 136 부터)만 `--profile` 로 다시 부른다
- **파이썬에서 부르는 자리** `ep_session.py` — 받는 손을 돌려 종료 값 · 세션 파일 · 손의 말을 닫힌 꼴 하나로 낸다. 사내 앱 스킬의
  얇은 명령 셋이 이 폴더를 `sys.path` 에 넣고 싣는다 — 받는 손의 계약을 읽는 코드가 이 한 자리다
- 부르는 꼴 · 종료 값 · 무엇을 파일에 남기나 · 환경변수는 세 파일의 머리말이 든다 — 여기 옮겨 적지 않는다

대화에서 쓰는 절차는 스킬 `ep-login` 이 든다. 이 폴더는 그 스킬과, 형제 폴더의 사내 앱 스킬(company-mail · company-calendar ·
company-ecm)과, 깔린 자리에서 불러 쓰는 앱이 함께 쓰는 손이다. 복사해 쓰는 밑판이 아니라 불러 쓰는 손이라, 공개 이름과 꼴(부르는
꼴 · 종료 값 · 세션 파일의 꼴)을 바꾸면 부르는 쪽이 다 깨진다. 바꿀 때는 아래 「돌려 보기」를 돌고, 부르는 스킬 · 앱을 같은 판에 고친다.

## 왜 이 길인가

새 브라우저로 사내 SSO 를 넘으면 SSO 가 「다른 PC에서 EP 접속 정보가 있어 안내드립니다」 창을 띄우고, 「확인」이면 쓰는 사람의
Edge 세션이 끊긴다. 사람이 다시 로그인하면 받아 둔 쿠키도 죽는다 — 한쪽이 늘 끊긴다. 쓰는 사람의 Edge 를 디버깅 포트로 띄우고
그 세션을 빌리면 둘 다 산다. 회사 데스크톱 · 사외 VDI 에서 잰 근거와 버린 길은 mail-secretary 의 결정 0009 · 0023 이 든다 — 이
폴더의 받는 손은 그 저장소 secretary/edge_session.js 의 꼴을 따라 지었고(아래 「빌린 것」), 새 창을 띄우는 옛 로그인 손은
`--launch` 갈래로 들어왔다.

## 사람이 하는 몫

받는 손은 사람이 띄운 Edge 에 붙기만 한다. 그 Edge 를 포트로 세우는 것과 로그인은 사람의 몫이고, 스킬 ep-login 이 대화에서
이끈다 — 영속 PC(한 번 세우면 남는다 · 비서 앱이 깔린 PC 는 그 상주가 로그온 때 띄운다)와 비영속 VDI(로그온마다 Edge 를
알림 영역까지 다 닫고 포트로 다시 띄워 한 번 로그인한다)로 갈린다.

## 세션 파일

- 자리 — 받는 손 머리말의 기본 자리(홈). 부르는 쪽은 그 값을 옮겨 적지 않고 받는 손의 끝 줄에서 읽는다. 자리를 바꾸려면 경로를
  인자로 주거나 `MAILBOX_COOKIES` 를 둔다. git 저장소 안의 자리는 받는 손이 거절한다
- 꼴 — Playwright 저장 상태(`{"cookies": [...], "origins": []}`). 회사 도메인의 쿠키만 든다. 메일 · 일정의 `.posco.net` 쿠키와
  ECM 의 `swpecm` 쿠키가 함께 들 수 있고, 읽는 쪽은 호스트로 골라 쓴다
- ⚠ 사내 앱의 열쇠다 — 남에게 넘기지 않는다. 다 쓴 PC · 남에게 넘길 PC 에서는 지운다. 비영속 VDI 는 로그오프 때 홈과 함께 사라진다.
  쿠키는 다 세션 쿠키라 Edge 의 SSO 세션이 끝나면(로그아웃 · 다른 자리에서 다시 로그인) 함께 죽는다

## 돌려 보기

```bash
node check_session.js            # 이 폴더의 edge_session.js 를 잰다 — 가짜 SSO · 메일함 · ECM 과 검사가 띄운 Edge(임시 프로필 · 창 없음)
node check_session.js <폴더>     # 다른 폴더의 사본을 잰다
```

끝 줄이 「통과 N/N」이면 선 것이다. 쓰는 사람의 Edge 에는 붙지 않고 127.0.0.1 · localhost 밖으로 안 나간다. Node 22 이상 · Edge
가 들고, `--launch` 판은 전역 playwright(`npm i -g playwright`)를 쓴다 — 받는 손이 `npm root -g` 로 찾는다. `ep_session.py` 는
`check_mail.py`(스킬 company-mail)가 대역 손으로 잰다. 가짜로 못 재는 것은 아래 「회사에서 잴 것」이다.

## 잰 것

- **Playwright 의 `connectOverCDP` 로 붙지 않는다** — 2026-11-06 이 PC(Edge 146 · 검사처럼 임시 프로필)에서 쟀다. 듣는 손이 없으면
  붙어 있는 동안 사람의 탭에 뜬 확인 창을 「취소」로 닫았고(`answered:false`), 한 탭이라도 확인 창을 띄운 채면 붙기 자체가 시한
  (5초 · 15초)까지 멈췄다. 브라우저 자리의 웹소켓(`Storage.getCookies`)은 같은 판에서 0.2초에 끝났고 그 확인 창은 그대로 떠 있었다.
  사내 화면은 확인 창을 띄운다(ECM 의 「세션이 종료되었습니다」 · SSO 의 「EP 접속 정보」) — 그래서 받는 손은 브라우저 자리에만 붙는다
- **136 의 선** — Chrome 은 136 부터 기본 데이터 폴더에 디버깅 포트 플래그를 안 받는다고 공지했다
  (developer.chrome.com/blog/remote-debugging-port). Edge 의 공지는 없고, 같은 증상의 사용자 보고만 있다(Microsoft Q&A). 잰 회사
  자리의 판은 데스크톱 131 · VDI 107 이다(mail-secretary 결정 0009 · 0023). 판은 깔린 폴더 이름으로 못 가린다 — 회사 데스크톱의
  Application 폴더에 아직 적용 안 된 업데이트의 판 폴더(143)가 도는 판(131)과 함께 있었다. 그래서 띄우는 손은 판을 묻지 않고 띄워
  본 결과(포트가 열리나)로 가른다
- **띄우는 손이 붙는 자리** — 띄운 탭 하나의 페이지 자리에만 붙는다. 브라우저 자리에 자동 붙기를 걸면 로그인 도중 SSO 가 여는 팝업
  (사내 SSO 의 ssoframe 페이지)이 디버거를 기다리며 멈추고, EP 가 빈 화면에 선다 — 회사 데스크톱에서 그렇게 멈췄다

## 회사에서 잴 것

가짜로는 못 잰다 — 회사 PC 에서 한 판씩(mail-secretary 의 회사 확인 대장 #28 이 줄을 든다).

- 데스크톱 · VDI 의 Edge 에서 `edge_session.js` 가 종료 0 이고, 같은 판에 ECM 쿠키(`swpecm` 의 `JSESSIONID`)까지 받나 — 조용한
  ECM 받기가 실물 넘김(SSO `redirect.jsp?redir_url=<맥락>/index.jsp` → `index.jsp`(POST · `ssoToken`) → `login.do…&USE_WEBSOCKET=F` → 메인)을 따라가나, 못 따라가면 `--ecm-tab` 이 서나
- 받은 뒤 사람의 Edge 에서 ECM · EP 가 그대로 도나(손이 되쓴 쿠키가 사람의 세션을 안 흔드나)
- SSO 만 서고 메일함에 한 번도 안 들른 Edge 에서 Domino 가 따라가기로 서나
- 메일함 주소 없이 부를 때의 Domino 확인 — 세션 확인 주소가 끊긴 세션에 무엇을 답하나(산 답 `{"status":"login"}` 만 쟀다) · 메일
  서버(`DOMINO_URL` 의 기본)가 사람마다 같은가
- 기본 프로필의 136 선 — Edge 136 이상 PC 에서 `edge_start.js` 없이 기본 프로필을 포트로 띄워 포트가 열리나 · `--profile` 로는 서나
- 회사 PC 의 Node 판(22 이상인가)
