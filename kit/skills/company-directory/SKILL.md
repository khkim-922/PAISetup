# 사람은 주소록에서 한 번 찾아 파일로 넘긴다

```bash
python -X utf8 -I "<이 스킬>/scripts/directory.py" find …     # 출처 · 거르기 · 보기의 지도는 find --help

# 흔한 걸음 — 이대로 친다(<…> 만 채운다)
python -X utf8 -I "<이 스킬>/scripts/directory.py" find --name "<이름>" --out "<임시 폴더>"   # 한 사람 · 여럿(「김철수 · 이영희」 그대로)
python -X utf8 -I "<이 스킬>/scripts/directory.py" find --dept "<부서>" --grade "<직급>" --out "<임시 폴더>"   # 부서에서 거른 사람들(산하 전체는 --sub)
python -X utf8 -I "<이 스킬>/scripts/directory.py" find --boss-of "<이름>" --out "<임시 폴더>"   # 그 사람의 윗사람
```

**찾은 사람은 받는 손까지 한 번의 셸 부름에 `&&` 로 잇는다** — `find … --out D && <일정 · 회의실 · 문서함 손> … --people-file D/people.json`, 메일이면 그 손의 `who … --out D && draft new … --to-file D/to.txt`. `find` 가 0 이 아닌 값으로 멈추면 뒤는 안 돈다. 끊는 것은 후보 가운데 누구인지 골라야 할 때뿐이다.

사내 사람의 원본은 주소록 하나다. 읽기만 한다. 한 사람은 어느 손에서나 같은 사람이어야 해서, 사람은 여기서 한 번 찾고 그 파일을
다른 손에 그대로 넘긴다 — 이름이나 주소를 손으로 옮겨 적지 않는다(한 줄이 빠지거나 동명이인이 바뀌어도 아무도 모른다). 0 이 아니면
메시지가 까닭과 다음 걸음을 드니 그 말대로 간다. 회사 사내망 안의 PC 가 전제다.

## 말을 출처 · 거르기로 옮긴다 — 한 부름에

사람이 어떻게 말하든 `find` 한 번이다. 출처 아무 조합에 거르기 · 빼기를 함께 주면 합친 명단 전체에 걸린다.

- **누구에서 출발하나** — 이름 · 주소(`--name`, 메일 머리의 사람은 주소 · `CN=` 이름 그대로), 부서(`--dept`, 「산하 전체」면 `--sub`),
  나(`--me`), 내 부서(`--my-dept`), 「○○ 님의 윗사람 · 팀장님」(`--boss-of ○○`), 배포그룹 구성원(`--group`), 회사 전체(`--all`),
  다른 손이 낸 사람(`--from-file` — 일정 · 회의실이 낸 참석자 줄의 JSON, 앞서 쓴 사람 파일, 이름 한 줄씩 적은 글)
- **누구만 남기나** — 「과장」은 직급(`--grade`), 「리더 · 그룹장 · 실장」은 직책(`--title`), 「조직의 장」(`--boss`), 위아래는 인사
  등급(`--at-least P5` 가 「리더 이상」), 「포항 안전 담당」(`--match 포항 --match 안전`). 직급과 직책은 다른 칸이고 등급 「리더」(P5)와
  직책 「리더」도 다르다. 등급은 같은 갈래(직원 · 임원 P1–P10 · 현장 직군 E1–E7)끼리만 견준다 — `--at-least` 로 거르면 현장 직군과 등급
  없는 사람(연구직 · 소장 · 이사 · 외주직)이 다 빠지니, 그 사람들이 들어야 할 자리면 거르기 없이 부른 직급별 수를 보이고 묻는다
- **거르기 밖에 둘 사람**(「기획팀 과장 이상, 그리고 김 대리」)은 부름을 둘로 나눠 `--out` 폴더를 달리 한다
- **부서원인가, 조직 하나인가** — 부서를 체크한 뒤 몇 사람을 해제한 것이 부서원(`--dept`), 체크만 한 것이 조직 하나(`--org`)다. 말로
  안 갈리면 그 차이를 대고 묻는다
- 명단이 길면 답은 수만 온다 — 수를 묻는 물음은 거기서 답하고 명단은 필요할 때만 `--list`. 부서 나무는 `--tree`, 배포그룹 목록은 `--groups`
- 조직도는 받아 둔 판을 쓴다 — 첫 줄의 「조직도 ○○ 판」이 그 날짜다. 사람이 갱신하라고 하거나 방금 바뀐 인사가 안 보이면 `--fresh`
- 「전화번호」는 `--phone` 을 함께 준다(사람 열 명까지). 사규 앱의 사람 창에서 오고, 못 물으면 그 말이 서고 명단은 그대로다

## 고르는 것은 사람이다

명령이 낸 수 · 직급별 · 직책별 수와 명단을 사람에게 그대로 보이고, 사람이 그 명단을 확인한 뒤 넘긴다.
**「⚠ 따로 둔 것」이 서면 고르지 않고 묻는다** — 동명이인 · 못 찾은 이름 · 여럿 걸린 부서 · 거르기가 못 거는 조직 · 맨 위의 장이라
윗사람이 없는 사람은 파일에 안 들었다. 그 줄의 후보를 보이고, 사람이 고른 것을 그 줄이 댄 꼴로 다시 준다 — 동명이인은 후보마다
부서 길 · 최근 주고받은 메일과 「고르면 --name "이름[부서]"」 를 대니 그것을 그대로, 부서는 부서 코드, 배포그룹은 「직책:이름」 이다.
「이름[부서]」 는 한 글자 틀리면 다른 사람이 아니라 아무도 안 선다. 그 줄을 둔 채 넘기면 그 사람들이 빠진 채 메일 · 회의가 나간다.

## 넘긴다 — 파일을 그대로

`--out <저장소 밖 폴더>` 를 붙여 부르면 한 명단에서 파일 셋이 선다. 끝 줄이 각 손에 줄 인자를 그대로 댄다.

- **사람 파일 people.json** — 사람을 받는 손(일정의 다 비는 때 · 회의실 참석자 · 문서함 권한)에 `--people-file` 로 준다. 문서함 권한은
  줄 칸(`--people-as`)을 함께 준다
- **칸마다 주소 파일** — 메일 저장 명령에 「draft 에 그대로:」 의 인자를 그대로 준다(받는 사람 · 참조 · 숨은참조 칸 그대로)
- **people.txt** — 한 줄에 「이름/메일ID」 — 문서함 권한이 받는 꼴이다

조직 · 사외 주소는 사람이 아니라 사람 파일에 안 든다 — 명령이 「안 넣은 것」 으로 대니 사람에게 보이고 그 손에서 따로 준다.

메일의 「지난번과 같이」 · 「이 메일 받은 사람들로」는 메일함을 읽어야 서서 스킬 company-mail 의 `who --last` 가 든다 — 같은 출처 ·
거르기 · 파일에 지난 메일 하나를 더한 명령이다.
