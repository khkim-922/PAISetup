# Claude 에게 맡긴다 — 쓰기는 작업 자리 안만

부르는 길은 이 스킬의 래퍼 하나다. **Claude 는 이 대화를 모르니 프롬프트가 일의 전부다** — 무엇을 맡기고 어떻게
쓰나는 agent-envelope 가 든다.

**권한은 부를 때 일에 맞춰 고른다**(무엇을 줄지는 agent-envelope 3 절 「자료 · 도구」) — `--write` 를 안 주면 읽기 · 찾기 ·
웹 읽기 도구만 보이게 뜨고 셸 · 쓰기 도구는 없다 — 그때는 저장소를 통째로 가리켜도 된다. 고칠 것은 답으로 받아 맡긴 쪽이 고치거나, 아래 고치기 레인으로 맡긴다. MCP 서버 · 스킬 · 훅도 끄고 뜬다(리뷰 모드는 스킬을 켠다).

## 고치기 레인 — `--write`

고치기뿐 아니라 리뷰 · 재기처럼 돌려 보고 적어 봐야 하는 일에도 준다(agent-envelope 3 절). **받는 Claude 가 작업 자리(`--cwd`) 안만 고친다** — 편집 도구
둘(`Edit` · `Write`)이 더 보이되 허락은 그 자리 안에만 걸려, 밖에 쓰려는 호출은 거절되고 실패(1)로 남는다. 사람 설정의
허락 규칙은 어느 레인에도 안 넘어간다 — 래퍼가 그것만 빼고 넘겨, 레인의 울타리는 래퍼가 건 허락이 다다.

- **셸은 고치기 레인에도 없다** — 이 러너가 쥐는 「재 볼 손」은 사본에 적어 보기까지다. 명령을 돌려 재야 하는 리뷰는
  셸이 있는 쪽(Claude 서브에이전트 · Codex 고치기 레인)에 맡기고, 검사 돌리기는 맡긴 쪽이 한다. 윈도에는 Claude 샌드박스가 없어 셸이 자리를 못 지킨다
- **작업 자리를 따로 세워 `--cwd` 로 준다** — 본 트리를 주면 그 트리를 고친다. 작업 자리가 없으면 안 뜬다(4)
- **이어 물을 때도 `--write` 를 다시 준다** — 안 주면 같은 대화가 읽기 레인으로 이어진다
- 끝나면 맡긴 쪽이 그 자리의 diff 를 읽고 검사를 돌린다. 커밋 · 푸시 · 이슈는 맡긴 쪽이 한다

## 리뷰 모드 — `--review [대상]`

리뷰를 맡길 때 준다. 내장 리뷰 스킬(`/code-review`)을 `medium` 으로 부른다 — 후보마다 검증 에이전트가 맞나를 가르고, 0건도
답이다. 여는 것은 그 스킬이 드는 만큼이다: 스킬을 켜고, 셸과 검증 에이전트를 띄울 `Agent` 를 보인다. 셸에는 허락 규칙을
안 건다 — Claude Code 가 읽기로 가르는 명령(`git diff` · `git log` · `git show` · `git status` · `cat` · `grep` 같은)만 서고,
코드 돌리기 · 파일로 내보내기(`git diff --output=<파일>` 포함)는 거절된다. 사용자 설정의 허락 규칙(이슈 닫기 · 다른 레인
띄우기 같은)도 이 모드에서는 안 선다 — 래퍼가 사용자 설정을 허락 규칙만 빼고 넘긴다. 그 거절은 울타리가 한 일이라 이
모드에서는 실패로 안 치고 끝 줄 `denied=<도구>:<수>` 로 남긴다 — 리뷰어가 「돌려 보지 못했다」고 답에 적었으면 그 까닭이다.

- **모델은 `--model` 로 준다** — 안 주면 사용자 설정의 모델로 뜬다. 깊은 리뷰면 맡기기 모델 표의 모델을 준다
- **봉투는 프롬프트 파일 그대로 주면 래퍼가 시스템 프롬프트 덧붙이기로 넘긴다** — 슬래시 명령 뒤에 붙인 글은 리뷰 대상으로
  읽혀서다. 표준 입력은 래퍼가 짓는 `/code-review medium [--max-findings <n>] [대상]` 한 줄이다
- **대상은 그 스킬의 낱말이다** — PR 번호 · 가지 · 경로. 안 주면 지금의 diff 를 본다. 고치기 · 올리기 · 클라우드 리뷰
  (`--fix` · `--comment` · `ultra`)는 래퍼가 안 싣고, 대상 칸으로도 안 받는다(4)
- `--max-findings <n|all>` 은 리뷰 모드에서만 받는다
- **`--write` · `--resume` 과 같이 못 준다**(4) — 리뷰는 읽기만 하는 새 대화다. 답을 더 물을 때는 `--review` 없이 `resume=`
  값으로 잇는다(읽기 레인)

## 맡기는 법

1. **프롬프트를 UTF-8 파일로 쓴다**(임시 폴더). 길이는 자유다 — 래퍼가 표준 입력으로 넘긴다. PowerShell 5.1 이면
   `Set-Content -Encoding utf8` 로 쓴다 — 기본값(ANSI · `Out-File` 은 UTF-16)으로 쓴 파일은 래퍼가 4 로 돌려보낸다.
2. **콘솔 있는 `python` 으로 부르고 끝날 때까지 기다린다** — 명령의 시간 한도는 `--timeout` 보다 길게 준다.
   `pythonw` 는 창 없는 프로그램이라 셸이 안 기다리고 바로 돌아온다. agy 는 명령이 기다림(`WaitMsBeforeAsync`)을 넘기면
   뒤로 넘어가니, 그때는 그 작업이 끝날 때까지 상태를 보고 나서 `--out` 을 읽는다. 승인 건너뛰기 없이 뜬 헤드리스
   agy(`agy -p`)에서는 이 명령이 자동 거절된다 — 권한 설정을 고쳐 뚫지 말고 거절됐다고 알리고 멈춘다. 헤드리스로
   맡기는 길은 부르는 쪽이 `--dangerously-skip-permissions` 를 붙여 띄운 agy 뿐이다(`agy-background` 러너의 꼴 · 결정 0114).

   ```sh
   python "<이 스킬 폴더>/scripts/claude_bg.py" --prompt-file <프롬프트> --out <답 파일> --cwd <작업 자리> \
     [--timeout <초>] [--model <이름>] [--resume <id>] [--write | --review [대상] [--max-findings <n>]]
   ```

   **Codex 에서는 이 명령을 샌드박스 밖에서 돌린다** — 셸 도구 호출에 `sandbox_permissions: "require_escalated"` 와
   허락을 묻는 한 줄(`justification`, 예: 「Claude 에게 리뷰를 맡기려 망이 드는 러너를 샌드박스 밖에서 돌려도 될까요?」)을
   실어 승인을 받는다. 받는 Claude 는 망이 있어야 답하는데 Codex 의 `workspace-write` 샌드박스는 망을 닫아 둔다. 망만 열어도 그 안에서는 Claude 가 제 홈(`~/.claude`)에 대화 기록을 못 써
   이어 묻기가 안 선다. 이 길은 승인 정책이 `on-request` 일 때(앱의 기본 `Auto`) 있다 — 출처:
   [Codex 문서 「Agent approvals & security」](https://developers.openai.com/codex/agent-approvals-security)(망이 드는
   명령은 승인을 묻는다 · `workspace-write` 는 망이 꺼져 있다) ·
   [Codex 의 승인 요청 안내](https://github.com/openai/codex/blob/main/codex-rs/prompts/templates/permissions/approval_policy/on_request.md)
   (`require_escalated` · `justification`). 승인 정책이 `never` 인 자리(`codex exec` 기본)에서는 이 요청이 안 선다 — 그
   자리는 Codex 를 `-c sandbox_workspace_write.network_access=true` 로 띄워야 답이 오고, 그래도 이어 묻기는 안 선다.

3. **끝나면 `--out` 파일을 읽는다.** 윈도에서는 BOM 붙은 UTF-8 이라 PowerShell 5.1 의 `Get-Content` 가 인코딩을 안 줘도
   한글을 그대로 읽는다. 끝 줄 `[claude-bg] <갈래> …` 이 레인(`mode=read|write|review`) · 모델(`model=`) · 쓴 도구 수(`tools=`) ·
   토큰 · 이어 묻기 값(`resume=`)을 든다. 인자가 틀렸거나 러너가 멈췄어도 `--out` 을 줬으면 그 파일에 까닭과 끝 줄이 남는다.

   | 종료 코드 | 뜻 |
   |---|---|
   | 0 | 답이 왔다 |
   | 1 | 실패 — 거절된 도구 호출(리뷰 모드 밖) · 러너가 멈춘 것도 여기다. 끝 줄 위의 까닭과 `raw=` 경로를 본다 |
   | 2 | 한도 · 과부하 또는 빈 답 — 잠시 뒤 다시 맡긴다 |
   | 3 | 시간 초과 |
   | 4 | 부르는 법이 틀렸거나(프롬프트 파일이 UTF-8 이 아닌 것 포함) Claude Code CLI 가 없다 |

4. **이어 물을 때**는 끝 줄의 `resume=` 값을 그대로 `--resume` 으로 준다. 대화 기록이 안 남은 실행은 `resume=-` 에
   까닭을 달고 끝난다 — 그때는 새로 맡긴다.
5. **사실은 쓴 도구로 가린다** — `tools=` 에 읽기 · 검색이 없는 답은 기억으로 낸 것이다. 판 번호 · 날짜처럼 시점에 매인
   답은 근거를 맞춰 본 뒤에 쓴다.

## 자리

- Claude Code CLI(`claude`)가 이 PC 에 서 있어야 한다. 사외는 구독 로그인으로, 사내는 설치기가 심은 게이트웨이 값으로
  붙는다 — 래퍼는 사용자 설정을 읽어 그 값을 그대로 쓴다. 인증 실패로 멈추면 터미널에서 `claude` 를 한 번 띄워
  로그인하게 알린다
- 맡긴 대화는 Claude Code 의 대화 기록(`~/.claude/projects`)에 남는다 — 이어 묻기가 그 기록으로 서고, 래퍼는 그 기록이
  실제로 있을 때만 `resume=` 에 id 를 싣는다

## 작업 자리

- 조사만 시킬 때 `--cwd` 는 임시 폴더다. 읽힐 자료는 그 폴더에 두거나 자료 폴더를 `--cwd` 로 준다
