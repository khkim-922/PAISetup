# Claude 에게 맡긴다 — 기본은 읽기, 고치기는 작업 자리 안만

부르는 길은 이 스킬의 래퍼 하나다. **Claude 는 이 대화를 모르니 프롬프트가 일의 전부다** — 무엇을 맡기고 어떻게
쓰나는 agent-envelope 가 든다.

**기본은 읽기만 하니 저장소를 통째로 가리켜도 된다** — 읽기 · 찾기 · 웹 읽기 도구만 보이게 뜨고, 셸 · 쓰기 도구는 아예
없다. 고칠 것은 답으로 받아 맡긴 쪽이 고치거나, 아래 고치기 레인으로 맡긴다. MCP 서버 · 스킬 · 훅도 끄고 뜬다.

## 고치기 레인 — `--write`

봉투가 고치기를 맡기기로 골랐을 때만 준다(agent-envelope). **받는 Claude 가 작업 자리(`--cwd`) 안만 고친다** — 편집 도구
둘(`Edit` · `Write`)이 더 보이되 허락은 그 자리 안에만 걸려, 밖에 쓰려는 호출은 거절되고 실패(1)로 남는다.

- **셸은 고치기 레인에도 없다** — 검사 돌리기는 맡긴 쪽이 한다. 윈도에는 Claude 샌드박스가 없어 셸이 자리를 못 지킨다
- **작업 자리를 따로 세워 `--cwd` 로 준다** — 본 트리를 주면 그 트리를 고친다. 작업 자리가 없으면 안 뜬다(4)
- **이어 물을 때도 `--write` 를 다시 준다** — 안 주면 같은 대화가 읽기 레인으로 이어진다
- 끝나면 맡긴 쪽이 그 자리의 diff 를 읽고 검사를 돌린다. 커밋 · 푸시 · 이슈는 맡긴 쪽이 한다

## 맡기는 법

1. **프롬프트를 파일로 쓴다**(임시 폴더). 길이는 자유다 — 래퍼가 표준 입력으로 넘긴다.
2. **콘솔 있는 `python` 으로 부르고 끝날 때까지 기다린다** — 명령의 시간 한도는 `--timeout` 보다 길게 준다.
   `pythonw` 는 창 없는 프로그램이라 셸이 안 기다리고 바로 돌아온다. agy 는 명령이 기다림(`WaitMsBeforeAsync`)을 넘기면
   뒤로 넘어가니, 그때는 그 작업이 끝날 때까지 상태를 보고 나서 `--out` 을 읽는다.

   ```sh
   python "<이 스킬 폴더>/scripts/claude_bg.py" --prompt-file <프롬프트> --out <답 파일> --cwd <작업 자리> \
     [--timeout <초>] [--model <이름>] [--resume <id>] [--write]
   ```

3. **끝나면 `--out` 파일을 읽는다.** 끝 줄 `[claude-bg] <갈래> …` 이 레인(`mode=read|write`) · 모델(`model=`) · 쓴 도구 수(`tools=`) · 토큰 ·
   이어 묻기 값(`resume=`)을 든다.

   | 종료 코드 | 뜻 |
   |---|---|
   | 0 | 답이 왔다 |
   | 1 | 실패 — 거절된 도구 호출도 여기다. 끝 줄 위의 까닭과 `raw=` 경로를 본다 |
   | 2 | 한도 · 과부하 또는 빈 답 — 잠시 뒤 다시 맡긴다 |
   | 3 | 시간 초과 |
   | 4 | 부르는 법이 틀렸거나 Claude Code CLI 가 없다 |

4. **이어 물을 때**는 끝 줄의 `resume=` 값을 그대로 `--resume` 으로 준다.
5. **사실은 쓴 도구로 가린다** — `tools=` 에 읽기 · 검색이 없는 답은 기억으로 낸 것이다. 판 번호 · 날짜처럼 시점에 매인
   답은 근거를 맞춰 본 뒤에 쓴다.

## 자리

- Claude Code CLI(`claude`)가 이 PC 에 서 있어야 한다. 사외는 구독 로그인으로, 사내는 설치기가 심은 게이트웨이 값으로
  붙는다 — 래퍼는 사용자 설정을 읽어 그 값을 그대로 쓴다. 인증 실패로 멈추면 터미널에서 `claude` 를 한 번 띄워
  로그인하게 알린다
- 맡긴 대화는 Claude Code 의 대화 기록에 남는다 — 이어 묻기가 그 기록으로 선다

## 작업 자리

- 조사만 시킬 때 `--cwd` 는 임시 폴더다. 읽힐 자료는 그 폴더에 두거나 자료 폴더를 `--cwd` 로 준다
