# 프로젝트 지시 파일

*(➔ 규범 [Single Source · Point or Derive] — 코드가 답하는 것은 적지 않는다 · [Layer Triage] — 빠뜨린 것은 글보다 장치 ·
문서 룰 [Diátaxis Axis] — 지시 파일은 참조가 아니다)*

표준은 둘이고 같은 말을 한다 — AGENTS.md 관례(에이전트용 README · 사람용 README 를 보완한다 · 큰 저장소는 폴더마다
제 AGENTS.md)와 Claude Code 의 CLAUDE.md 안내(팀이 공유하는 프로젝트 수준의 규칙 · 모호한 말 대신 구체 · 200줄 아래 ·
일부에만 걸리는 지시는 경로 룰로 · 서로 어긋나는 두 줄은 아무 쪽이나 고른다). 모델은 둘을 안다. 여기는 우리 자리에서 갈리는
것만 든다.

## 선택

- 파일은 AGENTS.md 하나다 — Claude 는 CLAUDE.md 자리에 이것을 읽는다. CLAUDE.md 는 두지 않거나 한 줄로 가리킨다
- 한 영역에만 걸리는 지시는 뿌리를 키우지 않고 그 폴더의 AGENTS.md 나 `.claude/rules/` 의 경로 룰로 간다

## 더하기 — 표준이 안 정한 것

1. **무엇이 들고 무엇이 나가나.** 표준은 「프로젝트 구조」를 들게 하지만 그 뜻은 부품의 지도(설계 문서)이지 기능마다의
   「고치려면 여기」 표가 아니다 — 그 표는 기능이 늘 때마다 늘고, 적는 것이 `ls` 와 grep 이 답하는 것이라 사본이다.

   | 든다 | 나간다 → 어디로 |
   |---|---|
   | 무엇인가 — 한 문단, 왜 만드나는 README · 비전 문서를 가리킨다 | 파일 자리 · 모듈 지도 → 설계 문서 한 장을 가리키고, 낱개 자리는 모델이 grep 한다 |
   | 지킬 것 — 굳은 규칙과 그 까닭(결정 기록 좌표) | 값 · 열쇠 · 목록 → 코드와 묶음이 원본이다 |
   | 내는 법 — 브랜치 · 커밋 · PR 의 꼴 | 「같이 바꿀 것」 → 그 값 곁의 주석이나, 한쪽만 바꾸면 빨개지는 검사(스킬 check-design) |
   | 확인 — 검사를 돌리는 명령과 어디까지 재나 | 경위 · 옛 판 · 누가 짚었나 → 커밋 · 결정 기록 |

   표는 소유로 가른다 — 그 사실의 원본이 이 파일뿐일 때만 둔다(문서 룰 [Single Source · Point or Derive]).
2. **줄을 더하려는 순간.** 레인이 빠뜨린 것을 적으려 하면 먼저 스킬 norm-design 1 절의 첫 물음을 댄다 — 어떤 장치가
   잡았을까. 장치를 댈 수 있으면 줄 대신 장치다. 지시 파일의 한 줄은 다음 레인의 눈에만 들고, 검사는 모든 레인에 든다.
3. **크기의 자.** 200줄 · 15KB 를 넘으면 더하기 전에 1 의 「나간다」 열로 턴다.
4. **정리의 끝.** 새 맥락의 레인에 「처음 온 공동작업자가 X 를 고치고 싶다」 과제 몇 개를 주고, AGENTS.md 와 grep 만으로
   자리를 찾는지로 받아들인다(스킬 agent-envelope 3 절의 받아들이는 레인). 줄인 뒤 찾기가 느려졌으면 턴 줄이 잘못 간 것이다
   — 지도를 되살리지 않고 설계 문서의 가리킴을 고친다.

## 갈리는 자리

| 갈리는 자리 | 어느 쪽 |
|---|---|
| 사람도 읽는 글인데 지시 파일에 둘까 | 사람의 들머리는 README 다(스킬 readme-standard). 지시 파일은 에이전트가 일하는 순간의 글이고, 사람은 거기서 원본으로 간다 |
| 결정 기록이 바뀌어 규칙이 바뀌었다 | 지시 파일의 「지킬 것」 줄을 고치고 결정 좌표를 바꾼다 — 옛 규칙 줄을 남겨 두면 어긋나는 두 줄이 된다 |
| 표를 걷었더니 레인이 자리를 못 찾는다 | 설계 문서(스킬 architecture-doc)가 부품을 못 드는 것이다 — 표를 되살리지 않고 그쪽을 고친다 |
