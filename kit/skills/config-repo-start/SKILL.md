# 설치가 되돌리는 고침을 내 설정 저장소로 옮긴다

설치가 도구 홈에 놓은 것은 다 생성물이다 — 다음 설치와 로그온 자동 실행이 원본에서 다시 쓰고, 손으로 고친 것은 말없이
되돌린다. 고침이 살아남는 자리는 그 사람의 설정 저장소 하나다. 설치가 그 저장소를 받아 개인 층을 채우고, 개인 층은 항목마다
제작자 것을 이긴다. 원본 상태(저장소)와 홈 상태를 가르고, 고침은 원본에 두고 홈은 적용으로 맞추는 dotfiles 관리의 틀(chezmoi 의
source state · `add` · `diff` · `apply`)과 같다. 아래는 우리 판에서 갈리는 것만 든다 — 원본이 제작자 층과 개인 층 둘이고,
더하기만 하면 통째로 가져가지 않는다.

## 1. 자리부터 가른다

- **고칠 자리는 생성물이 아니라 원본이다.** 생성물을 이미 고쳤으면 그 고침을 옮길 거리로 삼고, 아직이면 원본에서 고친다
- **설정 저장소가 있나** — `~/repos/` 아래 `deploy.ps1` 과 `memory/` 를 함께 든 폴더다(세션 훅이 설정 저장소를 알아보는 자와
  같다). 있으면 3 으로 간다
- **그 파일은 어느 항목의 생성물인가** — 갈 곳 표 `~/.paisetup/standard/tool-homes.conf` 가 원본이다. `route` 줄의 홈 자리에서
  항목을, 그 항목 `item` 줄의 넷째 칸에서 저장소 자리를 읽는다. 꼴(import · block · include · copy …)의 뜻은 표 머리가 든다

## 2. 없으면 세운다

1. **원격 자리를 사람에게 고르게 한다.** 추천은 앞의 것이다

   | 길 | 맞는 사람 | 대가 |
   |---|---|---|
   | GitHub 비공개 저장소 | 비영속 VDI를 쓰거나 PC 를 옮겨 다니는 사람 | GitHub 계정이 들고, 처음 한 번 로그인한다 |
   | 이 PC 의 폴더 | 영속 PC 하나에서만 쓰는 사람 | 계정이 안 든다. PC 를 바꾸거나 VDI 에서는 안 따라온다 — 고른 순간 이 말을 한다 |

   - 비영속 VDI 는 로그온마다 홈이 비워져, VDI 밖의 원격만 고침을 살린다
   - 저장소에는 키(`secrets.env`)가 들 수 있다 — GitHub 저장소는 반드시 비공개로 만든다
   - 폴더 길은 그 PC 에 bare 저장소를 두고 그 경로를 주소로 쓴다. 경로에 빈칸이 들면 `file:///` 꼴로 적고 빈칸을 `%20` 으로
     바꾼다 — 설치 창은 주소 여럿을 빈칸으로 가른다
   - 원격을 만드는 일(`gh repo create --private` 따위)은 밖으로 나가는 일이라, 이름과 공개 여부를 확인받고 한다
2. **씨앗으로 짓는다.** 씨앗 `~/.claude/seeds/config-repo/` 를 숨김 폴더까지 `~/repos/<이름>/` 으로 옮기고, `personal.conf` 를
   채우고, 첫 커밋을 원격에 민다. 걸음과 함정은 씨앗의 `config-repo-howto.html` 「만들기」가 든다 — 열어서 그대로 따른다

## 3. 고친 것을 찾는다

찾기는 명령이 하고, 가르기는 모델이 한다.

- 찾기 — 셋 다 아무것도 안 쓴다
  - 표준 층 — `python -X utf8 ~/.paisetup/standard/tool-homes.py sync --layer standard --from <짐> --dry-run` 의
    `CHANGE=fill … 원본과 다르다` 줄. 짐은 지금 판의 것이다 — `%LOCALAPPDATA%\Claude Code Setup\<판>\kit` 이고, 판은 그 아래
    판 번호 폴더 가운데 가장 높은 것이다
  - 홈 사본 · 표지 블록 — `python -X utf8 ~/.paisetup/standard/tool-homes.py check` 가 1 로 끝나며 대는 자리
  - 이미 되돌려진 고침 — `~/.paisetup/backups/<시각>/` 에 설치가 떠 둔 것
- 가르기 — 자리마다 diff 를 읽고, 사람이 고친 줄과 짐이 새 판이라 생긴 차이를 가른다. 가를 수 없는 줄은 사람에게 보이고 묻는다

## 4. 원본 자리로 옮긴다

- **규범에 줄을 더한 것** — 저장소의 더하는 규범 자리(표의 `norms-add` 항목이 가리키는 자리)에 그 줄만 둔다. 제작자 규범은 그
  앞에 계속 새 판으로 온다
- **제작자 줄을 바꾸거나 뺀 것 · 룰 · 스킬 · 에이전트를 고친 것** — 그 항목을 `~/.paisetup/standard/` 에서 저장소 자리로 가져와
  고친다. 규범 · 룰은 항목째 이기므로 통째로, 스킬은 폴더 하나씩 이기므로 그 스킬만 가져온다
- **가져가기 전에 대가를 말한다** — 가져간 항목은 그 사람 것이 되어 제작자의 다음 판이 안 온다. 제작자 판과 견줘 다시 들일지는
  그 사람 몫이고, 견줄 지금 판은 늘 `~/.paisetup/standard/` 에 있다
- 옮긴 뒤 커밋하고 원격에 민다 — 밀기는 확인받고 한다

## 5. 잇고 확인한다

1. 저장소 폴더에서 `deploy.ps1` 을 돌린다 — 계획을 보이고 승인받은 뒤 개인 층을 채워 도구 홈에 놓는다
2. 고친 줄이 그 사람이 규범을 받는 도구 홈마다 섰는지 본다 — Claude `~/.claude/CLAUDE.md` 가 가져오는 파일 · Codex
   `~/.codex/AGENTS.md` 의 블록 · agy `~/.gemini/config/AGENTS.md` 가 가리키는 파일. `tool-homes.py check` 가 0 이다
3. 설치 창 「연결」의 「내 저장소 받기」에 주소를 넣고 한 번 설치하게 한다 — 새 PC 와 비워진 VDI 가 그 주소로 다시 받는다.
   주소를 기억하는 기록은 설치기 몫이라 그 파일을 직접 쓰지 않는다
4. VDI 에서 고쳤으면 로그아웃 전에 민다 — 밀지 않은 커밋은 홈과 함께 사라진다
