# 코드 구현 원칙 — 편집 자리 층

> 원본은 `claude-config/.claude/rules.global/code-implementation.md` 다. 배포본을 고치지 않는다.
> 규범 코드 작성 원칙 가운데 **코드 파일을 만지는 자리에서만 뜻이 서는** 것이 여기 산다 — 조항마다 `*(➔ 규범 [X])*` 가 어느 원칙의 기전인지 든다.

1. **[Cognitive Anchoring]**
   프롬프트 자곤과 코드 명명을 정렬한다. `[English Jargon]`은 코드의 클래스·함수·주석에 그대로 옮겨 쓰고, 서술은 한국어로 한다. **한 이름은 한 자리만 가리킨다** — 뜻을 되묻게 하는 낱말은 그 자체가 결함이다. *(➔ 규범 [Recall Priority]와 짝 — 이름이 흔들려도 원칙과 코드의 축이 산다 · [Cross-Cultural Recoupling] — 자곤은 영문, 서술은 한국어)*

2. **[Surgical Changes]**
   요청 밖은 건드리지 않고 둘레 스타일을 따르되, **주석의 양은 둘레를 따르지 않는다** — 주석이 드는 것은 규범 [Docs-as-Code · State Only] 가 정한다. 무관한 죽은 코드는 지우지 말고 언급만 한다. *(➔ 규범 [YAGNI]의 편집 자리 — 저쪽은 안 짓고 이쪽은 안 건드린다)*

3. **[Guardrail]**
   단순성이 검증과 데이터 손실 방지를 생략하는 근거가 되지 않는다. 비자명한 로직은 실행 가능한 확인을 하고, 자명한 한 줄 코드는 생략해도 된다. **사람이 열어봐야 아는 항목은 다음에도 똑같이 틀리니 기계가 재게 한다.** 그 확인을 영구 검사로 남길지 · 어떤 꼴로 · 어느 층에는 스킬 check-design 이 가른다(규범 [Goal-Driven Execution] 의 「확인과 검사를 가른다」). *(➔ 판정을 **읽는** 자리 — 초록의 경계 · 빨강이면 검사를 연다 — 는 규범 [Goal-Driven Execution] 이 든다. 여기는 검사를 **짓는** 자리고, 지은 검사가 재려던 것을 정말 재나는 [Check Validity] 가 든다)*

4. **[Check Validity]**
   **검사가 재려던 것을 정말 재나는 넷이 정한다.** 하나라도 빠지면 초록은 「없다」가 아니라 「못 쟀다」다.
   1. **견줄 원본이 따로 있다** — 재는 자가 곧 재이는 것이면 답은 늘 초록이다(빈 것은 넘칠 것이 없고, 사본은 둘 다 낡아도 서로 같다). 한쪽을 원본으로 세우고 다른 쪽을 거기서 만들어 견준다
   2. **입력은 실물 꼴이다** — 손으로 지은 입력은 사본이라 「이 입력이 실제로 올 수 있나」부터 묻는다. 위층이 절대 안 만드는 꼴을 넣거나 실물이 새로 다루는 항목을 빠뜨리면 멀쩡한 코드가 빨개진다. 흉내가 필요하면 옮겨 적지 말고 실물의 그 자리를 불러 쓴다
   3. **재는 자리는 매번 같다** — 앞이 세운 상태를 물려받으면 없는 결함을 지어내 멀쩡한 것을 고치게 한다
   4. **일부러 틀린 표본에 빨강을 한 번 본다(물림)** — 한 번도 빨강을 못 낸 검사는 통과하도록 짠 검사와 구별되지 않는다. 작아도 문다

   ⚠ **임시 저장소에서 git 을 치는 검사는 물려받은 저장소 변수부터 걷는다.** 훅 안에서 돌면 git 이 내보낸 변수(`git rev-parse --local-env-vars` 가 이름을 댄다)가 진짜 저장소를 가리켜, 시험의 `init` · `commit` 이 진짜 색인 · 브랜치 · 공유 설정을 고친다. *(➔ 규범 [Goal-Driven Execution] 「초록이 무엇과 견준 초록인가」를 짓는 자리 · 남길지 · 어느 문에 둘지는 스킬 check-design)*

5. **[State Over Event]**
   **판정은 사건이 아니라 상태 위에 세운다.** 사건의 집합은 열려 있다 — 무엇이 *일어날 수 있는가*는 끝이 없어, 사건에 갈래를 붙이는 판정은 영원히 미완이다. 상태의 공간은 닫혀 있다 — 이 함수의 답이 *무엇일 수 있는가*는 셀 수 있고, 닫힌 것 위에서만 판정이 완결된다.
   **실물이 곧 상태이고, 신호는 사건이다.** 판정 대상이 스스로 증거가 될 수 있으면, 그것에 *대해 말하는* 것들은 판정자가 아니라 기록이다.
   ⚠ **걸리는 자리도 닫힌 쪽에 둔다.** 「근본을 보라」는 사건 쪽 언어라 발동하지 않는다 — 셀 수 있는 상태가 건다: **조건 갈래의 수가 답의 수를 넘었으면 판정이 사건을 세고 있는 것이고, 그 자리가 재설계 신호다.** *(➔ 규범 [Root Cause Fix] · [First Principles Thinking]과 짝)*

6. **[Named Constants]**
   **매직 넘버·매직 스트링을 코드에 박지 않는다** — 값에는 이름을 주고, 그 이름들은 **한 자리(상수 파일)** 에 모은다. *(➔ 규범 [Single Source · Point or Derive] — 흩어진 값은 손사본이다 · [Cognitive Anchoring]과 짝 — 저쪽은 「이름이 무엇을 가리키나」, 이쪽은 「값이 이름을 갖나」)*

7. **[Review Triage]**
   **코드를 고친 보고는 끝에 「리뷰가 필요한가」를 근거와 함께 적는다** — 묻기를 기다리지 않는다. 리뷰는 찾으라면 늘 무언가를 찾으므로 「찾을 것이 있나」로는 못 가른다. 가르는 것은 **만든 쪽이 못 본 자리를 리뷰가 보나**다. 셋을 차례로 묻는다.
   1. 고장이 **조용하고 넓게** 번지나 — 모든 세션 · 여러 기계 · 데이터에 걸리는데 틀어져도 아무도 모르나 → 리뷰한다
   2. 안 본 자리를 **이름으로 댈 수 있나** → 대면 그 자리만 좁혀 재고 끝낸다. 못 대거나 목록이 길면 리뷰한다
   3. 고치기 전에 빨강 · 고친 뒤 초록인 검사가 **양쪽**을 덮나 — 잡아야 할 것을 잡고, 둬야 할 것을 두나 → 덮으면 리뷰가 보탤 것이 적다

   ⚠ **판정만 적지 않는다.** 코드를 안 읽는 사람이 받는 판정이라, 근거가 없으면 믿으라는 말이 된다 — 셋 가운데 어디에 걸렸고 어디를 통과했나를 한 줄씩 댄다. *(➔ 안 본 자리를 판정 옆에 적는 일은 규범 [Goal-Driven Execution] 이 든다. 여기는 그 목록으로 리뷰 여부를 가르는 자리다 · 하기로 했으면 누가 보나는 스킬 agent-envelope 1 절)*

8. **[Comment Shape]**
   주석에 무엇이 드나는 규범 [Docs-as-Code · State Only], 좌표가 열리나는 [Single Source · Point or Derive] 가 정한다. 여기는 꼴만 든다.
   1. **까닭은 지금 꼴로** — 「Y 다 — 안 그러면 Z 가 깨진다」. 「옛 판은 X → 그래서 Y」로 쓰지 않는다. 한두 줄을 넘으면 결정 기록의 몫이다
   2. **⚠ 는 함정에만** — 모르고 밟으면 조용히 깨지는 자리. 까닭 문단의 머리표로 쓰지 않고, 굵게는 한 덩어리에 하나까지
   3. **머리 꼴** — 파일: 무엇 · 부르는 꼴 · 내는 것. 함수: 계약(받는 것 · 내는 것 · 종료 값 · 부작용). 걸음: 층 · 하는 일 · 받는 것 · 안 하는 것
   4. **우회는 범위와 걷는 조건을 단다** — 어느 도구 · 판 · 환경 때문이고 무엇이 되면 걷나. 빌린 판은 날짜가 아니라 커밋 해시로
   5. **이름으로 가리킨다** — 「N 칸」 같은 번호는 걸음을 옮기면 거짓이 된다
